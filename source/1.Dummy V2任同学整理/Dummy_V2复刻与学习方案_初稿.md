# Dummy V2 复刻与学习方案（初稿）

> 2026-09-06 审计修订：本文件保留初稿的学习背景与历史安排，已不作为独立执行依据。请以 [详细复刻方案：审计修订版](Dummy_V2详细复刻方案_审计修订版.md) 为准。制造资料、安全固件、六轴参数与预算门槛均有重要更新；生产固件尚未因本次文档修订而得到修复。

关键更正：Motor-42 Gerber 缺少独立 NC 钻孔文件；UART 原始解析/授权、编码器故障传播和失联停机需先修；`!STOP` 不等于硬件急停；视频 V2 参数截图与源码的减速比、方向位、限位和几何尺寸存在冲突。详见 [审计结论与证据](6.Docs/复刻审计_2026-09-06/审计结论与证据.md)。

## 1. 方案定位

这份方案不是“照着 BOM 买齐后组装”的教程，而是把 Dummy V2 当作一条项目式嵌入式学习主线。

当前已知条件：

- 机械专业背景，会建模和仿真，具备机器人运动学理论。
- 编程不是主要障碍，但嵌入式、电路、焊接和硬件调试接近零基础。
- Windows 与 Linux 均可使用，目前没有工具和实物器件。
- 第一目标是深入掌握原理，而不是尽快展示整机。
- 学习方式偏好“先动手暴露问题，再按问题补理论”，不希望学完整套课程后才实践。
- 短期不承担完整机械臂约 3900～6000 元甚至更高的材料与返工成本。
- 第一个月希望得到一个真实、可重复、可解释的闭环电机成果。
- 机械版本锁定 `4.Model/Dummy V2 版本 视频款/`，第一轮不混用其他版本。

因此采用以下总路线：

> 仓库与机械基线冻结 -> STM32 最小实验 -> 单个 42 电机板 -> 编码器与闭环 -> CAN 主从 -> 单关节 -> 双关节 -> REF 主控 -> 六轴机械与标定 -> 上位机和二次开发

整机不是启动条件，而是前面若干能力验收通过后的自然结果。

## 4. 首月目标：单个 42 电机闭环实验台

### 4.1 成果定义

“电机转起来”不算完成。首月成果需同时满足：

- 能从源码构建 Motor-42 固件并用 ST-Link 重复烧录。
- 能解释 Motor-42 板的电源、MCU、编码器、驱动和通信五个功能区。
- 未使能功率输出时，能读取并记录 MT6816 原始角度、校准角度和磁铁异常状态。
- 能安全执行编码器校准，并理解校准表为何写入 Flash。
- 能通过 UART 发送小范围位置指令，使电机稳定到达目标。
- 至少完成正反向、多次冷启动和 15 分钟低负载运行测试。
- 能记录目标、反馈、误差、电流限制、控制参数、温升和异常。
- 出现故障时，能判断问题属于供电、烧录、SPI、磁铁、驱动、控制方向还是固件参数。
- 有物理断电手段，断线、错误指令或控制失稳时能立即停止。

### 4.2 为什么首月不需要 REF

Motor-42 电机板自身已经包含完整闭环，并通过 UART 支持：

- `c...`：电流目标，外部单位 A
- `v...`：电机轴速度目标，外部单位转/秒
- `p...`：电机轴绝对位置目标，外部单位转数，不是关节角或增量

审计补正：这些入口会切换控制模式；`enableMotorOnBoot=false` 不是独立的运动授权门。原始解析器忽略长度且缺少严格数值检查，普通位置/速度命令没有通用失联保护。新版要求先完成解析、授权、传感器有效性与本地超时修复，再进入首次闭环。

见 `2.Firmware/dummy-42motor-fw/UserApp/protocols/interface_uart.cpp`。UART 为 115200、8N1，配置见 `2.Firmware/dummy-42motor-fw/Core/Src/usart.c:49`。

先绕开 REF、USB、FreeRTOS、运动学和 CAN，可以把首个问题面压缩到单块板和单个电机。闭环稳定后再接 CAN，学习价值更高，诊断也更清晰。

## 5. 首月逐周计划

### 第 1 周：建立可编译、可烧录、可观测的最小能力

实践任务：

1. 在 Windows 安装 STM32CubeIDE、STM32CubeProgrammer 和串口工具。
2. 在 Linux 安装 CMake 3.20 以上、GNU Arm Embedded Toolchain、OpenOCD、Ninja/Make、Python 虚拟环境。
3. 当前 Linux 环境尚未发现 `cmake` 和 `arm-none-eabi-gcc`，需要先补齐工具链。
4. 不改源码，分别构建 `dummy-42motor-fw` 和 `dummy-ref-core-fw`，保存完整构建日志和固件尺寸。
5. 用一块廉价 STM32F103 开发板完成四个小实验：GPIO 闪灯、UART 回显、定时器中断、SWD 断点与变量观察。
6. 用逻辑分析仪测量 UART 波特率和定时器周期，不只凭“现象正常”判断。
7. 为项目建立版本管理或至少建立只读原始副本，后续实验修改不直接污染原始文件。

即时理论：

- MCU、Flash、RAM、寄存器、外设和中断的基本关系
- STM32 时钟树
- GPIO、UART、Timer 的 HAL 调用链
- 编译、链接、ELF、HEX、烧录与复位的区别
- SWD、SWCLK、SWDIO、GND 的连接与调试过程

验收输出：

- 一份工具链版本记录
- 两个原始固件的构建日志
- 四个最小实验工程或提交记录
- 一张从 `main()` 到中断回调的调用图

通过条件：

- 连续三次可从干净构建目录生成固件
- 连续三次可烧录、复位、连接调试器
- 能在断点中解释一个定时器中断如何发生

### 第 2 周：读懂并准备一块 Motor-42 板

原理图阅读顺序：

1. `1.Hardware/motor42/PCB源文件/Power.SchDoc`
2. `1.Hardware/motor42/PCB源文件/MCU.SchDoc`
3. `1.Hardware/motor42/PCB源文件/Interface.SchDoc`
4. `1.Hardware/motor42/PCB源文件/Drive.SchDoc`
5. `1.Hardware/motor42/PCB源文件/Port.SchDoc`
6. `1.Hardware/motor42/PCB源文件/Motor-42.PcbDoc`

实践任务：

1. 自己重画一张功能框图，只画电源流和信号流，不抄完整原理图。
2. 建立网络检查表：24 V、3.3 V、GND、SWD、UART、SPI、CAN、两相电机输出。
3. 根据 `Motor-42.html` 和 PcbDoc 找出所有测试点、关键芯片方向和连接器 Pin 1。
4. 从同一选定 PcbDoc 重新生成并审核 Gerber、钻孔、BOM 和 CPL；审计确认 Motor-42 现成 Gerber 包缺少独立 NC Drill，三类主板没有已审核的独立标准 CPL，不能直接据此放行制造。
5. 采购一套单轴器件，不采购六轴器件。
6. 设计并打印一个电机固定夹具、磁铁防飞出结构和透明防护区域。

推荐双板策略：

- A 板：一块已知良好的 Motor-42 成品板或委外贴片板，用于建立硬件和固件基线。
- B 板：一块裸板，后续按电源、MCU、编码器、CAN、驱动的顺序自行焊接和分区验证。

A 板不是为了跳过学习，而是为了避免第一块板同时存在焊接、器件、供电、固件和磁铁五类未知故障。B 板承担焊接与硬件复现学习。

即时理论：

- 24 V 到逻辑电源的 DC-DC/LDO 电源树
- 去耦、电解电容、TVS、肖特基和反接/浪涌保护
- LQFP、SO-8、0402、1206 封装和焊接风险
- H 桥、PWM 斩波、采样电阻和两相步进电机
- PCB 地、电流回路、功率器件散热和测试点

验收输出：

- 一页 Motor-42 功能框图
- 一份带封装、数量、替代限制和来源的单板 BOM
- 一份制造资料检查结果
- 一张首板上电测量点图

通过条件：

- 不看原理图也能指出五个功能区之间的电源和信号关系
- 能说明 2 个 TB67H450 分别控制哪一相
- 能说明 MT6816、磁铁和电机轴的几何关系
- 所有器件方向、封装和耐压已经核对，而不是只按商品标题采购

### 第 3 周：分级上电、烧录和读取编码器

实践任务：

1. 断电检查 24 V-GND、3.3 V-GND 阻值和明显焊桥。
2. 电机暂不连接，实验电源设置电流限制后首次上电。
3. 依次测量输入电压、DC-DC 输出和 3.3 V，不跨级猜测。
4. 断电后连接 ST-Link，只接目标板要求的 SWDIO、SWCLK、GND 和必要参考电压。
5. 确认能读取 STM32F103CBT6 ID，烧录最小闪灯程序，再烧录原始电机固件。
6. 增加一个受宏开关控制的 20～50 Hz 低速遥测输出，记录 `rawAngle`、`rectifiedAngle`、`noMagFlag` 和校验状态。
7. 手动慢转电机轴，检查角度单调性、回绕、方向、噪声、磁铁偏心和间隙影响。
8. 用逻辑分析仪核对 SPI 时序，而不是立刻修改控制参数。

即时理论：

- SPI 模式、片选、时钟和数据采样
- MT6816 的 14 位角度、奇偶校验和无磁状态
- 角度回绕与多圈位置展开
- 采样频率、量化、噪声、滤波和速度估计
- Flash/EEPROM 仿真与参数持久化

特别注意：

- `MT6816Base::Init()` 会检查 16384 点、共 32 KB 的校准映射表，未校准时闭环会进入休眠保护，见 `Ctrl/Sensor/Encoder/encoder_base.h:19`。
- EEPROM 参数优先于源码默认值，见 `2.Firmware/dummy-42motor-fw/UserApp/main.cpp:30`。已经写入 Flash 后，只改源码默认参数可能不会生效。
- 原始校准电流默认是 2000 mA，见 `UserApp/main.cpp:44`。在确认电机额定电流前，不得直接按默认值执行校准。

验收输出：

- 首次上电电流和各电源轨记录
- ST-Link 连接、擦除、下载和恢复流程
- 一份至少覆盖一整圈的原始角度数据
- 磁铁同心度、轴向间隙和噪声观察结论

通过条件：

- 板卡无异常电流和异常发热
- 三次冷启动均可连接 SWD 和输出 UART
- 手转一圈时原始角度连续，回绕位置一致，无磁标志行为可解释

### 第 4 周：校准和低风险闭环

实践任务：

1. 查清电机额定相电流、绕组电阻/电感和磁铁规格。
2. 在首次写入 EEPROM 前，把校准电流和额定电流设置为与实物匹配的保守值。
3. 将电机牢固固定，磁铁固定并加防护，准备物理断电开关。
4. 执行编码器校准，保存校准结果和异常码。
5. 先验证禁用、休眠、制动和小电流输出，再进入位置模式。
6. 通过 UART 从很小的位置目标开始，例如电机轴的百分之一圈量级；不要第一次就发整圈、高速或高电流命令。
7. 完成正向、反向、阶跃、慢速正弦和重复定位实验。
8. 记录目标位置、反馈位置、误差、估计速度、电流命令、电源输入电流和温升。
9. 测试串口断开、错误命令、堵转趋势和断电后的恢复过程。
10. 闭环稳定后再做 CAN 收发；CAN 不作为首月必须项。

即时理论：

- 该项目的 DCE 位置/速度误差控制结构
- 硬件电流斩波与软件外环之间的关系
- 离散控制、采样周期、延迟和稳定性
- 饱和、积分累积、摩擦、死区与负载惯量
- 阶跃响应中的超调、上升时间、稳定时间和稳态误差

验收输出：

- 自动或半自动测试脚本
- 至少三组阶跃响应和一组慢速往返数据
- 当前有效 EEPROM 参数表
- 故障现象、假设、实验、结果和结论记录
- 首月演示视频或日志：上电、校准、小角度定位、停机、冷启动复现

首月最终 Gate：

- 连续 50 次小角度往返不失控
- 三次断电重启后的行为一致
- 低负载连续运行 15 分钟无异常复位和不可解释温升
- 断开命令源后系统行为符合预期，物理断电始终有效
- 能解释 `motor.cpp` 中“采样 -> 位置展开 -> 速度估计 -> 控制 -> 电流矢量”的数据流

## 6. 第一批采购策略

## 7. 第二阶段：把单电机真正学透

预计时间：首月以后 1～2 个月，不按固定周数追进度。

### 7.1 固件阅读顺序

1. `UserApp/main.cpp`：对象如何组装、配置如何加载、两个定时器做什么。
2. `Port/`：抽象控制逻辑如何落到 STM32 HAL、GPIO、PWM、SPI 和 Flash。
3. `Ctrl/Sensor/Encoder/mt6816_base.cpp`：原始角度与校准角度。
4. `Ctrl/Sensor/Encoder/encoder_calibrator_base.cpp`：200 整步、每步 16 次采样、正反向标定。
5. `Ctrl/Driver/tb67h450_base.cpp`：相位和电流幅值如何变成两个绕组命令。
6. `Ctrl/Motor/motor.cpp`：位置展开、速度估计、模式切换、DCE/PID 和保护。
7. `Ctrl/Motor/motion_planner.cpp`：速度和位置轨迹。
8. `UserApp/protocols/interface_uart.cpp`：最小调试入口。
9. `UserApp/protocols/interface_can.cpp`：分布式控制协议。
10. `Port/Platform/Memory/` 与 `UserApp/configurations.h`：参数持久化。

每读一层都配一个实验，不做纯源码抄读：

| 代码层 | 对应实验 |
|---|---|
| Encoder | 改变磁铁间隙，比较噪声、无磁标志和回绕 |
| Calibrator | 导出校准前后误差，解释正反向平均的意义 |
| Driver | 固定角度电流矢量，观察 A/B 相方向与幅值 |
| Motor | 改一个增益，比较阶跃响应，不同时改多个参数 |
| Planner | 比较直接阶跃和受限速度/加速度轨迹 |
| EEPROM | 修改、重启、擦除并验证参数优先级 |
| CAN | 抓取每条命令，手工解码 ID 和 8 字节数据 |

### 7.2 第二块板自行复现

建议按功能岛焊接和验收，不一次焊完：

1. 裸板检查
2. 24 V 输入保护和降压
3. 3.3 V LDO
4. STM32 最小系统与 SWD
5. UART 和状态 LED
6. MT6816 与 SPI
7. CAN 收发器和 120 Ω 终端
8. 两个 TB67H450 和功率输出
9. 电机与闭环

每增加一个功能岛，先与 A 板对比静态阻值、上电电流、波形和软件行为。这样手焊失败不会变成无法定位的“整板不工作”。

第二阶段 Gate：

- A、B 两块板在同一电机和同一固件下表现接近
- 能独立恢复一块擦空或参数损坏的板
- 能画出 Motor-42 的电源树、控制环和通信状态机
- CAN 命令、反馈、节点 ID、终端电阻和通信超时均经过实测

## 8. 第三阶段：CAN 主控与单关节

### 8.1 先做开发板主控

使用一块 STM32F405 开发板或 USB-CAN 控制单个 Motor-42，不立即制作 REF 正式板。

实践顺序：

1. PC -> USB-CAN -> Motor-42
2. STM32F405 -> CAN -> Motor-42
3. STM32F405 -> CAN -> 两个电机节点
4. 通信超时、重复帧、错误 ID、掉线恢复
5. 同步位置命令与反馈时间测量

项目 CAN 标准帧 ID 形式为：

```text
StdId = (nodeID << 7) | command
```

主要命令见 `interface_can.cpp`，包括使能、校准、电流、速度、位置、参数写入、位置查询、擦除配置和重启。

### 8.2 再做一个真实关节

不必先做 J1 全结构。先用简单打印夹具、同步轮或可控负载完成单关节实验：

- 无负载电机
- 已知惯量负载
- 同步带传动
- 减速器传动
- 真实关节结构

每一步比较空载电流、阶跃响应、反向间隙、重复定位和温升。机械背景可在这里发挥优势：建立电机惯量、传动比、输出惯量和控制增益之间的实验关系。

第三阶段 Gate：

- 单关节机械零位、编码器零位和软件零位关系清楚
- 实际总减速比与固件参数一致
- 负载变化后的参数调整有数据依据
- CAN 掉线时关节可安全停止

## 9. 第四阶段：REF 主控与两轴系统

REF 是系统集成阶段，不是嵌入式入门板。它同时引入 STM32F405、FreeRTOS、USB、CAN、IMU、OLED、ESP32 和多个任务。

### 9.1 REF 固件阅读顺序

1. `2.Firmware/dummy-ref-core-fw/UserApp/main.cpp`
2. `Bsp/communication/`
3. `UserApp/protocols/ascii_protocol.cpp`
4. `Robot/actuators/ctrl_step/ctrl_step.cpp`
5. `Robot/instances/dummy_robot.cpp`
6. `Robot/algorithms/kinematic/6dof_kinematic.cpp`
7. `Core/Src/freertos.c`
8. USB Fibre 协议和 CLI 最后阅读

### 9.2 最小 REF 路线

1. 先在 F405 开发板上跑 FreeRTOS 闪灯、队列和定时通知。
2. 保持电机板 20 kHz 本地闭环，REF 只做低频目标下发和状态管理。
3. 接一个电机节点，验证 200 Hz REF 调度和 1 Mbit/s CAN。
4. 接两个电机节点，完成同步运动和故障隔离。
5. 再制作 REF 正式板。

如果 REF 第一版选择不贴装 IMU/OLED/无线部分，需要先修改启动逻辑。当前 `UserApp/main.cpp:165` 会循环等待 MPU6050 连接，未贴 IMU 时程序会停在那里。

两轴系统比直接六轴更适合验证：

- 节点 ID 与反馈映射
- 指令同步和总线时序
- 两关节坐标、机械零位和方向约定
- 简化正逆运动学
- 急停、单轴掉线和恢复策略

## 11. 理论学习地图：只在实验需要时深入

| 当前问题 | 此时补的理论 | 暂时不学 |
|---|---|---|
| MCU 无法运行 | 时钟、复位、Flash、SWD、链接脚本 | FreeRTOS 内核源码 |
| UART/SPI 不工作 | GPIO 复用、电平、时序、中断/DMA | USB Fibre |
| MT6816 跳变 | 磁编码器、奇偶校验、回绕、采样噪声 | 六轴动力学 |
| 电机不转或发热 | 两相步进、H 桥、斩波电流、绕组参数 | ROS |
| 闭环振荡 | 离散控制、方向、延迟、饱和、DCE/PID | 复杂观测器 |
| 轨迹不平滑 | 速度/加速度约束、梯形规划、插补 | 全身最优控制 |
| CAN 不稳定 | 仲裁、位时序、终端、拓扑、总线负载 | Wi-Fi |
| 多任务互相影响 | 中断、优先级、队列、互斥、实时性 | UI 美化 |
| 末端位置不对 | 坐标系、零位、减速比、DH、FK/IK | 视觉抓取 |

学习循环固定为：

```text
观察现象 -> 提出可证伪假设 -> 设计单变量实验
        -> 采集数据 -> 对照理论 -> 修改 -> 回归验证 -> 记录结论
```

## 12. 当前仓库风险与待核实清单

### 高优先级

- 三套机械版本并存，BOM 只对应视频 V2；必须冻结版本。
- Motor-42 现成 Gerber 包缺独立 NC Drill，且 PCB/焊盘更改版/旧 Gerber 并存；须从单一版本统一导出制造文件，BOM/CPL 重新审核。
- 电机额定电流、绕组参数和编码器磁铁规格不完整，不能直接用默认 2 A 校准。
- 参数图证明 MINIF11/MINIF08 都有 30:1 和 50:1；视频 V2 装配体名称指向 50:1，但 REF 固件 J1～J5 仍配置为 30/30/30/24/30。必须按实物和同步轮逐轴确认总减速比后修改固件。
- J6 的具体行星减速器型号和总传动比信息不足。
- 视频 V2 参数截图的六轴比值为 50/50/50/50/50/5，当前源码为 30/30/30/24/30/50，方向位与部分限位也不同；J6 的 5/50 冲突不可忽略，详见修订版冻结表。
- 视频 V2 的两个装配体都同时出现 `42-34Motor Assembly` 和 `42-40Motor Assembly`，而 BOM 只列出 42×40 这一规格；正式采购前必须在 CAD 中核对数量、安装空间与最终选型。
- 紧固件只以购买截图给出，截图可辨认到 M3×5、M3×14、M3×35、M3×40、M3×45、M4×16、M4×20 等批量规格，但不是实际消耗数量表。
- REF 到 J1 与 J1 到 J6 的线缆方向不同，且 6 针接口同时承载 24 V 和 CAN；接错可能直接损坏硬件。

### 中优先级

- REF BOM/OLED 描述与固件 `SSD1306` 软件 I2C 实例存在接口/型号疑点。
- REF CubeMX 文件来自 6.2.1、F4 包 V1.26.1、旧 SW4STM32 工具链；重新生成代码有版本漂移风险。
- 电机工程 README 明确提示 CubeMX 重新生成后要撤销 `stm32f1xx_it.c` 的更改。
- Python CLI 存在脆弱的路径假设，DummyStudio 只有 Windows 成品。
- ESP32 的部分工具/HEX 占位文件为空，真正固件在 `examples/esp32/uart-bridge/`。
- Dummy 应用层没有单元测试，所有关键修改都需要建立自己的硬件在环回归。

### 明确缺失或暂不可靠

- 仓库无 ROS、MoveIt、Gazebo 和 URDF。
- 夹爪只有 CAN 控制代码，没有对应机械、PCB 和 BOM。
- 淘宝链接可能失效，项目 README 也明确不保证商品质量。
- 3900～6000 元通常容易漏算工具、备件、贴片起步费、加工返工和运费。

## 14. 不应采用的路线

- 不一次购买六个电机、五个谐波减速器和全部 CNC。
- 不按文件夹顺序从第一页读到最后一页。
- 不把 Mongoose、Unity 运行库、HAL/CMSIS 全部第三方源码当作学习起点。
- 不在同一天引入 STM32、20 kHz 闭环、CAN、FreeRTOS、USB 和六轴运动学。
- 不用“电机转了”代替电源、电流、温升、误差和异常恢复验收。
- 不在没有限流电源、固定夹具和物理断电手段时使能电机。
- 不在不清楚额定电流时直接使用原始 2000 mA 校准值。
- 不同时修改多个 PID/DCE 参数后凭感觉判断。
- 不把委外 SMT 等同于放弃学习，也不把首次手焊 0402 整板等同于真正理解硬件。
- 不在单轴和两轴尚未稳定时开始 ROS、视觉或夹爪扩展。
