## 1. 目标、背景与范围

### 1.1 沿用的用户背景

本版沿用初稿中的条件，不把它们当成本次重新确认过的新事实：机械专业，能建模和理解运动学；嵌入式、电路、焊接及调试经验少；Windows/Linux 可用；以理解原理为主，希望首月得到一个能解释、能复现的闭环电机成果；不先承担整臂材料和加工费用。

因此，成功不是“六轴最快转起来”，而是建立以下可迁移能力：

1. 能独立从源码构建、烧录、调试和恢复一块 STM32 板。
2. 能区分电源、焊接、时钟、通信、编码器、驱动和控制参数问题。
3. 能记录目标、反馈、有效性、误差、电流命令和实际温升。
4. 能解释关节角、电机转数、编码器原始角与内部计数之间的换算。
5. 能说明每个停止条件在断线、传感器坏帧、任务卡死时是否仍有效。
6. 最后才追求六轴一致性、末端精度和上位机体验。

### 1.2 保留与后置

| 项目 | 本版决定 | 原因 |

## 4. 安全设计必须先于首次运动

### 4.1 三层停止机制

| 层级 | 目的 | 本方案要求 |
|---|---|---|
| 正常停止 | 控制良好时平滑结束任务 | 停止新目标、受控减速、保持/失能策略明确 |
| 故障停止 | 失联、编码器错误、越界、任务异常时限制危险 | 节点本地检测、主控联动、故障锁存、人工重新授权 |
| 物理功率切断 | 软件不响应时的最终干预 | 可立即触达、适用于直流负载的断电装置；在实际电压/电流下验证 |

三层不能互相替代。普通按钮加软件 `!STOP` 不是经过认证的安全急停。限流电源也不保证所有错误接线都不会烧板。

裸电机应固定在台面，磁铁有防飞出结构，周围无缠绕物。进入关节阶段前必须增加托架、限位或受控支撑，尤其 J2/J3 不得在重力负载悬空时用“直接 Sleep”作为唯一故障策略。断电后的机构行为也必须验收。

### 4.2 建议的最小状态机

下列是待开发的安全结构，不是原固件已有命令：

```text
BOOT_SAFE -> SENSOR_CHECK -> DISARMED -> ARMED -> RUNNING
                    |            |          |        |
                    +------------+----------+--------+-> FAULT_LATCHED

FAULT_LATCHED -> 排除故障 + 显式人工确认 -> DISARMED
```

- BOOT_SAFE：功率输出关闭；不因旧 EEPROM 或上次运动状态自动使能。
- SENSOR_CHECK：确认当前采样有效、磁铁正常、校准状态和参数范围可解释。
- DISARMED：可以查询；运动/校准/写 Flash 必须分别授权。
- ARMED：设置当前反馈为初始目标，禁止恢复历史残留目标。
- RUNNING：只接受有界、有效、属于当前会话的命令。
- FAULT_LATCHED：屏蔽新运动命令；恢复通信、重新插 USB 或重连 GUI 均不自动运动。

建议首个**低能量裸电机试验**把命令更新周期定为 20～50 ms，本地命令失联阈值先按 100～200 ms 设计并实测；传感器持续错误检测目标可先设为不超过 5 ms。它们是教学试验初始设计值，不是整臂安全认证指标。装载、速度、制动距离变化后必须重新计算允许响应时间。

位置点命令不能简单要求不停重发而没有协议定义。可以采用已授权目标加独立心跳租约，也可以采用带时间戳的周期目标；无关查询不能刷新运动存活计时。主控断线时已断线节点收不到失能帧，因此检测必须在电机本地实现。

### 4.3 禁止的试验方式

- 不在运行中用手拔磁铁、插拔相线、接触旋转轴或堵住电机轴。
- 不把 CAN、UART 或 USB 线当作物理急停线。
- 不先装减速器再做会多圈转动的编码器校准。
- 不在无支撑的六轴机械臂上验证断电坠落。
- 不在正常伺服中断里打印长文本或执行长时间 Flash 写入。
- 不向整条总线广播校准、擦除、改 ID 或恢复配置以“试一下”。

故障注入优先用软件测试桩、断开功率的板卡、可控 SPI 数据源和固定防护夹具，再进入受控实物验证。

## 5. 开发基线与工具链

### 5.1 本次环境实况

审计时 PATH 中有 `make`、宿主 `gcc/g++`、Python、PDF 工具；没有发现 `cmake`、`arm-none-eabi-gcc` 或 `ninja`。**没有完成三个 STM32 固件的 ARM 构建。** 本次通过的 HSE 预处理和 Python AST 检查只是静态验证。

### 5.2 工作区管理

1. 保留当前原始资料，不删除 History、老 Gerber 或旧模型。
2. 另建实施工作副本或个人版本库，记录复制来源和本次哈希快照；不覆盖同级已有项目目录。
3. 分开存放原始输出、实验构建、安全修订固件、参数备份和测量记录。
4. 构建输出放新目录，不复用仓库中的 `cmake-build-debug` 缓存。
5. 每次试验同时记录源码版本、编译器、优化等级、固件 SHA-256、板号、电机、有效 EEPROM、磁铁和线束。

### 5.3 编译与下载路线

Windows 可用 STM32CubeProgrammer 和 SWD 工具；Linux 使用 GNU Arm Embedded Toolchain、CMake 3.20+ 和 Make/Ninja。先选一套主开发环境，另一套作为后期可移植性验证，首周不同时维护两套不同生成工程。

以下是工具安装完成后，在**工作副本根目录**执行的构建示例；本次未执行，也不是烧录命令：

```bash
cmake -S "2.Firmware/dummy-42motor-fw" -B "build/motor42-baseline" -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Debug
cmake --build "build/motor42-baseline" --parallel 2
cmake -S "2.Firmware/dummy-35motor-fw" -B "build/motor35-baseline" -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Debug
cmake --build "build/motor35-baseline" --parallel 2
cmake -S "2.Firmware/dummy-ref-core-fw" -B "build/ref-baseline" -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Debug
cmake --build "build/ref-baseline" --parallel 2
```

先保留原始构建结果，包括失败日志。若需要修改 CMake 才能构建，单独记录为构建修复，不把“修复后的成功”称为“原始工程开箱成功”。优先完成 Motor-42，Motor-35/REF 的问题可排队，不阻塞最小开发板实验。

注意事项：

- CMake 的 REF `COMMON_FLAGS` 变量声明不等于这些参数一定传给了编译/链接命令；必须检查实际 verbose 命令和 float printf/scanf 行为。
- 当前 Release 使用 `-Ofast`，安全输入验证中的 NaN/Inf 检查不能未经检查就运行在放宽浮点假设的构建下。先固定调试构建，再分别验证优化构建与 20 kHz 时间预算。
- 不先用新版 CubeMX 重生成。电机 README 已提醒中断代码中有手改逻辑，重生成可能破坏控制路径。
- 普通 F103C8 最小板可用于 GPIO/UART/Timer 学习，但不能未经核对就替代 128 KiB Flash 的 F103CB 正式电机板。
- SWD 正常连接、复位下连接、选择性擦除和全片擦除的区别必须清楚。烧录器参考电压和目标供电不可盲目并联。

G0 输出：三个工程各自的构建状态；Motor-42 的 ELF/MAP/HEX/BIN 和大小记录；已审核的 Flash 边界；至少三次干净重建及开发板下载恢复记录。

交期延误时，可提前做解析器测试、Flash 审查、协议解码和机械版本矩阵；不得用尚未验收的另一块未知板替代 A 板强行推进。

## 9. 首板上电与编码器验收 SOP

### 9.1 断电检查

1. 板卡拍照编号，记录正反面、Pin 1、功率/CAN 与调试口。
2. 核对 MCU、驱动、编码器、晶振、电容极性、采样电阻及连接器料号。
3. 测量输入和逻辑电源对地阻值，考虑电容充电，不把蜂鸣一次等同于短路。
4. 确认电源正负极、保险保护、开关额定直流分断能力和线端压接。
5. 电机相线暂不连接；CAN、REF、ESP32 暂不接入。
6. 建立实测点与批准范围，不凭经验指定“所有板都安全”的固定静态电流。

### 9.2 限流上电

1. 根据选定原理图确认输入范围，设置实验电源限流；从单板无负载状态开始。
2. 检查输入电流、每级降压输出、3.3 V 和异常发热；异常立即断电定位。
3. 断电后接 SWD，核对目标供电/参考电压，避免 ST-Link 与实验电源反向供电。
4. 读取芯片 ID、容量和原固件信息；成品板已有可用校准/参数时先备份再擦除。
5. 下载无运动诊断固件，确认默认不驱动；测试三次冷启动和恢复连接。
6. 外部 UART 使用 3.3 V 逻辑，TX/RX 交叉并共地；不把 RS-232 电平接入 MCU。

### 9.3 编码器检查

磁铁必须有已确认的尺寸、磁化方向、允许工作间隙和固定方式。按 MT6816 的对应资料和实际机械安装确认，不用任意小磁铁代替，也不只看磁铁“能吸住”。

在功率输出禁用时手转电机轴一整圈，至少记录原始角度、校验有效性、无磁状态、回绕和方向。未校准时 `rectifiedAngle` 的读数不能当作真实闭环位置。

G1 通过标准：供电/SWD/UART 可重复，原始角度单圈变化可解释，磁铁异常与坏帧能被观测，三次冷启动一致，接线记录完整；没有验证完电源、接口、磁铁前不进入校准。

## 10. 裸电机校准与闭环 SOP

### 10.1 校准前必须齐备的资料

| 项 | 必须记录的内容 |
|---|---|
| 电机 | 完整型号、步距角、额定相电流及峰值/RMS 口径、电阻/电感、相线配对 |
| 磁铁 | 型号、方向、安装同心度、间隙、固定与防飞出措施 |
| 电路 | 采样电阻、驱动电流换算、供电限制、散热路径 |
| 参数 | 实际 EEPROM、运行限流、校准电流、速度/加速度、故障阈值 |
| 固件 | FW01～FW08 适用项测试记录、Flash 区域和校准表备份方法 |
| 环境 | 无减速器/皮带/悬臂、轴自由转动空间、可触达断电开关 |

不能把默认 `currentLimit=1000 mA` 当成实物额定值，也不能认为它会自动把 `calibrationCurrent=2000 mA` 截断到 1 A。保守电流要根据实际电机和驱动确定；过低到无法完成校准时应停止诊断，不盲目加电流。

### 10.2 电机编码器校准

1. 固定电机与磁铁，断开传动机构，防止多圈标定带动关节撞限位。
2. 下载经批准的测试固件；读回实际参数，核对校准电流。
3. 在 DISARMED 状态单独授权校准；检查按键不会因误触或上电组合自动触发。
4. 执行校准，监视电源电流、异常声响和温升；不用手接触旋转件。
5. 检查成功/失败原因和写入结果；失败不自动进入正常运动。
6. 导出并校验 32 KiB 表，核对有效范围与持久化；断电重启后再次确认。
7. 重新手转检查校准角连续性，记录原始与映射后的关系。

这一步不是 REF 的 `!CALIBRATION`，也不是六轴机械零位标定。

### 10.3 第一次位置闭环

1. 优先位置模式，不以持续速度或持续电流模式作为首个运动展示。
2. 读取当前多圈反馈 `q0`，以它为初始目标，确认软件零点含义。
3. 设置保守电流、速度和加速度；空载教学试验可把速度上限 0.02～0.05 转/秒、加速度 0.1 转/秒²作为待评估起点，不当成所有电机的固定参数。
4. 首次增量按 0.001～0.005 电机轴圈量级试验，即约 0.36～1.8°；目标是 `q0 + 增量`，不是无条件发送 `p0.005`。
5. 确认反馈方向和实际轴方向一致，连续观测超调、振荡、饱和与温升。
6. 再做相反方向和更小阶跃，保持每次只改一个参数。
7. 验证停止、失联和故障锁存，然后才进入重复定位与持续运行。

原始 UART 单位速查，**只用于理解，修复与授权完成前不作为直接发送清单**：

| 命令族 | 外部值含义 | 内部换算 | 主要误用 |
|---|---|---|---|
| `c数值` | 安培 | ×1000 得 mA | 误把 mA 当 A，或以为是只读查询 |
| `v数值` | 电机轴转/秒 | ×51200 得计数/秒 | 与关节度/秒混淆，失联仍保留旧速度 |
| `p数值` | 相对软件零位的电机轴绝对转数 | ×51200 得内部位置计数 | 误当增量、度或关节角 |

MT6816 原始一圈 16384 档；51200 是控制内部尺度，不能据此宣称实际编码器精度或机械臂精度。

### 10.4 首月量化验收

以下是本项目建议的教学验收目标，不是原作者性能承诺：

- 50 次小范围往返，无不可控运动、不可解释复位、长期饱和或持续振荡。
- 三次冷启动保持 DISARMED，参数和校准状态一致，只有显式授权后允许运动。
- 每次目标都能在预设超时内完成或明确失败；首轮可按 5 秒完成窗口记录，不用“永远等待”。
- 位置误差采用测得反馈记录，并另做机械轴角对照；初始可用电机轴稳态误差不超过 0.5°作教学目标，未达到则调查而不是伪造通过。
- 低负载连续运行 15 分钟并记录温度曲线。可先以可触及表面 50°C 或相对环境升温 25°C 作为保守试验中止阈值；测量位置、仪器误差及器件额定值另行记录，该阈值不代表器件额定温限。
- 失联与传感器故障在批准的时间内触发锁存，重新连线不能自动运动。
- 日志能串联“输入目标、解析、授权、规划、采样、误差控制、两相输出、反馈与故障”。

## 11. CAN 与第二块板阶段

### 11.1 物理层

先用一块节点加 USB-CAN，再接第二块，不同时引入 REF。USB-CAN 必须支持真实 CAN 收发，逻辑分析仪不能代替 CAN 控制器和收发器。

1. 短线连接 CAN_H/CAN_L/必要地参考，核验共地与电源，避免功率地压差。
2. 只在总线物理两端保留所需 120 ohm 终端；断电测总线 H-L，约 60 ohm 仅是两只 120 ohm 并联的预期，不是所有拓扑无条件成立的判据。
3. 记录三位拨码与节点 ID，节点逐个接入冷启动核验，六轴计划使用 1～6，广播 0 不分配给关节。
4. 初始只发只读查询，先验证返回 ID、数据格式与终端，再授权运动。
5. 核对总线实际 1 Mbit/s，不能因软件设置了这个值就假定晶振和位时序正确。

### 11.2 协议核对

标准帧 ID 为 `(nodeID << 7) | command`，数据通常按 32 位小端整数或 IEEE754 float 编排。应由两端代码逐命令生成协议表，而不是只抄注释。主线可先统一要求经典 CAN 数据帧 DLC=8，其余帧拒绝；这是拟定的安全测试基线，需要明确落实到代码。

| 命令 | 当前源码语义 | 复刻阶段处理 |
|---|---|---|
| `0x01` | 值为 1 请求速度模式，其余 STOP | 不当作独立硬件总使能；所有入口仍须授权门 |
| `0x02` | 电机编码器校准 | 默认禁止广播，单节点维护授权 |
| `0x05` | 电机轴位置，byte4 请求 ACK | 检查有限值、范围、长度和反馈含义 |
| `0x06` | 位置加时间；高 4 字节还与 ACK 判断共用 | 首轮禁用，单独澄清协议再开放 |
| `0x07` | 位置加速度上限，自动返回位置/状态 | REF 主线路径，必须完整 8 字节且参数有效 |
| `0x11` | 修改节点 ID，可保存 | 冷启动会被拨码覆盖，首轮不在线批量改 |
| `0x12`～`0x1B` | 若干参数/零位/开关写入 | 逐项白名单，区别 RAM 与 Flash 写入 |
| `0x21` | 软件电流命令反馈 | 不标为实际绕组电流测量 |
| `0x23` | 位置/状态反馈 | 接收不等于完成；持续读取状态与反馈年龄 |
| `0x7D` | 开启温度监视 | 不是急停/使能命令，也不证明温度数值有效 |
| `0x7E/0x7F` | 恢复配置/重启 | 维护模式中执行，不作正常试验探针 |

### 11.3 故障与负载试验

按只读、单节点小位移、第二节点、错误帧、失联、bus-off/发送失败、恢复顺序进行。所有错误帧测试先断开功率或接模拟节点。

六轴 200 Hz 若每周期每轴一发一收，量级约 2400 帧/秒。按每帧约 110～135 bit 粗估，在 1 Mbit/s 总线上约占 26%～32% 的线时，再加查询、重发和错误开销。这是规划估计，不是实测；必须抓包记录周期、抖动和总线负载，CAN 不是六轴同时到达的硬同步保证。

G3 输出：协议表、逐节点参数、总线拓扑和终端照片、错误注入结果、本地超时记录、A/B 板同电机/同固件对比，以及恢复流程。

## 12. 单关节阶段

优先从台面受约束的旋转关节试验开始，不直接把长臂、重力负载和复杂线束一起引入。

1. 先在夹具上加已知惯量负载，比较空载与负载响应。
2. 选定一个真实关节的传动链与安装件，先做低成本几何样件。
3. 根据装配关系记录电机轴、同步带、减速器、输出轴各级方向和传动比。
4. 静态/低速实测总传动比，正反向各做多次，不只测一个方向。
5. 用独立输出侧角度基准测量回差、重复定位和弹性，不用电机编码器反馈冒充输出侧精度。
6. 记录轴承预紧、皮带张力、紧固方式、减速器安装面和平行/同心度。
7. 增加机械限位和支撑；确定正常停机、故障停机、断电时的输出行为。
8. 负载稳定后调整控制参数，每次只变一个量，重做温升和冷启动。

参数关系：

```text
r_total = 电机轴转数 / 关节输出转数
r_total = 各级减速比的乘积
皮带级减速比 = 从动轮齿数 / 主动轮齿数
电机目标转数 = 方向符号 × (关节目标角 - 关节软件基准角) / 360 × r_total
```

不要把电机步距角乘入机械传动比，也不要从 `GBN...-60` 的型号后缀推出齿数。若存在腕部耦合，必须建立多轴传动关系，不能强行套独立单轴比例。

G4 输出：一个可受控停机的关节、真实传动比/零位表、输出侧量测报告、负载和温升数据。该阶段通过后才批准其他减速器与整套加工的预算准备。

## 13. REF 与双轴最小系统

### 13.1 先分开验证，再集成

F405 开发板可用于 FreeRTOS、CAN 和任务调度学习，但其引脚、晶振、电源与外设通常不等同于 REF，不能直接刷原 REF 镜像并期待运行。

建议先在开发板上写一个只调用 `CtrlStepMotor` 的双轴试验应用，不运行六轴 `DummyRobot` 的 HOME/CALIBRATION。待通信、时序和故障路径稳定，再把 FW09～FW12 集成到 REF 工作副本。

最小 REF 裁剪必须同时处理：

- IMU 初始化改有限重试/显式可选；依赖它的更新任务也要条件化。
- OLED、RGB、无线与相关 DMA/PWM/任务不能只“不贴硬件”而不处理软件调用。
- 将活动轴列表用于下发、反馈判定、到达掩码、限位、故障和 GUI 显示。
- 缺席轴与掉线轴分别定义；不能把不存在的反馈伪造成“已到达”。
- 所有等待到位、发送信号量、查询和复位过程均有超时与可观察结果。
- 模拟两轴时不对外宣称得到真实六轴末端位姿；六轴运动学用离线数据单独验证。

### 13.2 REF 的命令使用顺序

先无运动查询、再单轴已授权目标、再双轴；原始 `!HOME`、`!RESET`、`!CALIBRATION` 在整改和六轴参数冻结前禁止使用。

| 入口 | 当前行为 | 本版要求 |
|---|---|---|
| `!START` | 节点使能相关请求 | 必须增加系统 READY、反馈新鲜和授权条件 |
| `!DISABLE` | 通过 CAN 请求停止模式 | 不是独立硬件急停；断线时不可达 |
| `!STOP` | 回发当前位置目标后停主控下发 | 先修独立安全路径，不能照旧使用 |
| `!HOME` | 移动到 `{0,0,90,0,0,0}` 并等待 | 不是寻零开关搜索；需可靠基准和超时 |
| `!RESET` | 进入 REST_POSE | 会运动，不是仅软件复位 |
| `!CALIBRATION` | 写偏置、移动、重启 | 只在整机校准维护流程开放 |
| `>` / `&` | 关节空间目标 | 区分接受、拒绝、到达，检查有限值/限位 |
| `@` | 末端位姿经 IK 转关节目标 | 只在 FK/IK 和坐标系验证后开放 |

G5 通过标准：缺失 IMU/OLED 时能安全诊断；两个活动轴可以完成任务；任一节点掉线或错误反馈不会永久等待或误判完成；200 Hz 调度抖动和 CAN 开销有测量；停止行为不依赖 GUI 正常工作。

## 15. 六轴集成、标定与验证

### 15.1 装配顺序

1. 六块电机板和六个电机逐个完成单节点验收，标注 ID、固件与校准备份。
2. 每个关节分别装配，测总比、方向、行程、温升和输出侧重复性。
3. 固定基座，J2/J3 使用支撑；先做下部关节，再装腕部，最后装线束和外壳。
4. 断电逐针核验整条线束，确认终端位置与保险/开关，不把前面的单线测试自动视为整机测试。
5. 首次整机只供逻辑/保持运动禁用，依次确认六节点在线和反馈合理。
6. 每次只授权一个轴，受限范围内确认方向、反馈、限位和机械间隙。
7. 检查多轴同时动作的供电压降、总线抖动、热负载和紧固松动。

J6 软件允许 ±720°不证明线束允许旋转两圈，更不表示有滑环；先按实际线束可承受行程设更窄限位。

### 15.2 分清三类基准

| 基准 | 解决的问题 | 验证方式 |
|---|---|---|
| 编码器校准表 | 电机轴磁角映射和非线性 | 裸电机标定与有效性检查 |
| 关节机械/软件零位 | 关节输出角、编码器零偏与安装姿态对应 | 机械基准、量具、逐轴正反向检查 |
| 机器人基座/工具坐标 | 六轴关节角与末端位姿对应 | CAD 几何、FK、外部量测、TCP 标定 |

原固件启动姿态假定为 `REST_POSE={0,-73,180,0,0,0}`，并不等于有绝对多圈关节编码器或自动寻找机械零点。关机后移动关节、磁铁/电机/减速器重装或整片擦除，都可能破坏这一假定。

因此先建立可重复的人工定位治具或可靠的零位恢复流程，并规定断电后能否移动关节。不能一上电便发 `!HOME` 试图“自动纠正一切”。

### 15.3 REF 零偏校准

原 `CalibrateHomeOffset()` 包含人工摆 L-Pose 的注释、使能、两次写偏置、移到收拢姿态和重启，中间没有完善的人机确认。复刻工作副本应改为明确的分步流程：

1. 所有节点已通过电机编码器校准，参数、方向、传动比和限位已冻结。
2. 机构有支撑，操作者按定义的 L-Pose 用治具定位并确认，不只凭肉眼摆直。
3. 软件读取当前反馈，验证姿态可接受后才进入写零偏阶段。
4. 若需收拢运动，先验证路径与剩余空间，受限速度执行；每一步有超时和可中断状态。
5. 保存偏置与参数，重启后以机械基准和读回值双重验证。
6. 原流程把 J2/J3 电流恢复到 1 A；实施时必须恢复到本机已批准的值，不能盲目保留固定 1 A。

### 15.4 FK/IK 与整机性能

先关节空间，后笛卡尔空间；先离线计算，后实物动作。当前函数名 `MoveL` 不足以证明末端整条路径是直线，它主要完成位姿逆解并转为关节运动，不能承诺经过碰撞检查的笛卡尔直线插补。

| 验证 | 执行方法 | 应保存的数据 |
|---|---|---|
| FK | 若干已知关节姿态与 CAD/量具比较 | 输入关节、坐标约定、计算位姿、外测位姿 |
| IK | FK→IK→FK 往返，含边界和不可达点 | 可行解、残差、拒绝原因、限位和连续性 |
| 奇异/非法值 | 离线注入 NaN/Inf、零速、极限姿态 | 无非法 CAN 下发；返回明确失败 |
| 重复定位 | 同一姿态双向接近，至少 10 次 | 输出侧/末端分布，不只保存编码器误差 |
| 负载 | 先无工具，再逐步增加已知负载 | 载荷、臂展、速度、温升、误差和供电 |
| 故障 | 单轴掉线、错误反馈、主机断开、复位 | 停止时间、输出行为、恢复条件 |
| 热稳定 | 分段延长到 30～60 分钟低风险运行 | 温度曲线、压降、总线错误、复位与松动 |

末端精度/重复定位指标应在负载、速度、温度、量具和测试姿态确定后设定。这里不承诺原项目宣传参数，也不把 `ok` 当作“目标实际到达”。

客户端需有明确连接目标、当前模式、使能/故障、反馈年龄、命令接受/到达/拒绝状态。第一版只做终端与 CSV，不先开发复杂 GUI。

### 17.2 ESP32 必须单独验收

1. 先修复主线被展平为普通文本的链接文件，逐一核对实际目标，记录上游来源；不能直接相信 `.c` 后缀。
2. 锁定 ESP-IDF、Docker 镜像/工具版本和分区表；不使用未固定版本的环境作为可重复构建基线。
3. 不把空 `dummy-iot.hex` 或空工具 ZIP 当成可烧录资料；确认 Linux/Windows 工具可用。
4. 用无电机的串口回环测试 HTTP/TCP/WebSocket/MQTT，不直接连 REF 运动接口。
5. 默认关闭公共 MQTT 和不必要监听；增加认证、最小命令权限、会话超时和本地授权。
6. 错误 Wi-Fi 凭据、断网、重连、配置写入失败均不使能机械臂。
7. 网络层绝不能绕过电机/主控本地安全机制，不能暴露到公网做无人值守控制。

### 17.3 可选学习方向

G7 后再考虑 URDF/ROS、MoveIt、轨迹规划、视觉和夹爪。URDF 必须来自最终冻结的坐标系、惯量和限位；夹爪需补机械、电控、固件与安全设计，不能因为 REF 有 node 7 类就认定已有可复刻夹爪。

未来公开发布或商业使用前，单独审查根 GPL、README 限制、模型来源、Unity 资产和 Mongoose 等组件的许可。GPL 不等于禁止商业使用，也不自动解决全部混合素材的授权。

## 19. 学习地图与故障排查顺序

| 现象 | 先排查 | 不要先做 |
|---|---|---|
| 无法烧录 | 供电、共地、SWD、复位、芯片容量和工具连接 | 调 PID 或反复全擦 |
| UART 乱码/CAN 不通 | 逻辑电平、晶振、时钟树、位时序、线序和终端 | 按源码函数名假定时序正确 |
| 编码器跳变 | 原始数据、parity、无磁、SPI、磁铁偏心/间隙 | 用滤波把无效数据隐藏 |
| 校准失败 | 电机步距角/相序、磁铁、校准电流、Flash 写入 | 装着减速器反复大电流校准 |
| 振荡/发热 | 电流口径、方向、采样时序、传动松动、饱和 | 同时改多个增益 |
| 断线不停 | 本地超时、授权状态、固件版本 | 只在上位机增加一个停止按钮 |
| REF 等待不返回 | 在线轴、到达掩码、反馈年龄、无限等待和 CAN TX | 直接加大速度“让它快点到” |
| 末端位置不对 | 当前参数与 V2 图冲突、坐标系、零位、总比、TCP | 先怀疑全部 IK 算法或加入视觉纠偏 |

每次实验固定采用“现象 → 假设 → 单变量试验 → 原始数据 → 结论 → 修改 → 回归”。无需先学习完 HAL、FreeRTOS、USB、CAN、控制和机器人学全部课程，但也不跳过当前风险所依赖的基础理论。

## 20. 最近应执行的三个工作包

### 工作包 1：开发与安全基线

完成主工具链安装、Motor-42 原始构建、Flash 保留区审查；在开发板/宿主测试环境验证有界解析和状态机。交付构建日志、固件版本表、FW01～FW06 的开发清单与首批离线测试。尚未完成这些时，不发电机运动命令。

### 工作包 2：单轴实物放行

确定 A 板可追溯来源、电机额定参数、磁铁和夹具；没有 A 板时先补 Motor-42 钻孔与 CPL，统一制造版本。只询价和采购 B0/B1，交付单轴采购单、线束逐针表与首板检查表，不订整套 CNC/谐波减速器。

### 工作包 3：机械数字冻结

在 CAD 中比较视频 V2 两个装配体，定位 42-34/42-40、J4 传动链和 J6 行星比；逐项量测源码与截图不同的几何常量。交付“轴—执行器—传动链—零位—限位—参数来源”矩阵，待定项明确标红或写“未放行”，不以截图替代量测。
