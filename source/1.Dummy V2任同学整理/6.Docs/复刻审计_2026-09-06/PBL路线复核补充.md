# PBL 路线复核补充：Motor-42 本地实验是否可行

日期：2026-09-06。本文是针对新学习路线的定点源码复核，不是重新宣称整个工程已经完成运行验证。

配套主文档：[Dummy V2 项目驱动复刻方案：PBL 版](../../Dummy_V2项目驱动复刻方案_PBL版.md)。原审计结论继续保留；本次改变的是启用某功能之前的依赖关系，不是删除风险。

## 1. 结论

**可以先做 TX-only 编码器观察，再做板上触发的有限次本地闭环，最后才做双向 UART 控制。** 电机位置环可直接通过 C++ 方法调用，不依赖 UART、CAN、REF 或 Python 实时下发目标。

前提是实验固件真正不启动外部命令接收和原有按键动作，而不是只在文档上说“不发送命令”。首次校准本身就会产生力矩并转轴；最基本的固定、断电、匹配电流和当前反馈有效性要求必须在校准前生效。

本轮只制作路线与实验固件改造规格，**未创建或测试可下载的 `motor42_lab` 固件，未安装 ARM 工具链、未烧录、未通电**。不能把文中的新命令、诊断字段或实验阶段名称当成仓库已经实现的功能。

## 3. 最小实验与完整工程保护的界线

| 不变的风险事实 | E2～E4 的缩小实验范围办法 | 重新启用功能时要补的工作 |
|---|---|---|
| 原 UART 解析不可靠 | TX-only，适配器 TX 不接板 RX，固件不启动 RX DMA/IDLE/旧解析 | E5 实现有界命令、STOP 和通信存活策略 |
| 原 CAN 校验/发送故障路径有问题 | 不连接总线，lab 不启动 CAN 路径 | E6 实现电机/测试主机侧校验；REF 侧到 E8 |
| 普通命令没有通用失联停止 | E4 不使用外部运动命令，固定一次动作并设本地最大执行时长 | E5 UART 失联，E6 CAN 失联；不能让查询或重连自动续跑 |
| 编码器失效仍可能输出 | 不能绕开；加同次采样有效性检查、异常即终止本次动作 | 后续再加诊断码、恢复策略、系统级传播 |
| 软件卡死可能保持输出 | 有人看守、固定裸电机、低电流、物理断 24 V；本地超时和有界 SPI 处理正常故障 | 上负载/长时运行前扩展到硬件 watchdog、异常路径和实测停机时间 |
| 原校准按键/自动复位 | 替换本地触发；重启后不自动重放 | 后期维护权限和 Flash 恢复流程 |
| 图纸/BOM/参数冲突 | 裸电机不使用六轴几何和减速器 | E7 解决所选关节，E9 全部冻结，E11 实测核对 |

本地最大执行时长不是通信 watchdog，软件超时也不能覆盖 CPU 完全卡死。这个残余风险没有被隐瞒，而是限定在有人看守、无负载、不接网络的实验边界内；不把这个豁免带到机械关节或整机。

## 4. 哪些数值不是已验证参数

**证**：源码给出的是默认 1 A 运行/2 A 校准，以及 30 转/秒和 100 转/秒²等默认值，不是通用低能量实验参数。

**设**：E4 可从 Δ=256 内部计数（0.005 圈、1.8°）、v=1024 计数/秒（0.02 圈/秒）、a=5120 计数/秒²（0.1 圈/秒²）规划首轮试验；每段设置有限超时，结束后 Sleep。这些是待本机验证的实验设定，不是仓库已经测试通过的性能参数。

**测**：I_RUN_mA、I_CALI_mA、电源限流、允许持续时间、反馈误差阈值、实际时序与温升，仍需依据 A 板/电机匹配资料和实际表现填写。不能因为“42 电机常用 1 A”就拿默认值运行，也不需要为填写这几项先完成六轴 BOM。

## 5. 本次限制

工具存在性复核仍未在 PATH 发现 `cmake` 或 `arm-none-eabi-gcc`。本轮没有构建 lab 固件，也没有验证任何低电流、校准时间或误差阈值。所有执行步骤中的新字段/阶段/协议均明确标为待实现；对现有源码的结论与对新实验的建议分开记录。
