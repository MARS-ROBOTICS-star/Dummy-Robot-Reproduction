# Dummy V2 项目全景科普讲义

## 0. 这到底是一个什么项目

一句话描述：

> Dummy V2 是一台由六个关节组成的桌面机械臂。电脑给它任务，REF 主控把任务变成六个关节目标，CAN 总线把目标送到六块电机控制板，每块电机板根据磁编码器反馈独立控制一个步进电机，电机再通过减速器和传动机构带动机械关节。

它不是一个单纯的机械项目，也不是一个单纯的单片机项目。它至少包含七个领域：

| 领域 | 解决的问题 |
|---|---|
| 机械设计 | 零件形状、装配、刚度、轴承、法兰和外壳 |
| 机械传动 | 电机如何通过同步带、谐波或行星减速器带动关节 |
| 电子硬件 | 如何供电、焊板、驱动电机、读取传感器和传输信号 |
| 嵌入式系统 | STM32 上的程序如何实时运行并控制硬件 |
| 自动控制 | 如何用编码器反馈让电机准确、稳定地到达目标 |
| 机器人学 | 如何在关节角与末端位置姿态之间换算 |
| 上位机软件 | 人如何发送命令、观察状态和调整参数 |

你已有的机械、建模、仿真和运动学基础覆盖了其中很重要的一部分。当前真正陌生的是电子硬件、嵌入式、通信和电机控制之间如何连接。

这份讲义的目标不是让你马上会设计每一块电路，而是让你形成一张“系统地图”。以后看到 `STM32F103`、`CAN`、`MT6816`、`Gerber` 或 `REF` 时，你应该知道它位于地图的哪一层、前后连接什么、为什么需要它。

## 1. 先用一个类比理解整机

可以把 Dummy 看成一个人：

| Dummy 部件 | 人体类比 | 实际职责 |
|---|---|---|
| 电脑和上位机 | 操作者发出的意图 | 指定目标和显示状态 |
| REF 主控板 | 大脑中的动作协调层 | 运动学、六轴协调、命令管理 |
| CAN 总线 | 神经干线 | 在主控和各关节之间传递消息 |
| 六块电机板 | 每个关节的局部反射控制器 | 高频读取反馈并控制本关节电机 |
| MT6816 编码器 | 本体感觉 | 告诉控制器电机轴现在在哪里 |
| TB67H450 | 肌肉的功率放大环节 | 把微控制器的小信号变成绕组电流 |
| 步进电机 | 肌肉 | 把电能变成旋转运动 |
| 减速器和同步带 | 肌腱与关节传动 | 降速、增扭并把运动传到关节 |
| 机械臂结构 | 骨骼 | 承受载荷并决定几何关系 |
| 24 V 电源 | 能量供应 | 为所有板卡和电机提供能量 |

这个类比最重要的结论是：

- REF 不直接产生两相电机电流。
- 电机板不负责计算末端坐标的逆运动学。
- CAN 只传消息，不产生控制算法。
- 编码器只测角度，不会自己让电机停到目标。
- 减速器只改变机械速度和转矩，不知道软件目标。

各层分工清楚，整机才容易扩展和排错。

## 2. 这不是“一块控制板带六个电机”

Dummy 采用分布式控制结构。

```text
                    PC
                     |
              USB / UART / WiFi
                     |
              REF（STM32F405）
                     |
                CAN 1 Mbit/s
       +------+------+------+------+------+
       |      |      |      |      |      |
      J1     J2     J3     J4     J5     J6
    F103   F103   F103   F103   F103   F103
     电机板 电机板 电机板 电机板 电机板 电机板
```

### 2.1 为什么要分成七个 STM32

一块 REF 使用 STM32F405，六块电机板各使用 STM32F103，所以整机至少有七个 STM32。

这么设计有三个原因：

1. 每个电机都需要很快的本地反馈控制，放在电机旁边延迟更小。
2. 六个电机的高频计算被分散到六块板，不压在一块主控上。
3. REF 只需要发送较高层目标，布线从大量 PWM/传感器线简化为一条共享 CAN 总线。

### 2.2 三个时间尺度

系统不是所有程序都以同样速度运行：

| 层级 | 典型频率 | 每次做什么 |
|---|---:|---|
| 人与上位机 | 按需或几十 Hz 以下 | 点击、输入目标、看状态 |
| REF 协调层 | 200 Hz，即每 5 ms 一次 | 使能时下发关节命令，失能时主动查询角度，并计算位姿 |
| 电机本地闭环 | 20 kHz，即每 50 μs 一次 | 读编码器、估计速度、算电流、更新驱动 |

20 kHz 不是电机每秒转两万圈，也不是 CAN 每秒发送两万条命令。它只是电机板内部控制算法的执行频率。

## 3. 从一个命令到真实运动

下面用仓库使用指南中的末端命令举例：

```text
@175,44,160,-135,-13.54,-14.66
```

它的含义大致是：把末端移动到给定的 XYZ 位置和 ABC 姿态。

### 第 1 步：电脑发送字符

DummyStudio 或串口工具把这一行字符通过 USB 虚拟串口发送给 REF。

此时传输的是人能阅读的 ASCII 文本。ASCII 只是字符编码方式，并不是一种电线。USB、UART 都可以承载 ASCII 文本。

### 第 2 步：REF 识别命令类型

REF 看到第一个字符是 `@`，知道这是末端位姿命令。

项目中常见命令前缀：

| 前缀 | 含义 |
|---|---|
| `!` | 整机状态命令，例如启动、停止、回零 |
| `#` | 查询或参数命令，例如读取关节角、修改增益 |
| `>` | 六个关节角目标 |
| `@` | 末端位置姿态目标，需要逆运动学 |
| `&` | `>` 的关节角目标别名；当前固件中两者没有功能差异 |

命令入口、参数解析和机器人动作分别位于 `2.Firmware/dummy-ref-core-fw/UserApp/protocols/ascii_protocol.cpp`、`UserApp/protocols/cmd_protocol.cpp` 和 `Robot/instances/dummy_robot.cpp`。

### 第 3 步：逆运动学把末端目标变成六个关节角

REF 调用 IK，也就是逆运动学。

```text
末端目标 XYZABC -> IK -> J1、J2、J3、J4、J5、J6 目标角
```

同一个末端姿态可能有多组关节解。程序会计算最多八组候选解，删除超过关节范围的解，再选择相对当前姿态变化较小的一组。

如果发送的是 `>` 关节角命令，这一步就不需要 IK。

### 第 4 步：REF 检查限位并协调速度

REF 知道每个关节的软件角度范围，例如 J1 是 -170°～170°。目标超过范围时，`MoveJ` 不会更新目标；但当前命令层仍返回 `ok`，所以上位机不能仅凭 `ok` 判断目标有效。

它还会根据六个关节需要转动的角度，估算各轴速度，让多个关节尽量协调到达。

这属于整机运动协调，不是电机内部 20 kHz 闭环。

### 第 5 步：关节角换算成电机轴转数

电机与关节之间有减速器，因此“关节转 1°”不等于“电机转 1°”。

代码使用：

```text
电机转数 = 关节角度 / 360 × 总减速比
```

例如 J1 的软件总减速比为 30：

```text
J1 转 12° -> 电机转 12 / 360 × 30 = 1 圈
```

这里的 30 是整条机械传动链的总换算，不一定等于某一个谐波减速器铭牌上的数字。

### 第 6 步：REF 通过 CAN 发给对应节点

每块电机板有节点 ID。J1～J6 通常设置为 1～6。

CAN 帧的标准 ID 在这个项目中按以下方式编码：

```text
CAN ID = (节点 ID << 7) | 命令编号
```

一帧中会放入目标电机转数、速度限制等数据。节点 1 只执行发给节点 1 或广播节点 0 的消息。

### 第 7 步：电机板把“圈”换成内部计数

项目把一个 1.8° 步进电机的一圈表示为：

```text
200 个整步 × 256 个软件细分 = 51200 个内部计数
```

所以 CAN 中的 `1.0 圈` 到了电机板，会变成 `51200` 个内部位置计数。

注意：这不是说 MT6816 原始分辨率就是 51200。MT6816 原始角度是 14 位，也就是一圈 16384 个位置。校准表负责把传感器原始位置映射到控制器使用的 0～51199 电机位置尺度。

### 第 8 步：运动规划器生成平滑目标

如果直接把目标从 0 跳到 51200，电机可能突然加速、失步或振荡。运动规划器会根据速度和加速度限制逐步改变目标。

这相当于先设计一条“怎么过去”的时间曲线，而不是只说“最终去哪”。

### 第 9 步：20 kHz 闭环计算误差

每 50 μs，电机板执行一次：

```text
读取实际角度
-> 处理一圈回绕并累计多圈位置
-> 估计速度
-> 目标位置减实际位置得到误差
-> DCE/PID 算出需要多大的电流和什么方向
```

核心代码在 `2.Firmware/dummy-42motor-fw/Ctrl/Motor/motor.cpp`。

### 第 10 步：双 TB67H450 产生两相电流

STM32 的 GPIO/PWM 只能输出很小的逻辑信号，不能直接驱动电机绕组。

项目使用两个 TB67H450，每个负责一个步进电机绕组。STM32 计算 A、B 两相应有的正弦电流方向和幅值，TB67H450 根据这些信号控制真实绕组电流。

```text
STM32 算法 -> PWM/VREF + 方向信号 -> TB67H450 -> A/B 相绕组 -> 转矩
```

代码把这个过程称为 `FOC` 电流矢量。它与常见无刷电机 FOC 的思想相似，都是控制旋转电流矢量，但这里对象是两相步进电机，不应把它简单等同于三相无刷电机 FOC。

### 第 11 步：MT6816 继续反馈

电机轴转动后，轴端磁铁一起转。MT6816 测量磁场方向，STM32 通过 SPI 读取角度。新的实际角度进入下一次 20 kHz 计算，闭环由此形成。

```text
目标 -> 控制器 -> 驱动 -> 电机 -> 编码器 -> 控制器
  ^                                           |
  +-------------------------------------------+
```

没有编码器反馈叫开环；把实际结果送回来修正命令叫闭环。

### 第 12 步：状态返回 REF 和电脑

电机板通过 CAN 返回当前位置与是否到达目标。REF 把电机圈数除以减速比再乘 360，恢复成关节角度，并可通过 USB 返回电脑显示。

至此，一条从文字命令到机械运动再到状态显示的闭环链条完成。

## 4. 机械部分：J1～J6 和传动链

### 4.1 六自由度是什么意思

自由度可以理解为机械系统能够独立变化的运动变量。Dummy 有六个转动关节，因此通常称为六自由度机械臂。

| 关节 | 大致角色 | 对整机的影响 |
|---|---|---|
| J1 | 基座旋转 | 决定机械臂朝向 |
| J2 | 肩关节 | 抬起或放下大臂，负载很大 |
| J3 | 肘关节 | 改变伸展距离，负载很大 |
| J4 | 腕部第一轴 | 调整末端姿态 |
| J5 | 腕部第二轴 | 调整末端姿态 |
| J6 | 末端旋转轴 | 绕工具轴旋转 |

J1～J3 对末端位置影响很大，通常使用更大的 42 电机；J4～J6 更关注腕部紧凑性，使用 35 电机。

### 4.2 为什么电机不能直接连接关节

步进电机通常转得较快，但直接输出转矩和保持刚度不足。机械臂需要：

- 更大的输出转矩
- 更低且可控的关节速度
- 更紧凑的传动布置
- 尽可能小的回程间隙

所以需要减速器和同步带。

### 4.3 三种主要传动元件

| 元件 | 通俗解释 | 优点 | 需要关注 |
|---|---|---|---|
| 同步带 | 带齿的皮带与带轮啮合传动 | 轻、便宜、可改变电机位置 | 张紧、齿数比、带长、柔性 |
| 谐波减速器 | 通过柔性齿轮变形实现大减速比 | 紧凑、减速比大、间隙较小 | 成本、刚度、寿命、安装精度 |
| 行星减速器 | 多个行星齿轮围绕太阳轮传动 | 紧凑、承载能力较好 | 回差、噪声、具体减速比 |

`mini11` 和 `mini8` 是产品尺寸/系列名称，不是 11:1 或 8:1。仓库参数图显示 MINIF11 和 MINIF08 都有 30:1、50:1 两档；视频 V2 装配体使用的名称包含 `-50`，因此它指向 50:1 版本。

### 4.4 总减速比为什么必须与固件一致

REF 固件当前写死的软件总减速比是：

| 关节 | 总减速比 |
|---|---:|
| J1 | 30 |
| J2 | 30 |
| J3 | 30 |
| J4 | 24 |
| J5 | 30 |
| J6 | 50 |

这里存在一项关键版本冲突：视频 V2 装配体指向 50:1 的 MINIF11/MINIF08，但 REF 固件的 J1～J5 仍是 30、30、30、24、30。这些固件值更像另一套机械配置的遗留值，不能直接当作视频 V2 的真实机械减速比。正式运动前必须按实物型号、同步轮齿数和关节实测结果逐轴确认；如果机械总减速比是 50 而软件仍写 30，命令 12° 时实际角度就不会是 12°。

总减速比可能由多个阶段相乘或相除得到：

```text
总减速比 = 同步带阶段 × 谐波/行星阶段 × 其他机械阶段
```

### 4.5 编码器测到的是电机轴，不是最终关节

MT6816 位于电机轴端。因此程序先得到电机角，再根据减速比推算关节角。

这带来一个重要限制：

- MT6816 是单圈绝对角度传感器，知道电机轴在一圈内的位置。
- 电机板靠软件累计跨圈变化，得到运行期间的多圈位置。
- 断电后，多圈累计会丢失。
- 减速器后没有独立的关节绝对编码器，也没有机械限位开关自动寻找零点。

这就是使用指南要求上电前折叠机械臂并对准刻度的根本原因。这里的 `HOME` 不是工业机器人那种“碰限位开关自动找原点”，而是建立在已知初始摆放和已保存偏移上的软件运动。

## 5. 电子硬件：电从哪里来，信号怎么走

### 5.1 PCB、PCBA 和芯片的关系

```text
原理图 -> PCB 布局 -> 制造裸板 -> 焊上元器件 -> PCBA
```

| 名词 | 含义 |
|---|---|
| 原理图 | 描述哪些电子元件如何连接，强调逻辑关系 |
| PCB | Printed Circuit Board，印制电路板；也常指设计文件或裸板 |
| PCBA | 已经把元件焊到 PCB 上的成品板 |
| 芯片 | PCBA 上执行某种功能的集成电路，例如 STM32、MT6816 |

### 5.2 24 V 为什么还要 3.3 V

整机以 24 V 供电，原因之一是电机需要较高功率。但 STM32 和大多数数字逻辑工作在 3.3 V 左右，不能直接接 24 V。

这里的“24 V 电源”通常是一个外置 AC-DC 适配器：输入家庭交流市电，输出 24 V 直流。视频 V2 BOM 选的是 24 V/6 A，表示它最多可提供约 6 A，并不是始终把 6 A 强行灌进机械臂；负载在允许范围内按需要取电。

电源链可简化为：

```text
24 V 输入
  |---> TB67H450 和电机功率部分
  |
  +---> DC-DC 降压 -> LDO/3.3 V -> STM32、MT6816、CAN 逻辑
```

DC-DC 是高效率的开关降压器；LDO 是结构较简单、输出较干净的线性稳压器。两者不是同一种器件。

当前视频 V2 不能由电脑 USB 直接供电：普通 USB 提供的是 5 V 和有限电流，而电机功率级需要 24 V。REF 的 USB-C 口用于 STM32 USB CDC 通信和 CP2102/ESP32 调试，USB 的 5 V VBUS 没有接入 REF 的 24 V 主电源链；只插 USB 可能出现一个串口设备，但不会让 REF 主控和六块电机板正常工作。该板也没有 USB-PD 协商芯片，不能从支持快充的 USB-C 充电器自动索取 24 V。

### 5.3 Motor-42/Motor-35 板上有哪些功能区

每块电机板可分为五区：

| 功能区 | 主要器件 | 职责 |
|---|---|---|
| 电源 | ME3116、LP2992、电容、TVS、二极管 | 把 24 V 变为逻辑电源并提供保护 |
| 计算 | STM32F103CBT6 | 运行 20 kHz 控制和通信程序 |
| 位置反馈 | MT6816 + 轴端磁铁 | 测量电机角度 |
| 功率驱动 | 2×TB67H450 + 0.1 Ω 采样电阻 | 控制两相绕组电流 |
| 通信调试 | SN65HVD232、DIP、UART、SWD | CAN、节点 ID、烧录和调试 |

Motor-42 和 Motor-35 的控制架构基本相同，机械尺寸和部分功率电容配置不同。两套固件代码也几乎相同，主要默认增益略有区别。

### 5.4 REF 板上有哪些功能

REF 是 Robot Embedded Framework 的项目名称，仓库 USB 描述中也使用了这个名称。实践中可以把它理解为 Dummy 的整机主控制板，而不是“参考文献”或电机功率板。

REF 主要包含：

| 器件/模块 | 作用 | 是否是首月主线 |
|---|---|---|
| STM32F405 | 整机主控 | 后置 |
| CAN 收发器 | 与六个电机节点通信 | 后置 |
| USB | 连接电脑 | 后置 |
| ESP32 | 可选 WiFi 网桥 | 非必需 |
| CP2102 | USB 转串口，主要服务 ESP32 烧录/通信 | 非必需 |
| MPU6050 | 惯性传感器 | 非首要功能 |
| OLED | 显示状态 | 非首要功能 |
| NRF24L01 | 2.4 GHz 无线通信 | 非必需 |
| RGB 灯环/蜂鸣器 | 状态提示 | 非必需 |

这说明 REF 板集成功能很多，但让机械臂运动的最小系统并不需要所有外设。

### 5.5 连接器和线束

电机板有两类容易混淆的 6 针接口：

- P1/P2：24 V、GND、CANH、CANL，用于供电和 CAN 级联。
- P3：SWD 和 UART，用于烧录与调试。

把 P3 当作电源/CAN 接口可能损坏硬件。

REF 到 J1 的第一条线与后续 J1 到 J6 的线序处理不同。文档称为“同向线”和“反向线”，并涉及 CAN 两线交换。不要根据插头看起来能插进去就通电，必须按 `6.Docs/Cable_connection.pdf` 和 `6.Docs/Pins definations.pdf` 逐针做通断检查。

## 6. STM32 与嵌入式程序

### 6.1 STM32 是什么

STM32 是一系列微控制器，也常称 MCU 或单片机。

它是一台缩小到一颗芯片里的专用计算机，包含：

- CPU：执行指令
- Flash：断电后仍保存程序
- RAM：运行时保存变量
- GPIO：读写引脚
- Timer：精确定时和产生 PWM
- UART/SPI/CAN/USB：与外界通信
- ADC：读取模拟电压

STM32 不是电机驱动芯片。它负责计算，TB67H450 负责功率输出。

### 6.2 F103 和 F405 的区别

| 型号 | 所在位置 | 为什么放这里 |
|---|---|---|
| STM32F103CBT6 | 六块电机板 | 外设够用、成本较低，负责单电机闭环 |
| STM32F405RGT6 | REF | 性能和存储更强，负责 RTOS、USB、运动学和多轴协调 |

型号里的每一段都可能代表系列、封装、Flash 容量等信息，不能随意拿另一颗“也叫 F103”的芯片替换。

### 6.3 固件和上位机软件的区别

| 类别 | 运行在哪里 | 本项目例子 |
|---|---|---|
| 固件 Firmware | STM32/ESP32 芯片中 | `2.Firmware/` |
| 上位机软件 Software | Windows/Linux/macOS 电脑中 | `3.Software/` |

固件编译后得到 HEX/BIN，再烧进 STM32。Python 脚本或 DummyStudio 不会被烧进电机板。

### 6.4 从源码到芯片的过程

```text
.c/.cpp 源码
-> 编译器生成目标文件
-> 链接器按芯片内存布局组成 ELF
-> objcopy 生成 HEX/BIN
-> ST-Link 通过 SWD 写入 STM32 Flash
-> 芯片复位并从 Flash 执行
```

相关名词：

| 名词 | 通俗解释 |
|---|---|
| GNU Arm Toolchain | 真正把 C/C++ 变成 ARM 机器码的一组工具 |
| CMake | 告诉编译工具要编哪些文件、用哪些选项、如何链接 |
| Linker Script | 告诉链接器 Flash/RAM 在哪里、各段如何摆放 |
| ELF | 包含程序、符号和调试信息的主要构建产物 |
| HEX/BIN | 常用于烧录的固件数据格式 |

### 6.5 HAL、CMSIS、CubeMX 和 FreeRTOS

这四个词经常同时出现，但职责不同：

| 名词 | 通俗解释 | 在项目中的位置 |
|---|---|---|
| CMSIS | ARM Cortex 内核的统一基础接口 | 最底层公共基础 |
| HAL | ST 提供的外设操作库 | 配置 GPIO、SPI、CAN、Timer 等 |
| CubeMX | 图形化配置引脚、时钟、外设并生成初始化代码的工具 | 生成部分 `Core/` 代码和 `.ioc` |
| FreeRTOS | 在一个 MCU 内管理多个任务的实时操作系统 | REF 使用，电机板不依赖它完成 20 kHz 环 |

CMake 负责“怎么构建”，FreeRTOS 负责“运行时怎么调度”，HAL 负责“怎么访问外设”，它们不能互相替代。

### 6.6 SWD 和 ST-Link

SWD 是调试接口规范，ST-Link 是使用该接口的调试器。

```text
电脑 -> ST-Link -> SWDIO/SWCLK/GND -> STM32
```

它不仅能烧录，还能：

- 暂停程序
- 设置断点
- 单步执行
- 查看变量和寄存器
- 在程序损坏时重新擦除 Flash

UART 串口主要用来收发运行时文本；SWD 用来控制和观察 MCU 内部执行。两者不是一回事。

## 7. 电机控制：为什么步进电机也能闭环

### 7.1 步进电机的基本直觉

两相步进电机有 A、B 两组绕组。按合适的方向和大小给两相通电，定子磁场会指向某个角度，转子会试图跟随这个磁场。

普通开环步进驱动器只相信“发出了多少步”，不验证转子是否真的跟上。负载太大时可能失步。

Dummy 在电机轴上加 MT6816，持续测量实际位置，所以它是闭环步进系统。

### 7.2 驱动器、控制器和电机不是同一个东西

```text
控制器 STM32：决定应该输出什么
驱动器 TB67H450：把小信号放大为绕组电流
电机：把绕组电流变成转矩和运动
编码器 MT6816：测量运动结果
```

项目中“驱动”一词可能指三种完全不同的东西：

| 语境 | “驱动”指什么 |
|---|---|
| TB67H450 电机驱动 | 功率芯片 |
| `Port/` 中的设备驱动 | 操作某个硬件的软件代码 |
| Windows USB 驱动 | 操作系统识别 USB 设备的软件 |

遇到“驱动有问题”时，必须先问是哪一种。

### 7.3 PWM 和斩波电流

PWM 是快速开关电压，通过导通时间比例控制平均效果。占空比 50% 并不直接等于电机转速 50%。

TB67H450 使用 VREF 和 0.1 Ω 采样电阻调节绕组电流。STM32 给出电流目标，驱动芯片内部快速开关功率管，使实际电流接近目标。这称为斩波电流控制。

因此有两层控制：

```text
STM32 软件外环：位置/速度误差 -> 需要的电流
TB67H450 硬件电流环：电流目标 -> 绕组实际电流
```

### 7.4 PID 和 DCE

PID 是根据误差的比例、积分、微分部分计算控制量的方法。项目电机固件除了速度 PID，还使用名为 DCE 的位置/速度误差控制结构。

初期不必纠结缩写的完整英文。先理解参数效果：

- Kp 太小：响应软、误差大。
- Kp 太大：可能振荡、噪声和发热增加。
- Ki 用来消除长期偏差，但过大容易积累和振荡。
- Kd/Kv 与变化速度有关，可增加阻尼，也会放大噪声。

调参不能弥补接反的编码器方向、错误的减速比、松动的磁铁或错误的采样周期。

### 7.5 轨迹规划和闭环控制的区别

| 功能 | 回答的问题 |
|---|---|
| 轨迹规划 | 目标应该随时间怎样变化，避免突然跳变 |
| 闭环控制 | 实际状态偏离当前目标时，应该施加多大电流 |

可以把轨迹规划看成道路规划，把闭环看成驾驶员不断修正方向盘和油门。

## 8. 编码器与三种校准

### 8.1 MT6816 如何测角度

电机轴末端安装一块磁铁，MT6816 位于磁铁附近。磁铁转动时磁场方向变化，芯片输出 14 位角度。

```text
一圈 = 2^14 = 16384 个原始位置
```

STM32 通过 SPI 读取两个寄存器，检查奇偶校验和无磁标志。

磁铁尺寸、磁化方向、同心度和轴向间隙都会影响结果。编码器算法再好，也不能完全修复严重偏心或错误磁铁。

### 8.2 第一层：编码器线性化校准

传感器、磁铁和安装会产生非线性。项目让电机缓慢经过 200 个整步，每步正反向各采样，并生成 16384 项查找表存入 Flash。

运行时不做复杂拟合，只需：

```text
校准角度 = 查表[原始角度]
```

这是用 32 KB 存储换取 20 kHz 下的计算速度。

### 8.3 第二层：电机/机械零点偏移

编码器的 0° 是磁铁和芯片定义的电气零点，不一定是机械关节的 0°。程序需要保存 `encoderHomeOffset`，把当前机械参考姿态映射为软件零点。

### 8.4 第三层：整机姿态校准

REF 的 `!CALIBRATION` 是两阶段关节零位偏移流程：先在人工摆放的参考姿态设置一次偏移，再运动到 `(0,0,90,0,0,0)` 设置第二次偏移，恢复参数后重启 REF。它与单电机的 16384 点编码器线性化校准不是同一件事。

### 8.5 `HOME`、`CALIBRATION` 和调 PID 的区别

| 操作 | 解决的问题 |
|---|---|
| 编码器校准 | 原始磁角与电机实际电角/位置不够线性 |
| Home Offset | 编码器零点与机械零点不一致 |
| `!CALIBRATION` | 六轴整机参考姿态和零点关系 |
| `!HOME` | 命令机械臂运动到约定的 Home 姿态 |
| PID/DCE 调参 | 到达目标时太软、振荡、超调或响应慢 |

项目里有人说“重新校准”，必须先确认他说的是哪一层。

## 9. CAN、UART、USB、WiFi 和 Fibre

### 9.1 UART

UART 是简单的点对点串行通信。通常至少有 TX、RX 和 GND。

在本项目中：

- 电机板 UART1 可直接接电脑调试单个电机。
- 它支持 `c`、`v`、`p` 电流/速度/位置命令。
- 这是首月绕开 REF 和 CAN 的最短闭环路径。

### 9.2 CAN

CAN 是多个控制器共享的差分总线，最初广泛用于汽车。

它适合机械臂，因为：

- 多个节点共用 CANH/CANL 两根信号线。
- 有仲裁和错误检测机制。
- 差分信号抗干扰能力较好。
- 每条消息带标识符，节点可判断是否与自己有关。

CAN 总线通常需要：

- CANH 和 CANL 双绞
- 总线两端各一个 120 Ω 终端电阻
- 所有节点波特率一致，本项目为 1 Mbit/s
- 主干式布线和尽量短的支线

CAN 的“主控/从站”是项目逻辑分工，不代表 CAN 电气协议本身只能由一个主机说话。

### 9.3 SN65HVD232

STM32 CAN 外设处理数字帧，但不能直接驱动 CANH/CANL。SN65HVD232 是 CAN 收发器，负责逻辑电平与差分总线电平之间的转换。

```text
STM32 CAN 外设 <-> SN65HVD232 <-> CANH/CANL
```

它不是 CAN 协议算法本身，也不是 USB-CAN 调试器。

### 9.4 节点 ID 和 DIP 拨码

六块电机板硬件相似，需要一个号码区分身份。板上使用四位拨码开关，其中三位被固件读取为 3 bit 节点 ID，可表示 0～7；整机中使用 1～6。剩余一位控制板载 120 Ω CAN 终端电阻。

节点 ID 类似教室里的座位号，不是芯片唯一序列号，也不是 IP 地址。

### 9.5 USB CDC

USB CDC 会让 STM32 在电脑上看起来像串口，因此也叫虚拟串口。DummyStudio 主要通过它发送 ASCII 命令。

USB 插头是物理接口，CDC 是 USB 设备类别，ASCII 是线上数据的文本表示，这三者属于不同层级。

### 9.6 Fibre

Fibre 是项目从 ODrive/Robot Embedded Framework 体系继承的二进制对象通信协议。它允许 Python CLI 访问 REF 暴露的对象和函数。

它不是“光纤”，也不是 CAN。初期只用 ASCII 时可以暂不学习 Fibre。

### 9.7 ESP32 和 WiFi

ESP32 在本项目中主要作为 UART 与网络之间的桥。它让浏览器或网络客户端间接访问 REF。

```text
网页/WiFi <-> ESP32 <-> UART <-> REF
```

移除 ESP32，REF 和六轴 CAN 控制仍然可以工作。因此 WiFi 是扩展功能，不是机械臂控制核心。

## 10. REF 中的机器人学

### 10.1 坐标系和 DH 参数

每个关节都有自己的坐标系。DH 参数是一种用少量参数描述相邻关节坐标关系的方法。

本项目构造运动学求解器时使用六个关键几何尺寸：

```text
0.109, 0.035, 0.146, 0.115, 0.052, 0.072 米
```

它们对应基座、臂长、腕部偏置等几何量。参数必须与实际选定的机械装配一致。

### 10.2 FK 正运动学

```text
已知六个关节角 -> 计算末端 XYZ 和姿态
```

这类似你在 CAD 中给六个转轴施加角度后，测量末端位姿。

### 10.3 IK 逆运动学

```text
已知末端 XYZ 和姿态 -> 求六个关节角
```

IK 可能：

- 有多组解
- 没有解
- 解超过关节范围
- 接近奇异位形，数值和运动表现敏感

REF 会从有效解中选择一组，但这不等于完整的碰撞规划。现有代码主要做关节限位检查，没有完整环境避障。

### 10.4 运动学正确不等于机械臂就准确

末端误差还可能来自：

- 连杆实际尺寸误差
- DH 坐标定义错误
- 机械零位误差
- 减速比错误
- 谐波和同步带回差/弹性
- 结构变形
- 编码器只在电机侧，无法直接测得减速器输出误差

所以机械、标定和控制不能被运动学公式取代。

## 11. 三套机械模型为什么会同时出现

这个仓库不是一次性发布的产品包，而是社区资料的组合：

```text
稚晖君原始原理与模型
        +
木子晓汶重做 PCB/部分机械和固件
        +
论坛视频 V2 机械版本
        +
整理者的 BOM、接线和使用指南
```

所以“项目版本”不是一个覆盖全部软硬件的统一版本号。

### 11.1 稚晖君原版模型

路径：`4.Model/稚晖君原版模型/`

主要特点：

- `Dummy v164.step` 是原始整机设计参考。
- 只有少量 STEP，没有完整 STL、工程图和参数化源文件。
- 装配体中使用的电机、CSF 谐波等选型与视频 V2 BOM 不同。
- 适合研究最初设计意图，不适合直接套用视频 V2 采购单加工。

看到“原版”时，应想到“设计源头和参考”，而不是“当前要下单的生产文件”。

### 11.2 木子晓汶版本

路径：`4.Model/木子晓汶版本3D模型/`

主要特点：

- 与木子晓汶重做的 35/42 电机板路线关系较近。
- 文件种类最丰富，含 SLDPRT、SLDDRW、DXF、STEP、STL。
- `Out_stp1/` 有 CNC、工程图、二维轮廓和 SolidWorks 源文件。
- 根目录、`latest/`、`BACK/`、v1/v2/v3 等多代文件并存。
- 可编辑性好，但版本管理比较混乱。

看到这个目录时，应想到“可研究、可修改的机械工程资料库”，而不是默认所有文件能直接混装。

### 11.3 Dummy V2 视频款

路径：`4.Model/Dummy V2 版本 视频款/`

主要特点：

- 顶层 README 和视频教学所指的复刻对象。
- `5.Bom/dummy V2版本_bom.xlsx` 只声明对应这个版本。
- 有总装 STEP、CNC STEP、打印 STL/3MF 和 PDF 工程图。
- 对不熟悉 SolidWorks 的人更容易查看和交付加工。
- 有普通件、`改版/`、两个总装 STEP、打印与 CNC 两条几何不同的制造路线。
- 装配体中的部分电机命名与 BOM 仍存在疑点，需要 CAD 审计。

因此我们选择它作为基线，但“锁定视频 V2”并不等于盲目把该目录所有文件一起下单。

### 11.4 三套模型不能混装的原因

同一个 `J1` 名字只说明它们都承担第一关节角色，不说明：

- 安装孔相同
- 电机相同
- 减速器相同
- PCB 外壳相同
- 法兰厚度相同
- 连杆尺寸相同
- DH 参数相同

文件命名、零件集合和装配体中的电机规格已经表明木子版与视频 V2 不是同一套机械发布。仅凭同名关节不能证明接口兼容；跨版本替换可能直到装配时才暴露孔位和干涉问题。

## 12. 机械文件格式：看到后应该想到什么

| 后缀 | 是什么 | 主要用途 | 不应误解为 |
|---|---|---|---|
| `.STEP/.step` | 通用实体 CAD 交换格式 | 看零件、装配、交给 CNC | 完整参数化源文件 |
| `.STL/.stl` | 三角网格外形 | 3D 打印切片 | 易修改的机械源模型 |
| `.3MF/.3mf` | 更现代的打印项目格式 | 保存模型、摆放等打印信息 | 必然比 STL 几何更新 |
| `.DXF/.dxf` | 二维轮廓交换格式 | 激光切割、二维加工 | 三维装配体 |
| `.SLDPRT` | SolidWorks 零件源文件 | 参数化修改单个零件 | 装配体或工程图 |
| `.SLDDRW` | SolidWorks 工程图 | 尺寸、公差、加工标注 | 三维实体本身 |
| `.PDF` 工程图 | 固定版式制造图 | 查看尺寸、与加工方沟通 | 可自动更新的 CAD 源文件 |

一个 STEP 文件能打开，不代表已经具备生产条件。加工还需要确认材料、公差、表面处理、螺纹、数量和版本。

## 13. PCB 文件格式：从设计到生产

| 文件/名词 | 回答的问题 |
|---|---|
| `.SchDoc` 原理图 | 元件为什么这样连接 |
| `.PcbDoc` PCB 源文件 | 元件放在哪里、铜线怎么走、板子多大 |
| Gerber | PCB 厂每一层铜、阻焊、丝印怎么制造 |
| Drill | 哪里钻孔、孔径多大 |
| BOM | 每种元件是什么、多少个、买哪个料号 |
| CPL/Pick-and-Place | 每个贴片元件的坐标、角度和所在面 |
| 钢网 | 批量把焊膏印到焊盘上的模板 |
| SMT | 贴片元件装配工艺 |
| PCBA | 已经完成元件装配的电路板 |

Gerber + BOM 并不自动等于可以委外贴片。贴片厂通常还需要 CPL，BOM 中还要有可采购的准确料号和封装。

仓库 Motor-42 有 Gerber、总 BOM 和带内嵌贴装数据的交互式 HTML BOM，但没有发现可直接交付贴片厂的独立 CPL 文件，所以正式委外前需要从 PcbDoc 重新导出并检查坐标、层和方向。

## 14. 仓库目录应该怎样看

### `1.Hardware/`

这是电子硬件设计，不是机械五金。

| 子目录 | 内容 |
|---|---|

## 15. 上电后各块板实际在做什么

### 15.1 电机板上电

1. STM32F103 读取三位 DIP，确定 CAN 节点 ID。
2. 从 Flash 模拟 EEPROM 读取电流、速度、加速度、增益和 Home Offset。
3. 初始化 TB67H450 和 MT6816。
4. 启动 100 Hz 慢任务和 20 kHz 电机中断。
5. 如果校准表无效，状态为 `NO_CALIB`，功率输出保持休眠。
6. 主循环处理编码器校准与参数写入。

### 15.2 REF 上电

1. 初始化 USB、UART 和 CAN。
2. 初始化 DummyRobot 对象及六轴参数。
3. 初始化 MPU6050；当前代码会持续等待它连接成功。
4. 创建 FreeRTOS 控制、命令、OLED 和 RGB 任务。
5. 启动 200 Hz 协调定时器。
6. 等待电脑命令。

### 15.3 为什么改源码默认值后可能没有变化

电机板启动时 EEPROM 参数优先于代码中的默认值。第一次运行后默认参数已被写进 Flash，后来只修改 `main.cpp` 的默认值，旧 EEPROM 仍会覆盖它。

因此必须区分：

- 编译进固件的默认值
- 当前 RAM 中正在使用的值
- Flash/EEPROM 中跨重启保存的值

## 16. 容易混淆的十组概念

| 不要混淆 | 区别 |
|---|---|
| STM32 与 TB67H450 | 前者计算，后者输出功率 |
| REF 与电机板 | 前者协调六轴，后者闭环控制一个电机 |
| PCB 与 PCBA | 前者通常是裸板/板设计，后者是已焊元件成品 |
| 固件与上位机 | 前者跑在 MCU，后者跑在电脑 |
| UART 与 ASCII | UART 是传输方式，ASCII 是字符表示 |
| USB 与虚拟串口 | USB 是总线，CDC 让设备表现成串口 |
| CAN 外设与收发器 | STM32 处理帧，SN65HVD232 驱动差分电线 |
| 编码器角与关节角 | 前者在电机轴，后者还要经过减速比和零位换算 |
| 轨迹规划与 PID/DCE | 前者生成平滑目标，后者修正跟踪误差 |
| 回零与编码器校准 | 前者建立机械参考，后者修正磁角映射 |

还有两个词在不同领域会重复：

| 词 | 可能含义 |
|---|---|
| 模型 | CAD 几何模型、DH 运动学模型、控制对象模型、某个产品版本 |
| 控制器 | REF 主控制板、电机板 MCU、某段 PID/DCE 算法、TB67 驱动系统 |

听到这些词时，要根据上下文确认具体层级。

## 17. 项目当前并不是一套无歧义产品资料

需要提前接受以下事实：

- 视频 V2 目录内有两个总装 STEP 和改版基座/J1。
- 打印件与 CNC 件不只是同一几何换材料，部分同名件尺寸不同。
- 视频 V2 的两个装配体都同时出现 `42-34Motor Assembly` 和 `42-40Motor Assembly`，但 BOM 只列出 42×40 这一规格，电机选型存在疑点。
- mini11/mini8 名称不能直接推出减速比。
- J6 行星减速器具体型号和参数不足。
- 紧固件只有购买截图，没有逐零件消耗表。
- REF 的 OLED BOM 与固件接口描述存在疑点。
- REF CubeMX/工具链版本较旧，重新生成代码可能产生变化。
- Dummy 电机/REF 应用代码没有自动测试；仓库中的测试文件属于第三方 Mongoose 网络库。此外也没有 ROS、URDF 和完整夹爪资料。

这意味着复刻过程也包含“工程考古”：你要把分散资料重新验证成自己的、可追踪的基线。

## 18. 现在你应该形成的核心认知

### 认知 1：机械臂有两层控制

- REF 管六轴协调和运动学。
- 每块电机板管一个电机的高速闭环。

### 认知 2：电机板本身就是一个完整小系统

它包含 MCU、传感器、控制算法、功率驱动、通信和参数存储。做通一块电机板，已经覆盖了嵌入式学习的大部分核心环节。

### 认知 3：通信协议只是传目标和状态

CAN 不替你完成 PID，UART 不替你驱动电机，USB 不替你计算 IK。

### 认知 4：机器人精度是一条误差链

```text
命令 -> 运动学 -> 减速比 -> 控制 -> 电机 -> 传动 -> 结构 -> 末端
```

任一层错误都会出现在末端。

### 认知 5：先做单电机不是缩小目标，而是截取完整闭环

单个 Motor-42 已经包含：

- STM32 固件
- 定时器和中断
- SPI 传感器
- Flash 参数
- 电机功率驱动
- 实时闭环控制
- UART 和 CAN 通信
- 焊接、烧录、测量与排错

它是整机最小但完整的技术切片。

## 19. 看见这些东西时，你应该想到什么

| 看见 | 第一反应应该是 |
|---|---|
| `STM32F103CBT6` | 这是每个电机节点里的小计算机 |
| `STM32F405RGT6` | 这是 REF 里的整机协调主控 |
| `MT6816` | 这是电机轴角度反馈，不是关节输出编码器 |
| `TB67H450` | 这是绕组功率驱动，一个电机需要两个 |
| `SN65HVD232` | 这是 STM32 与 CANH/CANL 之间的电气翻译器 |
| `20 kHz` | 这是单电机闭环周期，不是电机转速 |
| `200 Hz` | 这是 REF 的六轴协调更新频率 |
| `51200` | 一圈电机在控制器内部的细分计数 |
| `16384` | MT6816 14 位原始角度的一圈分辨率 |
| `node ID` | CAN 上区分 J1～J6 的地址 |
| `120 Ω` | CAN 总线两端的终端匹配，不是每板都随便接 |
| `REF` | Robot Embedded Framework 整机主控板 |
| `HAL` | ST 提供的硬件外设软件接口 |
| `FreeRTOS` | REF 中的多任务调度器，不是电机算法 |
| `CMake` | 构建说明，不是编译器 |
| `ST-Link/SWD` | 烧录和调试 STM32 的工具/接口 |
| `Gerber` | 发给 PCB 厂制造裸板的图层文件 |
| `BOM` | 买哪些元件，不告诉贴片机坐标 |
| `CPL` | 元件贴在哪里和转多少角度 |
| `STEP` | 通用实体 CAD，适合交换和加工 |
| `STL/3MF` | 主要面向 3D 打印 |
| `DH/FK/IK` | 关节角和末端位姿之间的几何换算 |
| `HOME` | 移到约定姿态，不代表自动碰限位找零 |
| `CALIBRATION` | 先问是编码器、零位还是整机姿态校准 |

## 21. 建议的后续教学顺序

在开始首月计划前，后续可以按四次专题教学继续：

1. Motor-42 原理图导读：沿 24 V 电源、STM32、MT6816、TB67H450、UART/CAN 逐网讲解。
2. Motor-42 固件导读：从上电入口一路跟到 20 kHz 控制中断。
3. 视频 V2 机械装配导读：从总装拆分 J1～J6，核对传动比和版本。
4. REF 与六轴控制导读：ASCII、CAN、FreeRTOS、FK/IK 和 Home 流程。

完成第 1、2 个专题后，再采购和调试单个 Motor-42，会比直接照步骤操作更有掌控感。
