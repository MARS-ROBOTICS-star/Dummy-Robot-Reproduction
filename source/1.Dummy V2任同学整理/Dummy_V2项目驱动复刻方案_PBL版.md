# Dummy V2 项目驱动复刻方案：先看到，再理解，再扩展

版本：PBL-1，2026-09-06。适用项目：`1.Dummy V2任同学整理/`。

> 主线从“按日期完成准备工作”改为“完成一个可见实验，再学习下一步实际缺少的知识”。第一个目标不是六轴，也不是全部安全重构，而是让一块真实 Motor-42 在你的工作台上完成闭环小角度往返。

本版是新的**学习与实施路线**，不只是上一版章节重排。上一版 [审计修订方案](Dummy_V2详细复刻方案_审计修订版.md) 和 [审计结论](6.Docs/复刻审计_2026-09-06/审计结论与证据.md) 继续作为风险/工程化参考，不再要求先做完其中所有 D01～D13 或 FW01～FW08 才出现第一次可见成果。

本次针对本地实验重新核对了启动、USART、SPI、MT6816、校准器、Motor 控制器、Flash 和 REF 相关源码，详见 [PBL 路线复核补充](6.Docs/复刻审计_2026-09-06/PBL路线复核补充.md)。**本轮交付方案与 `motor42_lab` 的最小改造规格，不声称仓库已经存在可下载、经实测的 lab 固件。** 后文标为“拟新增”的阶段、字段、方法或命令均需要在实验副本中实现，原固件不支持这些新名字。

证据标记：**[证]** 仓库原文件直接确认；**[设]** 本版为缩小实验范围作出的设计选择；**[测]** 尚需本机实测或供应方资料确认。方括号 S 编号对应文末原文件索引。

## 2. 为什么不再按 D01～D20 执行

用户已有机械、CAD、运动学、Python 和强化学习机器人项目经验，缺的是“代码如何通过真实电路产生可测运动”的经验。这种缺口适合用短反馈实验填补，不适合先排满课程。

上一版把几种系统混在了首次运动门槛中：本地一次性实验、任意 UART 交互、长期通信控制、多节点系统、带重力负载的机构。新路线先删掉暂时不用的**入口和负载**，而不是假装这些入口没有风险。

| 以前容易先做的事 | 现在替换为 | 等什么时候再补 |
|---|---|---|
| 先买 F103 最小板做四套通用实验 | 直接在 Motor-42 A 板上烧录、读传感器 | A 板确实不可用且另一个具体实验需要时才评估开发板 |
| 先学习 UART/DMA/parser 才控制电机 | E2 只有发送遥测；E4 动作保存在固件里 | E5 才接收 PC 的运动命令 |
| 先做完整 ARM/DISARM 和故障体系 | E4 仅“本地触发一次、完成/异常不再输出” | E5 增加会话授权，E8 增加系统级状态 |
| 首次运动前完成所有 CAN 防护 | E4 不接 CAN，lab 不启动 CAN 接收路径 | E6 启用 CAN 前完成电机/主机侧保护 |
| 先做六轴零位/传动比/DH 冻结 | 裸电机不用这些参数 | E7 只解决所选关节；E9 才解决全部六轴 |
| 第一块板全程手焊 | 先用已组装 A 板形成参考 | MVP-1 后用 B 板学习制造与焊接 |

这不是“先冒险转一下”。仍保留当前实验真正需要的固定、有效采样、有限参数、有限执行时间和直接断电手段；只是**没有引入的 UART/CAN/REF 功能不再要求提前重构**。

## 3. MVP-1：一块 Motor-42 单电机实验台

### 3.1 边界与两个里程碑

**MVP-1**：一块 A 板、一个匹配的 42 两相四线 1.8° 电机、轴端磁铁/MT6816、刚性夹具。在有人看守、无减速器/皮带/负载的条件下，闭环执行一次 `q0 → q0+Δ → q0`，记录反馈，然后 Sleep。

**M-angle / E2**：PC 实时看到 `rawAngle` 随手转轴变化。这时相线可以保持断开，尚未校准也可以成功。

**M-motion / E4**：轴上小标记发生可见的往返，反馈在目标附近稳定，程序报告完成并退出输出。这时不需要 PC 下发动作。

**重要区别 [证]**：E3 校准已经可能使电机转动，E4 是“第一次闭环小角度运动”，不是“第一次产生任何力矩”。校准前就要满足裸电机的固定、电流、原始反馈和断电要求。[S06]

### 3.2 接线只分三个用途

| 用途 | 当前需要的连接 | 暂时不接 |
|---|---|---|
| 供电 | 已核对的 Motor-42 功率输入 24 V/GND，前有直接断开 24 V 的手段 | REF、其他节点、电机线不得接 P3 |
| 调试 | P3 对应 SWDIO、SWCLK、GND；目标参考电压按调试器说明处理 | 不把 ST-Link 的供电脚随便并到已有板电源 |
| E2～E4 遥测 | 板 P3 的 UART_TX → USB-UART 的 RX，GND → GND | 适配器 TX 不接板 UART_RX；不接适配器 5 V/3.3 V 电源线 |

Motor-42 图中 P1/P2 为功率/CAN 链路，P3 是 UART/SWD 调试接口；不能凭“都是六针”互插。USART1 复用为 PB6 TX、PB7 RX，但实际接线按**本板版本、接口观察方向和导通实测**确定，不按纸面左右顺序猜针号。[证][S02][S03]

### 3.3 `motor42_lab` 最小改造，不是重写一套控制栈

**拟建实施工作副本**：独立命名 `motor42_lab`，从 Motor-42 工程复制/建立自己的实验分支。当前目录不是 Git 仓库时，不直接执行 `git switch -c`；先创建不覆盖原始资料的工作副本。本文没有把复制的固件源码写入原目录。

优先保留现有 STM32 外设底层、MT6816 解码、校准算法、Motor/DCE 和轨迹规划。只改应用入口及当前实验必要的少量观察/退出接口。

拟新增四个**编译时选择**的实验阶段，默认必须是 FLASH_ONLY 或 OBSERVE，不能由随机串口输入切换：

| lab 阶段 | 做什么 | 怎样启动动作 |
|---|---|---|
| `FLASH_ONLY` | 心跳/版本标识，桥输出关闭，不跑电机校准/闭环 | 不允许动作 |
| `OBSERVE` | 桥输出关闭，低频读原始角，TX-only 输出 | 手动转轴，固件不驱动 |
| `CALIBRATE` | 复用原校准，但加匹配电流、有效采样、一次性本地触发/退出 | 先观察到按键释放，再接受一次新按下；不沿用原长按逻辑 |
| `ONE_SHOT` | 由当前 q0 做一次往返，完成或异常即退出 | 先观察到按键释放，再接受一次新按下；重启后不能自动重放 |

只需要以下六处改造，逐实验加，不在 E1 前一次写完：

1. **入口裁剪**：lab 跳过 `MX_CAN_Init()` 的启动路径；在 `MX_USART1_UART_Init()` 中不启用 RX DMA、IDLE 和 `OnUartCmd` 绑定，仅保留发遥测所需配置。旧按键校准、模式切换和按键组合触发也停用。[S01][S02]
2. **默认无输出**：加载参数后强制本实验的 `enableMotorOnBoot=false`；FLASH_ONLY/OBSERVE 不调用原运动/校准调度，驱动初始化后 Sleep。电机相线断开时先验证它。[S01][S08]
3. **最小诊断**：给 MT6816 增加只读状态访问，输出 raw、当前传输/parity/noMag 的有效性；不是让 UserApp 直接访问 private 成员。先用于 E2 看见错误，再用于 E3/E4 中止动作。[S04][S05]
4. **有限本地实验**：在 E3/E4 的实际采样后检查有效性，有问题即禁止后续驱动；SPI 调用有界、检查返回状态。中断内的超时要用确实能推进的时基/有限轮询，不能仅把 HAL_MAX_DELAY 改成 1 就假定 SysTick 能抢占当前中断。ONE_SHOT 只有去程、返程、完成、异常几个状态；本地计时不依赖串口打印，也没有命令失联问题。[S05][S06]
5. **参数覆盖**：E3/E4 启动前，在 EEPROM 加载之后用本次已填写的 RAM 电流/速度/加速度限值覆盖；保留已有零偏/校准，不周期性写 EEPROM。E4 同步设置规划器的加速度缓存。[S01][S07]
6. **保留存储区**：下载前看 MAP/加载段，应用不跨 `0x08017C00`。lab 可以把链接脚本应用 FLASH 上限改成 95 KiB，简单防止侵占校准区；不要求此时设计双槽、参数迁移或完整掉电事务。[S09]

`ONE_SHOT` 的控制示意，**这是待实现的逻辑，不是可直接编译的源程序**：

```text
启动 -> Sleep -> 校准表有效且当前采样有效 -> STOP 状态完成位置初始化
     -> 等待按键释放 -> 等待新的本地按键触发
     -> 采集静止时的 q0 -> 目标先设 q0 -> 请求位置模式
     -> 目标 q0+Delta -> 实际反馈到位且稳定 -> 目标 q0
     -> 实际反馈到位且稳定 -> DONE -> 持续 Sleep，不再自动执行

任一运动阶段：采样失败 / 无磁 / 越出小窗口 / 段超时 -> ABORT
ABORT：取消本次调度，阻止后续 SetFocCurrentVector，Sleep，等待人工排查
```

这样可以后移通信 parser、完整会话 ARM/DISARM、通信 watchdog、CAN 安全、REF 队列与任务重构。**不能后移的是对当前反馈的最小有效性判断，以及“结束后原 tick 又把桥打开”的防重入问题。**

### 3.4 本地实验需要填写的参数只有一小张表

| 参数 | 首轮处理 | 证据类别 |
|---|---|---|
| `I_RUN_mA` | 来自匹配电机/板卡的低负载试验设定，写成 lab 常量 | [测] 不能照抄默认 1000 mA |
| `I_CALI_mA` | 单独确认、单独限制；与运行限流不是同一个值 | [证]+[测] 原默认 2000 mA 不自动受普通限流约束 |
| Δ | 首轮候选 256 内部计数＝0.005 圈＝1.8° | [设] 小纸片标记/手机近拍即可观察，不加长杆负载 |
| 速度 | 首轮候选 1024 计数/秒＝0.02 圈/秒 | [设] 不适用于校准阶段 |
| 加速度 | 首轮候选 5120 计数/秒²＝0.1 圈/秒² | [设] 不适用于校准阶段 |
| 段超时 | E4 每段候选 3 秒，失败不无限等；校准用独立的较长上限 | [设]+[测] 不能把短位移超时套到多圈校准 |
| 到位 | 候选误差 ≤64 计数（0.45°）、速度接近零，持续约 100 ms | [设]+[测] 是试验判据，不是原作者精度保证 |
| 最大运行窗口 | 相对本次 q0 的有限窗口，例如 ±0.02 圈，越界终止 | [设]+[测] 不是六轴软件限位 |

仓库只有默认参数，没有“对所有 42 电机都已验证安全”的低电流值。最快补齐方法是购买/借用**板、电机、磁铁相互匹配的一套 A 基准**，向提供者确认两个电流值和相线配对；不为此先核完整六轴 BOM。不能靠把台式电源限流设得很低来代替固件相电流限制，也不能把不转简单归因于电流太小。

## 4. 首批最小采购：只为 MVP-1

### 4.1 立即需要

“需要”指必须能获得，不等于必须购买；有现成或可借的就不买。

| 物品 | 最小数量 | 此刻解决什么问题 | 决策 |
|---|---:|---|---|
| 已组装 Motor-42 A 板 | 1 | 给 E1～E5 一个可信的真实目标板 | 首选可追溯版本、基本测试过的成品 |
| 匹配的 42 两相四线 1.8° 电机 | 1 | E2 的轴端传感与 E3/E4 的执行器 | 确认相电流、轴端磁铁安装、相线，不买六个 |
| MT6816 所需磁铁/安装件 | 1 套 | 角度反馈和机械固定 | 成品板通常已贴 MT6816，先确认，不重复买裸芯片 |
| ST-Link | 1 | 写入自己的固件，E1 恢复 | 可借；确认支持 STM32F103 的 SWD |
| USB-UART | 1 | E2 只收角度，E5 再双向通信 | 3.3 V 逻辑，不是 RS-232 |
| 配套供电/SWD/串口线 | 仅本台所需 | 避免临时裸线和六针误插 | 优先购买压接好的匹配线，不为此先买焊台 |
| 刚性夹具、固定件、断开 24 V 的手段 | 1 套 | 限制运动和快速断电 | 现有夹具可用则复用；断电装置适用于直流负载 |

### 4.2 优先借用

| 物品 | 何时必须在场 | 无法借用怎么办 |
|---|---|---|
| 可提供 24 V 且可限流、可切输出的实验电源 | A 板首次上电起 | 只买满足本台实验需要的一台，不提前按整机 6 A 采购 |
| 万用表 | 接线、极性、静态检查和电源轨检查 | 用现有的或购买基础可靠型号 |
| ST-Link、夹具、压接服务 | 当前缺少时 | 按实际缺口补齐，不采购完整工具套装 |

这里没有提前借一柜子仪器。示波器、逻辑分析仪只在出现时序/电源问题时按故障借用，不作为开局“必须借到”的清单。

### 4.3 从首批删除

普通 F103 开发板、USB-CAN、示波器、逻辑分析仪、焊台、热风枪、显微镜、REF、第二块 Motor 板、其余电机、减速器、全套机械件、ESP32、LED Ring **全部从首批删除**。

这不是永久不买，而是它们对 E2/E4 没有新增必要作用。首批金额用真实缺口逐项报价，不重新打包一个“入门必买工具预算”。采购前只问三件事：**下一实验用不用？已有/借用能不能解决？能否只买一个？**

### 4.4 A 板与 B 板为何分工

A 板承担“固件能否运行、角度是否正常、控制是否有效”的学习。B 板以后承担“相同设计为什么这块不工作”的学习。没有参考板时，焊桥、错料、供电、SPI、磁铁、参数可能同时出错；有 A 板后可以逐点、同电机、同固件比较，每次排除一类原因。先拿到参考板不是跳过硬件，而是在为以后学硬件建立对照实验。

**能获得 A 板时**：索取板版本/芯片与晶振信息、供电/接口图、测试固件来源、电机/磁铁配套说明；到货仍做 E1 的简单静态/上电检查。不要求先自己导出整套制造资料，更不以 Motor-42 原包缺钻孔阻塞一块已经存在的合格板。

**不能获得 A 板时**：由熟悉 Altium 的人协助，用现有 `1.Hardware/motor42/PCB源文件/` 中的选定版本核对原理图/PCB；与“焊盘更改版”明确二选一；从同一 PcbDoc 统一重新导出 Gerber、NC Drill、装配 BOM、CPL/装配图；核对铜层、板框、孔位、贴装正反面与 Pin 1，再委外组装并验收一块。工厂若有起订量，只支付必要工艺余量，不因此把多块同时变成调试任务。

**不允许直接发送当前 `motor42 Gaber.zip` 投板：已有审计确认它缺少独立 NC Drill。[证][S10]** 制造审核在这个替代路线中不可省，但可以借助专业协作完成，不要求初学者先把全板手焊课程学完。

## 5. E0～E5：从编译到单电机互动

### E0：原始 Motor-42 固件能否构建

**1. 实际结果**：得到 `Ctrl-Step-STM32-fw.elf`、`.hex`、`.bin` 和 `.map`；第一次从源码获得可检查的产物。[证][S11]

**2. 为什么现在做**：没有成本即可确定工具链与代码的真实关系，也能在 A 板等待期间推进；不需要先会 STM32 外设。

**3. 最少硬件**：现有电脑；不买开发板，不要求 A 板已经到货。

**4. 操作顺序**：

1. 选一个主要开发环境。Windows 可用 Arm GCC+CMake+STM32CubeProgrammer；Linux 用 Arm GCC+CMake+Make。先不同时维护两套环境。
2. 检查 `arm-none-eabi-gcc --version`、`cmake --version`；需要 CMake 3.20+。本次检查的环境仍未发现二者，不能把旧审计的“工程结构齐全”当成编译成功。
3. 在工作副本根目录执行下列构建示例；`-S` 是源目录，`-B` 是单独输出目录，不复用仓库旧缓存。

```bash
cmake -S "2.Firmware/dummy-42motor-fw" -B "build/motor42-baseline" -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Debug
cmake --build "build/motor42-baseline" --parallel 2
arm-none-eabi-size "build/motor42-baseline/Ctrl-Step-STM32-fw.elf"
arm-none-eabi-objdump -h "build/motor42-baseline/Ctrl-Step-STM32-fw.elf"
```

4. 找到 ELF/HEX/BIN/MAP，记下工具版本和首个错误/成功日志。不在这一刻烧录带相线的电机板。
5. 只在 E1 准备下载、需要保留 A 板校准时，检查 Flash 加载地址及保留区；应用上限与简单 95 KiB lab 链接设置见第 3 节。
6. 保留原始构建结果；此后创建独立 `motor42_lab` 工作副本，只从本实验开始修改。新阶段选择要落实到源码/CMake，不能凭空传一个未实现的 `-DLAB_STAGE=...` 就声称已经切换模式。

**5. 现在只学**：GCC 把哪些文件变成 ELF；HEX 有地址、BIN 是原始字节；CMake 负责组织构建；linker script 决定代码存在哪里。学到能定位本次首个错误即可。

**6. 现在不学**：启动汇编逐行、完整 CMake 教程、HAL 全库、REF 构建、FreeRTOS、USB 协议。

**7. 成功/失败后的下一步**：成功转 E1；失败按“找不到工具→配置路径→编译第一条错误→链接第一条错误”定位。路径/版本问题先解决，不买更多板、不先重生成 CubeMX。

### E1：真实 Motor-42 可以通过 SWD 烧录

**1. 实际结果**：A 板输出你自己的 lab 版本/计数标识，且能完成三次下载、所需应用区擦除、复位和重连恢复。

**2. 为什么现在做**：直接在最终会控制电机的板上学 Flash/SWD，避免另买最小板后再重新适配。

**3. 最少硬件**：A 板、ST-Link、板供电线、借用电源和万用表；USB-UART 可用于看版本。电机暂不接相线，不需要 CAN。

**4. 操作顺序**：

1. 按本板资料确认功率口与 P3 调试口，拍照标记；断电核对 24 V/GND 和明显短路、反接/焊桥。用供方测试值作对照，不能用一个“万能正常阻值”。
2. 电机相线拔下并绝缘，电源限流后上电；测输入和本板逻辑电源轨，出现异常电流/发热即断电。电源轨未确定就询板方，不凭芯片型号猜值。
3. 断电接 SWDIO、SWCLK、GND。P3 图中没有可直接当作 VTref 的电源脚；需要 VTref 的调试器应按板资料取目标 3.3 V 参考点，不把参考误当供电脚。[S03]
4. 上电后在 STM32CubeProgrammer 选择 ST-LINK/SWD，保守降低 SWD 频率连接，读取 MCU/Flash 信息。核对目标是板卡所用的 F103CB 规格，不能按 F103C8 容量操作。
5. 对已有固件/校准的 A 板先备份允许读取的 Flash，特别是 `0x08017C00` 的 32 KiB 校准和 `0x0801FC00` 的 1 KiB 参数；记录板与电机配对。不解除读保护来“尝试备份”，因为可能触发全擦。[S09]
6. 实现第 3 节的 `FLASH_ONLY` lab：不启动 CAN/RX/旧按键动作，默认不运行电机 tick/校准；只输出如 `LAB_FLASH build=... count=...` 的低频心跳。这是当前需要的第一个小固件，不是新建通用 Blink 课程。
7. 打开 lab HEX，Program/Verify 后 Reset。优先用已接好的 TX-only 串口看版本/计数，或无相线时用调试器观察自增变量。
8. 重复下载/校验/复位/重连三次。选应用区擦除即可，**不要求三次全片擦除**。一次练习复位下连接时相线仍断开；校准/参数被全擦则明确标为待重建。

**5. 现在只学**：SWD 的三根基本信号、Flash 擦写粒度、复位下连接、HEX 地址；只有连接失败时才展开 Reset/Boot 排查。

**6. 现在不学**：Bootloader 设计、寄存器编程、完整时钟树、普通开发板课程、量产烧录流程。

**7. 成功/失败后的下一步**：三次可重复转 E2；无法连接先查目标供电/共地、SWDIO/SWCLK、接头方向、调试频率和复位方式。不要通过反复全擦或连接电机来验证 MCU 是否活着。

### E2：手转电机轴，PC 实时看到 MT6816

**1. 实际结果**：终端持续出现原始角度。手转轴时数值跟随，跨过单圈边界可见接近 16383 后跳到接近 0，或反向经过边界。这就是 **M-angle**。

**2. 为什么现在做**：立刻建立“机械轴→磁场→芯片→MCU→PC”的真实反馈，给后面校准和闭环一个可信起点。未校准不阻塞这个实验。[S04]

**3. 最少硬件**：原 A 板、匹配电机/磁铁安装件、夹具、电源、USB-UART。电机相线保持断开；板与磁铁需按实际传感位置安装同心。不增加仪器。

**4. 操作顺序**：

1. 固定电机，安装磁铁/板卡，保证手转不碰线。按 MT6816 配套资料确认磁化方向和间隙；不是任意磁铁都可用。
2. 断电接板 UART_TX→适配器 RX、GND→GND，**适配器 TX 悬空**。打开 115200、8N1 串口终端，不运行仓库中会发 `!START` 的 simple-cli。
3. 在 lab `OBSERVE` 中初始化驱动后 Sleep，不启动原 TIM4 控制/校准调度；主循环约每 50 ms 调 `mt6816.UpdateAngle()` 并输出一次数据。这样先不学习 20 kHz 中断。
4. 观察现有 public `mt6816.angleData.rawAngle`；另外在 MT6816 类内加只读诊断 getter，导出本次 `spi_ok/parity_ok/noMag`。这些字段目前不能从 UserApp 直接访问，因为 `spiRawData` 是 private。[S04][S05]
5. 先输出短整数 CSV，例如拟新增字段 `ms,seq,raw14,spi_ok,parity_ok,no_mag,rectify_valid`；不要求浮点打印、TX DMA 或 GUI。坏读数写明 `valid=0`，不能悄悄继续显示旧角度为新样本。
6. 手转轴约一圈，停止、反转、慢慢经过回绕。50 ms 采样不一定恰好捕到 16383 和 0，这不是故障。无力矩时通常仍有齿槽手感，不以“完全没阻力”作为断输出的唯一证明。
7. PC 计算 `degrees=raw14*360/16384`；观察两次读数差，而不是把回绕看成倒转。
8. 想看多圈时，在本次软件会话内累加有效样本差：`d=raw_now-raw_prev`，大于 8192 则减 16384，小于 -8192 则加 16384。前提是相邻有效样本间轴转动少于半圈；掉样太久就标不可信，重启不能恢复绝对多圈位置。

可选的 PC 终端命令，先在自己的 Python 环境安装 `pyserial`；把端口替换为实际端口：

```bash
python -m serial.tools.list_ports
python -m serial.tools.miniterm /dev/ttyUSB0 115200 --raw
```

Windows 使用实际 `COM` 号。此处只接收遥测，不需要 `arm/start/p` 命令，也不要求写 Python GUI。

**5. 现在只学**：14 bit 为什么是 16384 档；原始角度不等于高精度保证；SPI 是 MCU 从 MT6816 取数的链路；parity/noMag 用来区分坏读数；回绕是周期变量的正常现象。

**6. 现在不学**：SPI 驱动从零编写、DMA 环形队列、FOC 数学、PID 调参、Flash 校准表生成、六轴坐标系。

**7. 成功/失败后的下一步**：原始值跟手转一致就记录一段 CSV/视频，转 E3。数值不变先查磁铁有没有随轴转、板/磁铁位置和 `spi_ok`，再查 SPI 片选/时钟与引脚；乱码先查串口/共地/晶振；`rectify_valid=0` 但 raw 正常是允许的，不为此回去重焊板。只有线序和代码检查不能定位时才借逻辑分析仪看 SPI。

### E3：理解并完成最小校准

**1. 实际结果**：得到与当前板/电机/磁铁组合匹配的校准表，冷启动能识别有效，手转时校准角连续可解释。若需要执行原校准，会看到有控制的转轴和结束复位。

**2. 为什么现在做**：E2 已证明原始角度链路，现在才需要把 16384 档磁角映射到控制器的 51200 计数/圈。**不是先学一章电机标定再找实验。**[S04][S06]

**3. 最少硬件**：E2 同一套硬件；现在才在断电下接好两相绕组。仍无减速器、同步带、悬臂、REF。电机夹紧，磁铁防飞出，断 24 V 可触达。

**4. 操作顺序**：

1. 判断 A 板是否带有**这台电机和这套未改变安装的磁铁**的已验证校准。若是，先备份并做有效性/手转核验，可以复用，不为“完成学习打卡”强制擦掉重标；稍后仍可做一次受控重标定比较。
2. 若没有可靠配对校准，向提供者确认额定相电流、相线配对和建议校准电流。万用表在断电时识别两组有电阻的绕组，再对照 A 板输出定义连接，不能按线色猜。
3. 构建 lab `CALIBRATE`：保留原校准算法；加载后覆盖 `motor.config.motionParams.caliCurrent` 和本次 RAM 参数；原来的上电组合/长按自动触发停用，改为释放后一次新按键触发。此阶段恢复原 TIM4 的 20 kHz 节拍，由 `Tim4Callback20kHz()` 在允许校准时调校准器 `Tick20kHz()`，主循环调 `TickMainLoop()`，不能继续用 E2 的 20 Hz 观察循环代替；等待触发时仍无输出。[S01][S20]
4. 在编码器实际读取之后、首次驱动之前加入最小有效性检查。校准器直接调用驱动，**仅在普通 `motor.Tick20kHz()` 增加保护覆盖不到校准**。传输失败或无磁时终止，不能把保持的旧 raw 写入标定样本。[S05][S06]
5. 先不按键，确认 24 V 上电和校准完成后的复位都保持等待、无输出。给 `state/errorCode` 增加只读 getter，从主循环低速打印阶段；私有字段不能直接外部访问。
6. 移开手，触发一次校准。原流程有预备转动、正向采样、反向消隙与采样，不是 q0±1.8°；必须留完整转轴空间。小位移窗口此时不适用。
7. 校准速度来自 `AUTO_CALIB_SPEED=2`、`FINE_TUNE_CALIB_SPEED=1` 及 20 kHz 节拍，**不受 E4 的 ratedVelocity 限速**。首轮不任意改这些常数；若要改慢，要同时核对整除/等值状态切换和采样等待。校准的“低能量”主要来自匹配且受限的电流、无负载、有限次数/时长，不谎称与 E4 同样慢。
8. `TickMainLoop()` 完成计算/Flash 写入。原成功分支会复位；看到重新出现启动标识不等于失败。复位后不自动重标、不自动运动，检查 `rectify_valid` 和表读回结果；失败则保留错误信息，不自动重试。lab 的 ABORT 同时阻止校准 tick 和后续主循环继续计算/写表，不能只把普通 Motor 模式切 STOP。[S06]
9. 功率关闭后再手转复查。表应覆盖 16384 个 uint16、32 KiB，校准计数范围应与 51200 尺度相符；不能只看“不是全 0xFFFF”就证明映射准确。若要观察误差，用现有量具/轴标记作对照，不为这个步骤先买高精度角度台。

**5. 现在只学**：为什么磁角要校准；200 整步×256 是内部尺度；正反向采样减少哪些误差；为什么表写 Flash、为何成功后复位；运行电流与校准电流是两项设置。

**6. 现在不学**：完整磁场建模、电机辨识、在线自适应、整机 HOME/TCP 标定、双槽 EEPROM、六轴校准协议。

**7. 成功/失败后的下一步**：复用或重建的表经核验后转 E4。电机只抖不转先断电，检查相线、磁铁、当前电流和错误阶段；连续性/方向错误回 E2 看原始角，不靠盲目增大电流反复校准。校准表丢失先查擦除范围/写入/复位，不改 DCE 增益。

### E4：第一次本地闭环小角度往返

**1. 实际结果**：按一下板上实验键，电机从当前停住的位置出发，微转后返回；PC 只记录，拔掉 PC 遥测不改变动作。完成后 Sleep。这就是 **M-motion / MVP-1**。

**2. 为什么现在做**：传感器、下载和校准已有实证，可以直接复用位置环来感受闭环；不先把 PC 控制协议做成一个新项目。

**3. 最少硬件**：E3 的全部已有物品，加轴上极轻的小标记即可。无新增控制器、总线、仪器或机械件。

**4. 操作顺序**：

1. 构建 lab `ONE_SHOT`；仍关闭 RX/CAN/原按键处理。把两个已确认电流、Δ/速度/加速度、最大运行时长写成实验常量，启动日志打印**实际加载后值**。保留原 TIM4 控制节拍：按当前代码 12 MHz HSE、PLL×6、TIM4 预分频 71/周期 49 推导为 20 kHz，A 板晶振要与之匹配；用低频日志报告 tick 增量作初步自检，异常再借仪器核时序，不为此先购示波器。[S01][S07][S20]
2. 先在电机相线断开时验证：启动不执行；需要按键释放后新触发；超时/软件注入无效采样走 ABORT；DONE/ABORT 后不能由下一次普通 tick 重新输出。然后断电接回相线。
3. 位置环保持 STOP，等待有效校准和若干有效 tick 初始化位置、轴静止。`Init()` 把位置置 0，首次 tick 才根据编码器初始化，不能过早抓 q0。[S07]
4. 在新的按键事件被接受时读取 `q0=GetPosition(false)`，单位是电机轴转数；将 `round(q0*51200)` 作为给 `SetPositionSetPoint()` 的 q0 计数。它会自行加零偏，不能再加一次。目标先设 q0，再请求 `MODE_COMMAND_POSITION`，避免启动朝历史零点走。[S07]
5. 发出本地去程目标 q0_count+256；复用 `positionTracker`。普通速度写 `ratedVelocity`，加速度除 `ratedVelocityAcc` 外同步 `positionTracker.SetVelocityAcc()`，避免使用旧缓存。[S01][S07]
6. 由周期路径监控**实际反馈误差和速度**，满足短稳定窗口才转返程。`STATE_FINISH` 只表明规划器结束，不足以断定轴到位。不在控制中断里 `printf`。[S07][S08]
7. 设置返程 q0_count，实际到位后记录结果并 DONE→Sleep。每个阶段都有本地时间上限；采样坏、超窗口或超时就 ABORT，不用无限 `while` 等待。
8. 第一次只做一次；观察正常后可人工重新启动另外两次，记录三次结果。自动 50 次循环、15 分钟运行和大量参数调优放在第一次成功之后，不阻塞 MVP 的首次确认。

这里的本地时间上限不是通信 watchdog：没有外部命令就没有“命令失联”。但 MCU 完全卡死时软件计时也会停止，所以仍需有人看守、低能量裸电机和物理断 24 V；不因此为首轮开发完整产品级硬件看门狗框架，也不把这种边界用于重力负载。

**5. 现在只学**：两相绕组与两个 TB67H450 的对应；软件给出相差 90° 的正弦电流矢量；每个控制周期“读角→误差→电流命令”；位置模式用 DCE，速度模式有 PID，不需要一开始同时调两套环。[S07][S08]

**6. 现在不学**：完整 FOC 推导、三相无刷控制、控制系统课程证明、UART parser、CAN、RTOS、六轴轨迹规划。

**7. 成功/失败后的下一步**：一次完成就承认 MVP-1 已出现，保存视频/日志；复现两次后转 E5。完全不动看校准/模式/参数是否实际生效；方向/振动异常先退 E3/E2，不同时改电流、相线、磁铁和增益；刚使能就大动优先查 q0 抓取时点、单位、零偏和残留旧入口。

### E5：Python UART 控制单电机

**1. 实际结果**：Python 能读状态/位置，发送有界小目标；STOP 和 PC 断开有清楚行为。现在才把“PC 会控制电机”作为独立成果。

**2. 为什么现在做**：本地闭环已成功，新增问题主要剩“命令如何正确进板”；通信错误不再与电机能不能工作混在一起。

**3. 最少硬件**：已有设备，只增加 USB-UART TX→板 RX 的一根连接；**先完成接收路径修改，断电后再接该线**。仍不买 USB-CAN/REF。

**4. 操作顺序**：

1. 冻结 E4 已成功版本。新增 `UART_LAB` 测试模式，保持上电不输出，先用断开相线的板验证解析。
2. 不直接打开旧 `OnUartCmd`。它忽略长度、用 `strtok/atof` 并切模式，原 `c/v/p` 不含查询与可靠 STOP。[证][S12]
3. 第一版只实现小白名单：例如拟新增 `status`、`arm`、`p <整数计数>`、`stop`、`hb`，每行最多 48 字节；p 是本次会话 q0 周围有限窗口内的绝对计数。**这是新协议，单位不同于旧 `p` 的转数，必须回显 `protocol=LAB1 units=count`，不能复用旧客户端。**
4. 接收可先用中断单字节累积，学到能形成完整行即可；或者保留项目的 DMA_NORMAL+IDLE 但把分片交给主循环行缓冲，IDLE 不是消息结束符。DMA 本身不是首个互动的另一个毕业门槛。[S02]
5. 按换行组帧，超长整行丢弃；参数必须完整匹配、拒绝溢出/垃圾/错误前缀。命令只在主循环解析，由控制 tick 消费已验证目标。整数协议避免一开始处理浮点格式，但不能省范围和溢出检查。
6. `arm` 仅在健康、静止时捕获本次 q0；stop 屏蔽后续输出并结束授权。每次串口重连先读状态，不能自动发 arm/旧目标。心跳/有效运动命令才续租，status 查询不续租。
7. 先用主机固定样例测试空行、分片、两行粘连、裸 p、超长、超范围、错误数字；确认它们不移动、不误写 Flash。再接相线、读状态、显式 arm，从 E4 同样的小目标开始。
8. Python CLI 做 `connect/read/status/arm/goto/stop` 即可，不做 GUI。轮询记录目标/反馈/状态，并在退出时发 stop；**节点本地仍需超时**，不能只依赖 Python 的 finally。
9. 可从 50 ms 心跳、200 ms 节点超时作试验起点，记录真实停止时间；它们是 [设]/[测]，不是已验证常数。分别试退出程序、断接收线、暂停主机、超时后重连，故障后不能自行继续旧动作。
10. E4/E5 稳定后再增加 50 次往返和较长温升试验；此时若波形问题确实不能定位，才借示波器/分析仪，不先购买。

**5. 现在只学**：UART 帧格式、行缓冲、输入验证、DMA/IDLE 的真实边界、命令接受与动作完成区别、节点本地 timeout。每项都服务于“Python 下发的这一条目标为什么可靠”。

**6. 现在不学**：USB 协议栈、Fibre、网络鉴权、多节点寻址、串口通用框架、复杂 GUI、全部故障码体系。

**7. 成功/失败后的下一步**：往返、STOP、断连与重新授权都可重复后转 E6；也可进入可选 B 板支线。无回显查端口/交叉连接/共地，数据混乱查收包边界，接受了命令但不动查授权/单位/超时，退回 E4 判断是否仅通信版本引入了问题。

## 6. E6：第二 Motor 节点与 CAN

### E6：让两台电机只执行发给自己的目标

**1. 实际结果**：PC 通过一条 CAN 总线分别读到两个节点的位置，并让其中一个小范围运动而另一个不动；两者可以分别 STOP。不是先把整臂插上试通信。

**2. 为什么现在做**：单电机已独立成立，现在引入的唯一主要新问题是“多块板如何共享一条线”。这是学习 CAN 寻址、仲裁、终端和超时的具体理由。

**3. 最少硬件**：已有 A 节点；新增/借用一个完整可用节点、一个支持实际 CAN 收发的 USB-CAN、短线和所需终端。第二节点可以是已完成的 B 板，也可借已组装板，**不要求先完成自焊 B 板才允许学 CAN**。仍不需要 REF。

**4. 操作顺序**：

1. 用 E2～E5 的简化验收检查第二节点，确认与第一个不同的 ID。原电机启动会从三位拨码覆盖 ID，因此不要只发 `0x11` 改 ID 然后假定冷启动仍保持。[证][S01][S13]
2. CAN 尚未接入时，先在副本补电机/PC 主机两端的 ID、IDE/RTR、逐命令 DLC 和数值范围校验，发送失败要退出而不是关中断死循环；不在此时修改尚未使用的 REF 代码。
3. 断电接 CAN_H→H、CAN_L→L 和必要地参考。核对电源/CAN 共用六针的每根网络，不买全套臂内线束。不得把 CAN 接口插到 P3 调试口。[S03]
4. 只在总线物理两端形成所需的两只 120 ohm 终端。USB-CAN 可能已有终端，Motor 板也可能带终端开关/焊装，先数清实际启用的数量；断电 H-L 约 60 ohm 是常见双终端预期，不是无条件通用标准。
5. 设置并核对 1 Mbit/s。先接一个节点，用只读位置查询 `0x23` 观察反馈，再加第二个。标准 ID 由 `(nodeID<<7)|cmd` 得到；例如节点 1/2 的位置查询 ID 为 `0x0A3/0x123`。[S13]
6. 前四字节浮点/整数的含义按对应命令解码，不把 E5 的 LAB1 整数文本协议当成原 CAN 字节协议。首轮只开放位置/反馈/停止小白名单，广播校准/擦除/改 ID 不开放。
7. 在节点本地实现 CAN 运动租约/超时，并说明如何与原“点目标一直有效”的语义兼容；只读查询不为运动续租。USB-CAN 软件退出不等于节点已经停止。
8. 限流、裸电机固定后逐个授权小范围运动，验证寻址、反馈、STOP、失联和冷启动。错误帧/短帧测试先断相线；bus-off/发送失败不应让驱动无限保持旧输出。
9. 最后做两个节点的交错/同时任务，记录时间戳和反馈，不把 CAN 的顺序发送宣称为硬同步。只需测当前两节点，不先做六轴满负载总线压力测试。

**5. 现在只学**：CAN_H/L、终端电阻、标准 ID、DLC、波特率/位时序、浮点字节布局、共享总线与节点超时。学到能手工解码一帧位置命令和一帧反馈即可。

**6. 现在不学**：CANopen/J1939、完整汽车网络课程、REF FreeRTOS、六轴运动同步、自动节点发现、网络 GUI。

**7. 成功/失败后的下一步**：两个节点地址、反馈和故障行为可重复就转 E7。只有一个正常先查 ID/终端/分支线；全部不通先查地参考/H-L/速率；一动就掉线查供电、发送故障路径，再借仪器，不先换六块板。

### 可选支线：B 板才开始教制造、贴片与排故

这条支线可在 E4/E5 后开始，与 E6 前后并行；它不是额外必修学期。

1. 保留可工作的 A 板原状、固件、磁铁安装和基准日志，不拆 A 板来练习返修。
2. 冻结 Motor-42 PCB 版本，重新导出同版 Gerber+NC Drill+BOM+CPL，按第 4 节审查；当前缺钻孔的旧 ZIP 仍不能投板。[S10]
3. 优先利用学校/实验室焊台、钢网、热风或显微观察工具；根据实际封装选择适合工艺，不认为“学硬件”就必须用烙铁硬焊所有底部散热焊盘。
4. 对 B 板分区装配/验收，按电源、MCU/SWD、UART、编码器、驱动/通信推进；是否能单独上电由原理图决定。
5. B 板某点异常时与 A 板同测点比较阻值/电压，使用同一电机/固件/线缆交叉试验；先确定是板问题还是传感安装/软件问题。
6. B 板至少复现 E2/E4 后才成为第二个 CAN 节点。失败时继续用 A 板学习，保留 B 板排故记录；不要让一处焊接问题冻结整个项目。

这时再学习封装、去耦、焊盘、焊桥、虚焊、热容量、地回路、元件替代和进料检查，每一个知识点都能对应 B 板的一个实际测点。

## 7. E7：一个真实机械关节

### E7：把“电机转数”变成“关节角度”

**1. 实际结果**：一个受约束、可测量的关节按小角度往返，能用实测解释电机转数与关节输出角的比例、方向和回差。

**2. 为什么现在做**：电控与通信已经工作，现在让机械专长参与，理解减速、惯量、摩擦和输出误差为什么会改变原来的闭环表现。

**3. 最少硬件**：复用一个通过 E6 的节点；只买所选关节的一套传动/轴承/紧固件与样件，优先台面固定且不会断电坠落的模块。可以先打印验证接口，但不买全套谐波/CNC，也不承诺打印件等于长期承载件。

**4. 操作顺序**：

1. 选择一个 V2 候选关节，例如台面有支撑的基座旋转模块，明确使用哪个装配版本。只解决这一轴的电机安装、传动链、方向和可活动范围，其他五轴待定不阻塞它。
2. 在 CAD 中测接口和间隙，确认现有电机长度/轴端可装；先做接口样件，再采购本轴那一个减速器或传动件。现有 A 电机若装不进去，明确把它保留为实验资产，不先为“以后必然复用”采购错误结构。
3. 电机编码器校准在无传动负载时完成；装上减速器后不再直接运行会多圈转轴的 E3 校准。
4. 断电安装，核对轴承、预紧、固定和线束余量。先手动检查实际允许的输出范围；不以 REF 默认限位替代机械检查。
5. 用低速小目标实测：`r_total=电机转数/关节输出转数`。带传动按从动/主动齿数算，方向独立记录；不把步距角乘进机械比，不从同步带型号后缀猜齿数。[S14]
6. 根据实测建立局部关节零位，目标仍用当前反馈和本次安全窗口换算。不需要先修全六轴 DH；如果使用本轴 REF 构造参数，必须替换成这一轴实际值。
7. 用量角器/百分表/已有量具看输出侧往返和反向间隙。电机编码器位置稳定不意味着关节输出也准确。
8. 加入真实负载前确认关节限位、托架/支撑、堵转/饱和/温升以及断电行为；此时再完善异常停机和独立看门狗等针对持久输出的措施。失能会失去保持力的轴不能只用 Sleep 作安全策略。
9. 小负载逐步增长，一次只改一个控制参数，记录与裸电机相比的变化。发生振荡/热异常先减小实验负载并排机械问题，不直接套整机增益。

**5. 现在只学**：总传动比、扭矩/速度换算、惯量/摩擦、回差、零位、软件与机械限位、重力负载下“断电”为什么可能不安全。

**6. 现在不学**：六轴整机采购、完整动力学辨识、最优控制、末端 TCP、视觉误差补偿、全套 CAD 版本治理。

**7. 成功/失败后的下一步**：这个关节的比值/方向/零位可解释且停机可控，转 E8。比值错先查传动级与单位；回差大看输出机构而不是编码器；负载振荡退回裸电机对照，区分控制与装配问题。

## 8. E8：REF 双轴最小系统

### E8：让主控协调两个已经可信的执行器

**1. 实际结果**：F405/REF 周期下发两个轴的目标并显示两轴反馈；任一活动节点掉线时有明确结果，不无限等待不存在的另外四轴。

**2. 为什么现在做**：现在才需要“机器人主控”而不是“PC 直接控制电机”。用两个轴学习调度和反馈，避免一开始加入六轴几何、全套外设和复杂任务。

**3. 最少硬件**：E6 的两个节点、E7 的关节、短 CAN/电源线；新增或借用一块可追溯的 REF。若使用 F405 开发板替代，只选这一条路线，不同时买开发板和 REF；需要核对引脚/晶振，不能直接刷原 REF 镜像。第二轴可以仍为固定裸电机，**不强制再造第二个完整关节**。

**4. 操作顺序**：

1. 先不给执行器力矩，完成 REF 的供电/SWD/单独构建。遇到 MCU/FPU/FreeRTOS 链接问题此时才学习对应内容，不追溯成 E0 的毕业要求。
2. 复用已有 `CtrlStepMotor` 收发封装，先做仅含两个活动节点的试验循环；单独维护在线/反馈年龄/到位状态。不要直接启动原六轴 `Homing/Resting`。[S15]
3. 核对构造函数/启动依赖，原 `InitCommunication()` 和 `dummy.Init()` 在 MPU6050 无限等待之前；不能认为“IMU 卡住所以所有通信都没启动”。未贴/故障 IMU 要有限重试并进入安全诊断，依赖它的 OLED/更新任务也一起处理。[S16]
4. 若采用原 `DummyRobot`，把 1～6 发送循环和 `0b1111110` 到达条件改为两个活动轴；若用独立双轴试验应用，则不要同时伪造六轴位姿。不是随便把循环上界改成 2 就结束。
5. 补 REF 接收 ID/DLC/有限值检查和发送有界等待；两轴参数先用各自已验证的换算，不用整机截图推测。先只查询，再发单轴小动作，再两轴交错动作。[S15]
6. 如果开放原 REF ASCII/Fibre 入口，就在开放前修复它的解析/队列和 STOP 路径；如果首轮仍是主控本地硬编码双轴动作，可保持这些入口关闭，把对应解析修复放在 E11/首次开启前。**只要运行 `MoveJ`/EmergencyStop 路径，零位移/零速问题就不能后移。**
7. 将当前位姿重复发送、正常停止、单节点断开、发送失败纳入短试验，确认不会产生 NaN/永久等待。原 `!STOP` 不是独立硬件急停，也不能用温度监视接口 `SetEnableTemp(false)` 代替失能。[S15]
8. 先以低频验证，然后推进目标 200 Hz 调度，记录发送/反馈时间戳和实际负载；先学会解释两轴为何不同步，不先追求零抖动或完整工业实时认证。

**5. 现在只学**：F405 与 F103 的区别、任务/中断/周期唤醒、活动轴集合、反馈年龄、总线调度、有限等待、两轴实际完成条件。

**6. 现在不学**：FreeRTOS 内核全源码、MPU6050 姿态融合课程、所有 OLED/无线外设、六轴 IK、复杂多任务框架。

**7. 成功/失败后的下一步**：两个活动轴能协调且故障可识别，转 E9。启动卡住先查 IMU/任务依赖，命令等待不结束先查活动掩码与反馈年龄，加入 REF 才出错则回 E6 PC-CAN 基准对照，不重新怀疑全部机械件。

## 9. E9：视频 V2 最终机械冻结

### E9：形成只加工一套、参数来源可解释的 V2

**1. 实际结果**：一个选定的六轴装配版本、一份实际净用量/工艺清单、六轴传动/方向/零位/限位/几何参数表，可据此分批报价而不混买不同版本。

**2. 为什么现在做**：单关节与双轴已证明电控路线可行，此时为全量机械投入做决定，避免花大钱后才发现驱动、调试或制造路线走不通。

**3. 最少硬件**：现有 CAD 电脑、已有板/电机/单关节；这一实验以数字模型和测量为主，不先买整机件。A 板等待期间可以提前看 CAD，但不把全部审查提前变成 E2 门槛。

**4. 操作顺序**：

1. 比较 `4.Model/Dummy V2 版本 视频款/Dummy-B v2装配体.step` 和 `改版/Dummy-B.STEP`；明确基座/J1 改版替代关系，不把两套同名零件都下单。[S14]
2. 建立每轴的电机、减速器、传动级、安装件和文件路径矩阵。STEP 的 PRODUCT 名称不是装配实例数量，必须在 CAD 中展开实际实例。
3. 定位 42-34/42-40 的轴归属，核对磁铁端空间；BOM 的三台 42×40 是候选，不是已经解决的安装结论。
4. 对照下表逐项测量和推导。图片/代码是互相冲突的两个来源，不从中任选一套覆盖所有轴。[证][S15][S17]
5. 把第 E7 已量测的那一轴结果并入表；剩余每轴先由 CAD 和供应规格确认，装配后 E10/E11 再实测。对无法确认的总比、方向和零位写“未放行”，不能填默认值伪装完成。
6. 冻结每个加工件的材料、工艺、关键配合/公差、数量、表面处理和检验方式。同名 STL/STEP 可能是替代工艺；购物车/螺丝截图不是净用量。
7. 解决皮带长度冲突、端子/线束长度与活动空间；按最终装配检查全行程干涉、工具可达性、重力支撑和 J6 线束扭转。
8. 先报价与接口样件，再放行整套净用量采购。当前有四个 mini11、一个 mini8 和 J6 行星电机的候选，不应概括成“先买六个一样的谐波减速器”。[S14]

| 多套模型/内部改版 | 原版、木子版、视频 V2 并存 | 视频 V2 内仍有改版 | E7 仅局部锁定；E9 整体闭合 |

**5. 现在只学**：把已有 CAD/运动学能力用于本机；按求解器坐标定义测轴线距离、零偏和传动关系；材料/公差必须能服务于具体配合。

**6. 现在不学**：为课程完整而重建所有旧版 CAD、完整 GD&T 培训、还没装上的视觉标定、未购买减速器的高级寿命模型。

**7. 成功/失败后的下一步**：版本/规格/工艺闭合后才进入 E10 分批采购装配。卡在单一零件时继续已有模块，不把猜测提交给工厂；询供应商完整规格或修改本轴接口，并把变化回写参数表。

## 10. E10～E12：六轴整机

### E10：逐轴装配，不一次使能整臂

**1. 实际结果**：六个独立验收的关节逐步构成机械臂，每新增一轴都能说明其 ID、方向、传动比、零位和允许行程。

**2. 为什么现在做**：E9 已避免版本混装，E2～E8 已给出每个模块的试验方法，可以复制“已理解的模块”而不是复制未知故障。

**3. 最少硬件**：按已冻结 BOM 分批补齐剩余电机/板/减速器/加工件。扣除现有可用于整机的 A/B 节点和单关节，不重复购买；长线束与整机电源到实际需要时再定型。

**4. 操作顺序**：

1. 板卡离线逐一验证 SWD、原始编码器、配对校准、有限小运动和 CAN；复制的是安全实验能力，不把 A 板的校准表复制到其他电机。
2. 每关节单独安装/量测，把 E9 的候选总比、方向和范围变成实际值。电机与磁铁重新装配后确认是否需要拆下传动重标定。
3. 固定基座，按选定 CAD 的装配依赖组装下部和腕部；J2/J3 等重力轴配支撑。先检查机械活动再通电，不徒手托住带载轴边调边装。
4. 按实际接口方向逐针检查电源/CAN 线，所有并联供电针均测通断；确认终端只有总线两端。此时才制作完整线束，不把首条短线经验套到全部接口。
5. 首次整机上电保持全部禁用，只确认六节点反馈；随后一次只动一轴，在窄于最终限位的窗口内核对输出方向和机械间隙。
6. 每增加一轴记录供电压降/电流、线束拉扯、发热和紧固；J6 的源码 ±720°不是线束两圈能力证明，先按实际布线设更窄范围。
7. 通过单轴的负载/停机/恢复后才组合动作，不运行原始整机 HOME/CALIBRATION 去“自动找正确姿态”。

**5. 现在只学**：多节点供电和线束管理、模块验收、重力轴停机、装配顺序与零位一致性。

**6. 现在不学**：Wi-Fi 遥控、视觉闭环、全部工业可靠性标准、尚未建立的高负载性能宣传指标。

**7. 成功/失败后的下一步**：六轴逐一可控后转 E11；哪一轴失败就回它的 E2/E6/E7 对照，不同时拆改六轴。未定位的线束错误优先断电处理，不能靠多次重启排除。

### E11：REF 六轴、零位与 FK/IK

**1. 实际结果**：主控能正确显示六轴状态，用真实参数解释末端位置，并完成小范围关节目标及经过检查的末端位姿目标。

**2. 为什么现在做**：六轴实体、传动和方向有实际证据，计算结果才可能对应真实机械，而不是先把漂亮的仿真当成复刻完成。

**3. 最少硬件**：已有六轴、REF、有线 PC、支撑及已有量具；不加视觉相机、网络模块或第二套主控。

**4. 操作顺序**：

1. 从已验证的 REF 双轴副本扩展活动轴为真实 1～6，检查接收白名单、到位条件、节点超时和发送故障。打开原 ASCII/Fibre 前完成尚未使用路径的解析/队列修复。[S15]
2. 将实测传动比、inverse、限位、零位和求解器几何常量写入本机配置，逐项读回/对照。若总比非整数，不能把原 `uint8_t reduction` 四舍五入使用，需要相应类型/换算修改。[S15]
3. 明确原启动 `REST_POSE` 是假设的姿态，不是绝对多圈传感器。用可重复的机械标记/治具建立上电基准，定义关机后是否允许搬动关节。
4. 把 REF 零位标定拆成“人工定位确认→读反馈→写偏置→确认受限移动→校验→重启”；原 `CalibrateHomeOffset()` 会使能、改变 J2/J3 电流、自动收拢、写偏置并重启，不是原地读取。固定恢复 1 A 的代码也要与本机额定值一致。[S15]
5. 离线用已有 Python/运动学能力测试 FK 和 IK：已知姿态、FK→IK→FK、不可达、限位、零位移、零速度和非有限数。先验证代码与坐标，不在实体上试所有边界。
6. 先下发单轴/关节空间小目标，比较末端量测与 FK；有误差按总比→方向→零位→坐标→几何尺寸→TCP 排查，再讨论控制误差。
7. FK 一致后才开放 `@` 位姿输入，检查失败返回和解的连续性。函数叫 MoveL 不代表已实现经碰撞检查的笛卡尔直线插补，现有路径主要是 IK 后转关节运动。[S15]
8. 分级做组合动作、掉线/复位恢复、温升、输出重复性和负载测试。目标与反馈接近、到达标志、上位机 `ok` 是不同证据，不可互相替代。

**5. 现在只学**：本项目使用的坐标与几何定义、零位偏置、FK/IK 解和可达性、主控调度/节点完成、TCP 与重复定位。

**6. 现在不学**：从头再上一遍已掌握的机器人学课程、视觉纠偏、强化学习直接上实机、网络自动恢复运动、未定义工况的精度优化。

**7. 成功/失败后的下一步**：有线关节/末端目标均可解释且故障可恢复，转 E12。末端坐标不对先检查 E9/E10 参数来源，不先改整套 IK 或使用视觉掩盖几何错误；队列卡住回 E8 的任务/反馈边界检查。

### E12：DummyStudio 或最小有线上位机

**1. 实际结果**：在可见界面中连接本机、读取姿态、发送受限任务，并明确显示“接受/执行/到达/拒绝/故障”。可以选择现有 DummyStudio，也可以继续使用你理解的 Python 客户端。

**2. 为什么现在做**：界面是已经可靠的控制链路的外壳，而不是首个闭环的依赖。现在适配 UI 不会同时承担焊板、编码器和运动学调试。

**3. 最少硬件**：已有 PC/USB 线。DummyStudio 为 Windows Unity 成品；使用它需要可运行的 Windows 环境，不为此购买新控制硬件。[S18]

**4. 操作顺序**：

1. 保留 E11 可工作的终端客户端作为诊断基准。先在运动禁用、必要时相线断开的条件下启动新客户端，检查连接时是否自动发 START/HOME/旧目标。
2. 核对实际端口、VID/PID 和串口配置；源码 VID=0x1209 与配置线索相符，但真实枚举仍需验证。不把“配置看起来一致”当成功连接。
3. 先读状态/关节位置，确认反馈新鲜度；再显式授权一条小范围任务。原 simple-cli 的 start 会循环发 `!START`，不能直接作为默认连接行为。[S18]
4. 在兼容已有协议的同时，保留固件侧输入、限位、到达和停止判定；GUI 的停止按钮不等于物理急停。
5. 测试关闭窗口、拔 USB、异常退出、重连，确保设备不会自动继续历史运动。记录拒绝原因，不让所有失败都显示成 `ok`。
6. 若 DummyStudio 的内部行为无法可靠适配，就先使用有源代码的最小 Python 面板；不为“复刻完成必须长得一样”逆向整个 Unity 成品。

**5. 现在只学**：客户端协议适配、异步状态显示、连接/重连、命令生命周期与本地安全边界。

**6. 现在不学**：Unity 完整开发课程、漂亮动画、自定义 USB 协议栈、App 商店发布、网络远控。

**7. 成功/失败后的下一步**：有线上位机稳定后，基础 Dummy 复刻路线完成；按兴趣选 E13。UI 不工作就回 E11 终端复测，区分客户端与底层，不通过放宽固件保护来迎合界面。

## 11. E13：后置扩展，不再开一个大坑

### E13：每次只选择一个能展示的新能力

**1. 实际结果**：选择一个小目标，例如隔离环境下的网络串口回环、RViz 中正确的 URDF，或仿真中的一次 MoveIt 规划；不是同时完成 ESP32、ROS、视觉和强化学习实机部署。

**2. 为什么现在做**：底层已可解释，扩展价值清楚，而且你已有 Python/RL 经验可以发挥，不用再把新增问题和电机基础混在一起。

**3. 最少硬件**：ROS/URDF/FK 仿真通常只需现有电脑；选 ESP32 才使用/购买对应硬件；选视觉才评估相机；不因进入 E13 就一套全买。

**4. 操作顺序**：

1. 写一句可验证目标，例如“URDF 在三个已知关节姿态与实物一致”，其余扩展暂不做。
2. 做 ROS/MoveIt：从 E9/E10 的最终坐标、几何、限位和惯量资料建立模型；先 RViz/FK，再规划仿真，再通过受限有线接口接实物。不假定仓库已有可用 URDF。
3. 做 ESP32：先核对并恢复主线相对路径占位文件、固定 ESP-IDF/工具版本。现有 `main/net.c` 是普通文本路径，空 HEX/工具 ZIP 不是可用构建产物。[S19]
4. ESP32 首次只连串口回环或模拟目标，不接带力矩的 REF。关闭公共 MQTT/不必要监听，补认证/授权与断连行为，确认无未经授权写命令再接本机。
5. 做 RL/视觉：先沿用仿真经验，在离线模型/回放中验证目标和限位，再通过本地受限接口执行；模型输出不是直接跳过控制层的许可。
6. 每个扩展独立记录成功/失败和新增物品；涉及分发或商业使用时再逐项核对模型/软件/资产许可证，不把 GPL 错解为禁止一切商业使用。

**5. 现在只学**：当前所选扩展的接口、坐标或通信知识。每个知识点必须让这个新展示更可靠，而不是泛学“机器人全栈”。

**6. 现在不学**：其他尚未选择的扩展、互联网远程运维框架、全部 ROS 生态课程、未明确用途的硬件。

**7. 成功/失败后的下一步**：一个扩展可演示再选下一个；失败保持 E12 有线基线不动，用模拟/回环定位。扩展失败不等于前面的硬件复刻失败。

## 13. 分阶段安全：按真正引入风险的时点

### 13.1 A～F 前置分类

### 13.4 第一次成功不等于长期运行许可

E4 的一次往返验收只说明这个**短时、固定裸电机、有人看守、本地单次**实验成功。之后再做重复性、温升、异常注入和通信恢复测试；进入负载、持久保持、多轴或网络时不能沿用这一简化许可。

不在运动中手拔磁铁、接拔相线或用手堵转。故障注入先用软件标志/断相线测试逻辑，再在防护与支撑条件下验证实际故障。普通物理断电开关不是认证安全系统，但在这个实验台上必须直接有效。

## 15. 故障排查树：保住最近一次成功

```text
没有成功构建？
  -> 工具是否存在 -> CMake 源/输出目录 -> 第一条编译/链接错误
  -> 不买硬件解决软件安装问题

有产物但板不运行？
  -> 电源/共地 -> SWD 线与方向 -> 降低 SWD 频率 -> 复位下连接
  -> 相线保持断开；恢复最近 FLASH_ONLY，不随意全擦

程序运行但 PC 无数据？
  -> 正确串口/115200 -> 板 TX 到适配器 RX -> GND -> lab 是否输出
  -> 先在终端看到整数，不先做 GUI/浮点图形

有数据但 raw 不跟手转？
  -> 磁铁是否随轴转/位置正确 -> spi_ok -> parity/noMag
  -> 再查片选/线序/时序；必要时借分析仪，不先改控制参数

raw 正常但校准失败？
  -> 匹配电流/两相配对 -> 磁铁与供电 -> 错误阶段 -> Flash 区域
  -> 校准不受普通位置限速；不在带减速器的轴上反复重标

校准正常但 E4 异常？
  -> STOP tick 是否初始化 -> q0/单位/零偏 -> 实际 RAM 限值
  -> 同次采样健康/旧入口是否隔离 -> 实际反馈是否到位
  -> 不靠 STATE_FINISH 一项，也不同时改四个变量

E4 好，E5 不好？
  -> 新增 RX/行缓冲/单位/授权/timeout
  -> 退回 E4，证明传感与电机基准没坏

单节点好，CAN 双节点不好？
  -> ID/拨码 -> 终端数 -> H/L/参考地 -> 位时序/DLC -> 供电/TX 错误

电机好，关节/末端不好？
  -> 机械干涉/传动比 -> 方向/零位 -> 输出回差/负载
  -> 活动轴/反馈 -> 几何/坐标/TCP -> 最后才审 IK/复杂控制
```

一轮排查只改变一个条件。停在 E2/E4/E6 哪个最近成功点，就先用那个版本回归；不要因为一个新增功能失败就同时换电机、板、磁铁、参数和代码。
