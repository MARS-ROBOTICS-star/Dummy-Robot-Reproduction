## 1. 规划依据

### 1.1 我对你的理解

- **背景**：机械专业，会建模和仿真，懂运动学；Python 熟练，做过强化学习机器人项目；C 语言尚可；嵌入式、电路、焊接动手经验接近零。电脑有 Windows 和 Linux。
- **目标**：借这个项目从嵌入式入门走到进阶；能看懂原理图、画 PCB、会焊接；最终完整复刻 Dummy V2（机械锁定"视频款"）。
- **学习方式**：先动手看到效果，再回头补理论。不接受"学完整套课程再动手"，也不满足于"买成品只负责装配"。看得见的效果会给你很大的成就感。
- **约束**：从零开始，没有工具；担心整机 4000–6000 元的花费和失败风险；时间不均匀，但时间不是主要矛盾；会大量使用 AI。

### 1.2 四条原则

1. **每个阶段都有一个看得见的成果。**
2. **先让它工作，再弄懂为什么，最后自己改一处。** 原版代码的缺陷不是开工前必须修完的门槛，而是后面的练习题。
3. **有对照才能排错。** 先有一块确定能用的板（A 板），再造自己的板（B 板）。
4. **花钱按关口。** 只买下一阶段要用的东西。

## 3. 各阶段详解

### 阶段 0：打地基

**目标**：从"跟着视频能做出来"，变成"能说清楚每一行代码让哪个引脚做了什么"。同时开始动烙铁。

**成果**

- 最小板上：PWM 呼吸灯；电脑串口发 `led on` 控制 LED；SPI 读出 W25Q64 的芯片 ID。
- 一块自己焊好的练习板。

**嵌入式线：课程选学**（完整选学表见第 4 节）

- 必学：6-1～6-4（定时器、PWM）、9-1～9-5（串口）、11-1～11-5（SPI）、15-1～15-2（Flash）
- 先跳过：6-5～6-8（输入捕获、编码器接口）、12（RTC）、13（低功耗）；第 10 章 I2C 留到阶段 7
- 已学的 3–5 章：挑"按键控制 LED"，关掉视频重做一遍

**每节课的学法**（五步，别只跟做）

1. 开始前写下一个问题。例如："为什么改 CCR 的值，LED 亮度就变了？"
2. 跟着视频做一遍。
3. 关掉视频，从空工程重做一遍。
4. 改一个参数，先猜现象，再运行验证。
5. 画一条链：代码 → 外设寄存器 → 引脚 → 电路 → 现象。

**三个"回到 Dummy"练习**（每个 30–60 分钟，答案都在源码里；路径相对 `source/1.Dummy V2任同学整理/2.Firmware/dummy-42motor-fw/`）

| 学完 | 去源码里找 | 要回答的问题 |
|---|---|---|
| 第 6 章 定时器/PWM | `Core/Src/tim.c` 里的 TIM1、TIM2、TIM4；`UserApp/main.cpp` 的 `Tim4Callback20kHz()` | 20 kHz 是怎么算出来的（提示：72 MHz ÷ 72 ÷ 50）？每 50 µs 执行一次的函数做了哪两件事？TIM1 的 100 Hz 管什么？TIM2 的两路 PWM 输出到哪两个引脚？ |
| 第 9 章 串口 | `Core/Src/usart.c`、`UserApp/protocols/interface_uart.cpp` | 波特率多少？用哪两个引脚？如果发送 `p10` 会发生什么（答案：电机转到绝对第 10 圈，不是转 10°）？ |
| 第 11 章 SPI | `Port/mt6816_stm32.cpp`、`Ctrl/Sensor/Encoder/mt6816_base.cpp` | 读一次编码器传了几个字节？14 位角度是怎么拼出来的？为什么是 16384 档？校验位是干什么用的？ |

**硬件线：开始动手**

- 买万用表、恒温烙铁和耗材（清单见第 6 节）。
- 焊一块直插练习板，再焊贴片练习板上的 0805 部分。
- 用万用表量你的最小板：3.3 V 在哪里；按键按下前后引脚电压怎么变。把课程里的"上拉输入"和表笔上的读数对上。
- 推荐买一个 24 MHz 8 通道逻辑分析仪（几十元），装免费软件 PulseView，看串口和 SPI 的真实波形。课上讲的时序原理，在波形里一眼就能看懂。

**完成标准**

- [ ] 不看视频，能从空工程写出"定时器中断 + PWM + 串口收发"
- [ ] 能手算：给定时钟、预分频、重装值，求出中断频率和 PWM 频率
- [ ] 三个"回到 Dummy"问题都能用自己的话答出来
- [ ] 焊完一块练习板，焊点光亮、没有连锡
- [ ] 会用万用表量电压、电阻、通断

### 阶段 1：纸上读懂 Motor-42

**目标**：买板之前，先在纸面上把这块板弄懂。之后判断"买什么、怎么接、哪里出了错"，都靠这一步打下的底子。

**成果**：一张你亲手画的 Motor-42 功能框图，加一张"代码—引脚—原理图—芯片"对照表。

**第 1 步：认识板上的每个元件（最直观，先做这个）**

浏览器打开 `1.Hardware/motor42/Motor-42.html`（交互式 BOM）。点列表里的元件，板图上会高亮它的位置。对照实物照片 `6.Docs/PCB/m42.jpg`，找到这几个关键元件：

| 位号 | 元件 | 一句话作用 |
|---|---|---|
| U3 | STM32F103CBT6 | 大脑，运行闭环控制 |
| U8 | MT6816（在背面，正对电机轴） | 磁编码器，测电机轴转角 |
| U1、U2 | TB67H450FNG | 电机驱动芯片，每颗驱动电机的一相线圈 |
| U5 | SN65HVD232 | CAN 收发器，把 MCU 的信号转换成总线上的差分信号 |
| U6 | ME3116 | DC-DC 降压，先把 24 V 降下来 |
| U7 | LP2992 | LDO，稳出 3.3 V 给 MCU 和编码器 |
| Y1 | 12 MHz 晶振 | MCU 的时钟源 |
| R3、R8 | 0.1 Ω 电阻 | 电流采样，驱动芯片靠它限制线圈电流 |

这块板只有 41×41 mm，却有 82 个元件，大部分是 0402 封装（1.0×0.5 mm）。这也是第一块板不建议自己焊的原因。

**第 2 步：打开原理图**

原理图是 Altium 格式（`1.Hardware/motor42/PCB源文件/` 下的 5 个 `.SchDoc` 和 `Motor-42.PcbDoc`）。在 Linux 上可以这样打开：

1. **KiCad（免费，推荐）**：在原理图编辑器里选"文件 → 导入 → 非 KiCad 原理图"，逐张导入 5 个 `.SchDoc`；在 PCB 编辑器里选"文件 → 导入 → 非 KiCad 电路板"，导入 `Motor-42.PcbDoc`。阶段 4 导出制造文件也用它，现在装上正好先熟悉。
2. **嘉立创 EDA 专业版**：支持导入 Altium 文件，和下单打样在同一个平台。
3. **Altium 365 Viewer**（网页版，免费注册）：上传就能看。前两种导入后如果显示错乱，以它为准。

**第 3 步：按顺序读 5 张图，每张读三遍**

顺序：`Port` → `Power` → `MCU` → `Interface` → `Drive`

- 第一遍：只画方框和箭头——电从哪来，信号往哪走。
- 第二遍：追具体的线——从 MCU 某个引脚，一直追到外部芯片的某个引脚。
- 第三遍：才去看电阻电容的取值、查芯片手册。

| 图 | 要找到的东西 |
|---|---|
| Port | P1、P2 每一针是什么（24 V、CAN_H、CAN_L、GND；两针 24 V、两针 GND 是并联的）；P3 每一针是什么（SWDIO、SWCLK、UART_TX、UART_RX、GND）；电机的四个焊盘 A+ A- B+ B- |
| Power | 24 V 进来后依次经过哪些元件：D1（SS54 肖特基二极管，看它串在哪里、起什么作用）、D2（SMBJ28CA 浪涌保护管）、ME3116 降到几伏、LP2992 再稳成 3.3 V。中间电压是多少，请你自己在图上找出来 |
| MCU | 每个供电脚旁边的 0.1 µF 去耦电容；晶振和两个 20 pF 电容；复位电路；BOOT0 的接法；SWD 的两根线 |
| Interface | MT6816 的 SPI 四根线；CAN 收发器和 120 Ω 终端电阻 R12；4 位拨码开关（固件只用了 3 位做节点 ID，第 4 位接到了哪里？和 R12 有没有关系？）；两个按键；两个 LED |
| Drive | TB67H450 的 IN1、IN2、VREF 分别接到 MCU 的哪里；VREF 为什么要先经过电阻和电容（把 PWM 滤成直流电压）；0.1 Ω 采样电阻在哪 |

| 编码器片选 | PA15 | SPI1_CS | | |

**第 5 步：从标准库过渡到 HAL，补够用的 C++**

课程用的是 Keil + 标准库；Dummy 用的是 CubeMX 生成的 HAL 库 + C++ + CMake。两边原理完全相同，只是写法不同。

- **桥接练习**：装 STM32CubeMX（Linux、Windows 都有），给你的课程最小板生成一个 HAL 工程（工具链选 CMake），把"串口打印 + 定时器中断 + PWM"重做一遍，用 E0 编译 Dummy 固件时的同一套 `arm-none-eabi-gcc` 编译，再用 ST-Link 烧录。重做时对照：

| 课程（标准库） | Dummy（HAL） |
|---|---|
| `GPIO_Init(GPIOA, &s)` | `HAL_GPIO_Init(GPIOA, &s)` |
| 自己写 `TIM_TimeBaseInit(...)` | CubeMX 生成 `MX_TIM4_Init()` |
| `TIM_ITConfig(...)` + `TIM_Cmd(...)` | `HAL_TIM_Base_Start_IT(&htim4)` |
| `USART_SendData(...)` | `HAL_UART_Transmit(...)` |
| 中断函数里自己判断、清除标志位 | HAL 处理完标志位，再调用你的回调函数 |

  结论：开时钟 → 配引脚 → 配外设 → 开中断 → 启动，这个顺序两边一样，区别只在函数名和"初始化代码由谁来写"。

- **读 Dummy 代码够用的 C++**（不必系统学完 C++）：
  - 类和对象，比如 `Motor motor;`，以及成员函数和 `->`
  - 继承和 `virtual`：`EncoderBase` → `MT6816Base` → `MT6816`，驱动也是同样的三层。这样控制代码不用关心具体是哪颗芯片
  - `extern "C"`：C 写的中断入口调用 C++ 写的函数时要用它
  - `static_cast`

- **读代码的路线**：`Core/Src/main.c`（HAL 初始化）→ `UserApp/main.cpp`（组装电机对象、启动定时器）→ `Tim4Callback20kHz()` → `Ctrl/Motor/motor.cpp` → `Ctrl/Sensor/Encoder/mt6816_base.cpp` → `Ctrl/Driver/tb67h450_base.cpp`。读 `motor.cpp` 时对照 `2.Firmware/Dummy 源码注释/motor.cpp`，那是带中文注释的版本。

- **遇到任何函数，先问六个问题**：它做什么？参数是什么类型？单位是什么？取值范围多少？调用前系统要处于什么状态？调用后硬件或状态会怎么变？

**完成标准**

- [ ] 能对着你的框图讲清楚两条链：
  1. 手转电机轴 → 磁铁 → MT6816 → SPI → STM32 → 串口 → 电脑上的数字
  2. 电脑发 `p0.1` → 串口 → 解析命令 → 位置规划 → 20 kHz 闭环 → PWM 和方向引脚 → TB67H450 → 线圈电流 → 电机转 36°
- [ ] 对照表填完，每一行都在原理图上亲眼找到过
- [ ] 能说出 P1 和 P3 的区别，以及插错会怎样

### 阶段 2：点亮第一块 Motor-42（A 板）

**目标**：你编译的固件跑在真实的电机板上；第一次看到"手转电机轴，电脑数字跟着变"。

**成果**：串口终端里 0–16383 的角度值随手转变化；一段用 Python 画的角度曲线。

**为什么第一块板买现成的**

你想亲手做硬件，这个方向是对的，阶段 4 就会做。但如果第一块板也自己焊，出了问题你没法判断是焊接、元件、固件、磁铁还是接线的原因——五个未知数同时存在。先有一块确定能工作的 A 板，之后你焊的 B 板哪里不对，拿 A 板的同一个测点一比，一次就能排除一类原因。A 板是对照组，不是偷懒。

**要买的东西**

A 基准套件：优先买"电机板 + 配套 42 步进电机 + 磁铁 + 固定件"一整套、卖家实测过的（论坛、复刻群、闲鱼、淘宝都有人出）。下单前问清 6 件事：

1. 发实物正反面照片：MCU 是 STM32F103**CB**T6（不是 C8T6），晶振 12 MHz，背面焊了 MT6816
2. 是否上电测过：3.3 V 正常、ST-Link 能连上、编码器有读数、电机能转
3. 电机型号、机身长度（V2 用 42×40）、额定电流、哪两根线是同一相
4. 磁铁尺寸、是否径向充磁、和芯片之间的间隙、怎么固定
5. 是否已经用这台电机做过编码器校准
6. 板子版本（资料里有原版和"焊盘更改版"），接口是否和 `6.Docs/Pins definations.pdf` 一致

第 3、4 条答不上来的卖家，不要按"基准套件"买。

其他：

- **24 V 电源**：推荐 0–30 V、3 A 以上的可调直流电源（带限流），整个项目都用得上。省钱方案是 24 V 适配器 + 保险丝 + 开关，但第一次上电就没有限流保护了。
- **ZH1.5 6P 线材**：买成品线，或者端子加压线钳自己做。
- **ST-Link、USB 转串口**：江协套件里如果有，直接复用。P3 需要的就是 SWDIO、SWCLK、GND，以及 3.3 V 电平的 TX、RX。

烧录软件用 STM32CubeProgrammer（Windows、Linux 都有官方版本）。

**步骤**

1. 到货后对照交互式 BOM 认一遍元件，拍照存档。
2. 断电，用万用表确认 P1 的 24 V 和 GND 之间没有短路。
3. **电机相线先不接。** 电源设 24 V、限流 0.3 A，从 P1 上电。量 3.3 V，看 LED。电流异常或芯片发烫，立即断电。
4. P3 接 ST-Link（SWDIO、SWCLK、GND），用 CubeProgrammer 连接，读出芯片型号。如果卖家已经做过校准，先把整片 Flash 读出来存档：校准表从 `0x08017C00` 开始，占 32 KB；参数在 `0x0801FC00`。如果芯片开了读保护、读不出来，就算了，不要去解除读保护——解除会把整片擦掉。
5. **你对 Dummy 固件的第一次修改**，在 `UserApp/main.cpp` 里：
   - 取消第 73–75 行三个 `printf` 的注释，让它开机打印当前参数。仔细看第 74 行：格式串里有三个 `%d`，却只给了两个参数——这是原作者留下的小 bug，由你来修。再加一行，打印 `enableMotorOnBoot` 和 `calibrationCurrent`。
   - 在 `for (;;)` 主循环里加上：

     ```cpp
     static uint32_t lastPrint = 0;
     if (HAL_GetTick() - lastPrint >= 100)   // 每 100 ms 打印一次
     {
         lastPrint = HAL_GetTick();
         printf("raw=%d\r\n", mt6816.angleData.rawAngle);
     }
     ```

   - 为什么这样做是安全的：原版固件默认 `enableMotorOnBoot=false`，上电处于停止模式（`Ctrl/Motor/motor.cpp:557`），不按键、不发命令就不会驱动电机。而编码器每 50 µs 都会更新一次（`motor.Tick20kHz()` 里的 `encoder->UpdateAngle()`），所以在主循环里直接读就行。
   - 重新编译后只烧写程序，**不要选"全片擦除"**，否则校准表和参数会丢。
6. 断电，装上电机和磁铁（相线仍然不接）。USB 转串口接 P3：板子的 TX 接适配器的 RX，GND 接 GND。串口助手设 115200。
7. 上电，先看开机打印的参数，确认 `enableMotorOnBoot` 是 0（如果卖家改过设置，这里会暴露出来）。然后手转电机轴：`raw` 在 0–16383 之间跟着变，转过一圈会从 16383 跳回 0。★
8. 用 Python（pyserial + matplotlib）写个小脚本实时画角度曲线。按"角度 = raw × 360 ÷ 16384"换算，和你手上实际转过的角度对比。

**这一阶段顺带搞懂**

- 14 位 = 2¹⁴ = 16384 档，每档约 0.022°。档位多不等于精度高——精度还取决于磁铁装得正不正，所以才需要校准。
- 从 16383 跳到 0 是转过了一圈，不是倒转。多圈位置要靠软件累加，`motor.cpp` 里计算 `deltaLapPosition` 的那几行就是在做这件事。
- 如果数字不变：先看磁铁是否跟着轴一起转、有没有对中；再用逻辑分析仪看 SPI 波形。

### 阶段 3：第一次闭环——电机听你的话

**目标**：电机转到你指定的角度并停住，你能解释它为什么能停住。然后自己改进一处原版代码。

**成果**：串口发 `p0.25`，电机转 90° 停住；Python 画出目标位置和实际位置的曲线；一段你自己写的新串口命令解析。

**步骤**

1. **找相线**：断电，万用表测电机的四根线，两两之间电阻只有几欧的是同一相。对照 Port 图的 A+ A- B+ B- 接好。
2. **定电流**：默认运行电流 1 A、校准电流 2 A（`main.cpp` 第 41、44 行）。如果电机额定电流低于 1.5 A，把两个值都调低。
   **注意这个坑**：第一次上电后，参数就存进了 EEPROM，之后一律以 EEPROM 为准，改代码里的默认值不会生效（`main.cpp` 第 31–34 行）。可以在第 58 行后面直接赋值覆盖，例如 `boardConfig.calibrationCurrent = 1200;`。
3. **编码器校准**（卖家已经用这台电机校准过的可以跳过）：电机夹紧，轴上不装任何东西。长按 KEY1 约 1 秒，电机会正转、反转几圈采集数据，写入 Flash 后自动重启。这一步是在建立"磁铁读数 → 真实角度"的对照表（16384 个点，32 KB）。
4. **第一次闭环**：单击 KEY1 进入位置模式。电机会先回到零位（上电时它离零位不超过半圈），然后保持住。用手轻拧轴，能感到它在往回顶，松手又回到原位——这就是闭环。★ 再单击一次 KEY1 停止。
5. **串口控制**：把适配器的 TX 也接到板子的 RX。
   - 发 `p0.25`（转到 +90°）、`p0`、`p-0.25`。注意 `p` 是**绝对位置，单位是圈**。
   - 发 `v1`（每秒 1 圈），再发 `v0` 停下。
   - 先用手捏住轴，再发 `c0.1`（恒定 0.1 A）：你感受到的是一股恒定的扭力，而不是"位置"。松手后它会加速转起来，随时发 `c0` 或单击 KEY1 停止。
   - 三种模式的手感差别，就是控制理论里电流环、速度环、位置环最直观的一课。
6. **Python 小工具**：发送目标，同时读回位置。在主循环的打印里加上 `(int)(motor.controller->GetPosition() * 1000)`，以"千分之一圈"为单位打印整数，避开嵌入式里浮点数打印的麻烦。画出目标和实际曲线，观察上升时间、超调、稳态误差。
7. **调参实验**（可选）：改 `dce_kp`、`dce_kv`、`dce_ki`、`dce_kd` 中的一个（同样要注意 EEPROM 的坑），对比曲线变化。一次只改一个。

**这一阶段顺带搞懂**

| 现象 | 背后的知识 | 看哪里 |
|---|---|---|
| 步进电机能停在任意角度，而不是只能一步 1.8° | 两相电流按正弦、余弦分配，合成一个可以连续转动的磁场方向（"细分"）。本项目一圈 = 200 步 × 256 = 51200 个计数 | `Ctrl/Driver/tb67h450_base.cpp` 的 `SetFocCurrentVector`；`Ctrl/Motor/motor.h` |
| 驱动芯片怎么知道该给多大电流 | MCU 输出 PWM，经电阻电容滤成 VREF 电压；TB67H450 根据 VREF 和 0.1 Ω 采样电阻自动斩波限流 | Drive 原理图；`Port/tb67h450_stm32.cpp` |
| 位置为什么不会冲过头 | 先由运动规划生成平滑的目标轨迹，再由 DCE 控制器（类似 PID）算出电流 | `Ctrl/Motor/motion_planner.cpp`、`Ctrl/Motor/motor.cpp` |
| 为什么要校准 | 磁铁装得再准也有偏心，原始读数和真实角度不是一条直线 | `Ctrl/Sensor/Encoder/encoder_calibrator_base.cpp` |

**学习项目：改进一处原版代码**（建议两个都做）

原版代码有几处真实的缺陷（附录 B 有完整清单），修它们正好用上课程第 8、9 章：

- **重写串口命令解析**：原版不检查长度和格式，`p` 后面跟着乱码也可能被当成数字（`interface_uart.cpp`）。改成按行接收、限制长度、非法命令回复 `ERR`，并新增 `stop` 和 `status` 两个命令。
- **加通信超时**：规定"1 秒内没收到新命令就停止"。这样电脑程序崩溃时，电机不会一直执行最后一条命令。
- 进阶：**编码器失效保护**。MT6816 报告"没检测到磁铁"或校验失败时，让电机进入停止状态。`mt6816_base.cpp` 已经读出了这些标志位，只是没有任何代码去用它们。

新代码先在断开相线的情况下测试，确认不会误动作，再接上电机。

- [ ] `p`、`v`、`c` 三种命令都用过，能说出三种控制模式的区别
- [ ] Python 能发目标、画出目标与实际曲线

### 阶段 5：两块板 CAN 通信

**目标**：电脑通过一根 CAN 总线，分别控制 A、B 两台电机。

**成果**：Python 脚本让 1 号电机转、2 号不动，反过来也行；能读回两台电机的位置。

**先学**：江协科技 CAN 总线教程（B 站 BV1vu4m1F7Gt），重点是差分信号、终端电阻、标准帧 ID、数据长度、波特率。

**步骤**

1. 用拨码设节点号：A 板设 1，B 板设 2。节点号每次开机都从拨码读取（`main.cpp` 第 25–28 行），用 CAN 命令改的 ID 重启后会被拨码覆盖。
2. 接线：两块板的 P1、P2 串起来，USB-CAN 接到总线上。CAN 总线只在**物理上的两端**各需要一个 120 Ω 终端电阻。但每块电机板上都有一个（R12），USB-CAN 适配器也可能自带一个——按阶段 1 在 Interface 图上查到的接法，确认哪些接入、哪些断开。断电时量 CAN_H 与 CAN_L 之间约 60 Ω，说明正好两个；约 40 Ω 说明多接了一个。
3. 读懂协议：帧 ID = (节点号 << 7) | 命令号，波特率 1 Mbit/s。例如给 1 号发位置命令 `0x05`，ID 就是 `0x085`，数据前 4 字节是 float（单位：圈），第 5 字节为 1 表示要求回复；读位置命令是 `0x23`，1 号对应的 ID 是 `0x0A3`。完整命令表在 `UserApp/protocols/interface_can.cpp`。
4. 先只发"读位置"（只读，不会让电机动），确认两块板都能回复；再给 1 号发一个小角度的位置命令；再给 2 号发。
5. 用 Python（python-can）写一个小控制台：列出节点、读位置、发目标、全部停止。

**学习项目**

- 电机板端：给 CAN 命令加长度检查（原版不检查，收到短帧时会读到上一帧残留的数据）；加 CAN 通信超时停止。
- 用逻辑分析仪抓 CAN 波形，手工解码一帧。

**完成标准**

- [ ] 两台电机能分别寻址、分别停止
- [ ] 能手工解码一帧位置命令
- [ ] 能解释终端电阻的作用，以及差分信号为什么抗干扰
- [ ] 拔掉 USB-CAN 后，电机的行为是你设计的（停止），而不是一直执行最后一条命令

### 阶段 6：第一个真实关节（你的主场）

**目标**：电机 + 减速器 + 结构件组成一个关节，按关节角度准确转动。**这里是决定要不要投入整机的决策点。**

**成果**：一个能按指令转到 ±30°、±90° 的关节模块；实测的减速比、方向、回差数据。

**选哪一轴**：推荐 J1（底座旋转轴）。它是竖直轴，不受重力影响，断电也不会掉下来。

**步骤**

1. 在 CAD 里打开 `4.Model/Dummy V2 版本 视频款/Dummy-B v2装配体.step`，找出 J1 的完整装配：用哪台电机、哪个减速器、哪些打印件或 CNC 件、轴承和螺丝。同目录的 `改版/` 里有基座和 J1 的改版，先决定用哪一版。
2. 只买这一轴的减速器和标准件。结构件先 3D 打印验证（打印件用来验证，长期承载以后再考虑 CNC）。
3. **先校准，再装配**：装减速器之前，在裸电机上完成编码器校准。装上之后不要再触发校准——它会连续转好几圈。
4. 装配，手动转动，检查有没有干涉、卡滞。
5. 实测减速比：让电机转 N 圈，量输出端转了多少度。同时记录方向。
6. 定零位（做一个机械标记）和软件限位。
7. 量回差：来回转动，用百分表或量角器看输出端的空程。
8. 逐步加负载，观察闭环表现的变化。一次只改一个控制参数。

**完成标准**

- [ ] 减速比、方向、零位、限位都是实测值，并且能解释
- [ ] 关节能稳定停在目标角度；知道回差有多大、从哪里来
- [ ] 写下你的决定：继续整机，还是先停在这里深入某个方向

### 阶段 7：REF 主控 + 双轴

**目标**：由 REF 主控（而不是电脑）通过 CAN 协调两个轴。

**成果**：REF 周期性地给两个轴发目标、显示两轴反馈；任一轴掉线时能识别出来。

**REF 是什么**：主控芯片是 STM32F405RGT6（比 F103 快，带浮点运算单元），运行 FreeRTOS 多任务系统。板上还有 ESP32（Wi-Fi）、CP2102（USB 转串口）、MPU6050（姿态传感器）、NRF24L01（无线模块）和 OLED 屏。一共 99 个元件、双面贴装，比电机板难焊。

**获取方式三选一**：买成品；嘉立创贴片后自己焊剩下的；全部自己焊（电机板焊熟了再考虑）。

**先学**

- 课程第 10 章 I2C 和 MPU6050（REF 上正好有这颗芯片）
- FreeRTOS 基础：任务、延时、队列、信号量（B 站 BV1394y1h7ho 讲了移植和创建任务）
- REF 工程带有 CubeMX 文件 `2.Firmware/dummy-ref-core-fw/REF-STM32F4-fw.ioc`，可以直接用 CubeMX 打开，图形化地看引脚分配

**原版 REF 固件需要改的地方**（附录 B 第 8–9 条）

- 程序写死了六个轴，只接两个轴时会一直等另外四个。需要改成"只管在线的轴"，或者单独写一个两轴测试程序。
- 启动时会一直等 MPU6050（`UserApp/main.cpp` 第 166–170 行），没焊或者坏了就卡在这里。改成有限次重试。
- `!STOP` 只是"停在当前位置"，不是断电急停，所以物理电源开关必须保留。

**步骤**

1. 单独给 REF 上电、烧录，先不接电机板。
2. 读懂 `UserApp/main.cpp` 的启动顺序和各个任务。
3. 写或改出一个两轴版本：先只读两轴的位置，再让单轴做小动作，最后两轴交替动作。
4. 测试掉线：运行中拔掉一个节点的 CAN 线，看 REF 能否发现并停止。

**完成标准**

- [ ] 能画出 REF 固件的任务结构：有哪些任务、多久执行一次、各做什么
- [ ] 两轴能协调运动；拔掉一轴能被识别出来
- [ ] 理解在 CAN 上"命令发出去了"和"电机执行完了"是两回事

## 7. 安全底线

只列真正会烧板、伤人的事：

1. **电机相线只在断电时插拔。** 带电插拔会损坏驱动芯片。
2. **任何板第一次上电都用限流电源**（先设 0.2–0.3 A）。电流异常或芯片发烫，立即断电。
3. **P1/P2（24 V + CAN）和 P3（SWD + 串口）外形一样，插错会烧板。** 做线时用不同颜色区分，或者用你画的转接板。
4. **24 V 回路上要有一个伸手就能按到的物理开关。** 软件里的"停止"不等于断电。
5. **做实验时电机必须夹紧；校准时轴上不能装减速器和负载。**
6. **串口 `p` 命令是绝对圈数。** 第一次发小数值，比如 `p0.1`。
7. **烧录时不要选"全片擦除"**，否则校准表丢失，需要重新校准。
8. **装上减速器后，不要再触发编码器校准**，它会连续转好几圈。
9. **J2、J3 这类受重力的关节断电会掉下来**，调试时要有支撑。
10. **AI 写的代码，你能逐行讲明白之后，才烧进接了电机的板子。**

## 8. 怎样用 AI 学得更扎实

- **让 AI 讲解时，要求它给出具体的文件和行号**，你自己打开核对。AI 说错的时候，源码不会错。
- **先自己预测，再让 AI 验证。** 例如先写下"TIM4 改成 10 kHz 要改哪个数"，再问 AI。
- **AI 写的代码，你逐行复述一遍**，讲不通的地方就是你该补的知识点。
- **让 AI 出题考你**："根据 Motor-42 原理图，如果 3.3 V 没有输出，应该依次测哪几个点？"
- **排错时，把"现象 + 已经排除了什么 + 测量值"一起告诉 AI**，而不是只说"不工作"。
- **每个阶段结束写一页笔记**（你装了 Obsidian，正好用它）。一个阶段后你还能用自己的话讲清楚，才算真的学会。
