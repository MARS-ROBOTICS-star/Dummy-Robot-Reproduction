## 一、文件在哪:两个世界

这套资料最容易糊的地方,是**设计文件**和**制造文件**混在一起看。

| | 设计文件(可编辑) | 制造输出(定稿) |
|---|---|---|
| 文档世界的类比 | `.docx` | 导出的 `.pdf` |
| PCB 世界 | `.SchDoc` / `.PcbDoc` | **Gerber + 钻孔文件** |

### Motor-42 的文件地图

| 要什么 | 路径 | 说明 |
|---|---|---|
| 原理图 5 页 | `source/dummy/hardware/motor42/*.SchDoc`<br>`source/1.Dummy V2任同学整理/1.Hardware/motor42/PCB源文件/*.SchDoc` | ✅ **两处 SHA-256 逐字节一致**(2026-10-13 实测 MCU/Power/Port/Interface/Drive 五个文件全部命中) |
| 版图 `Motor-42.PcbDoc` | `<V2>/1.Hardware/motor42/PCB源文件/` | ✅ **只有这一处**。`source/dummy` 整个克隆里一个 `.PcbDoc` 都没有(find 实测),只有 11 个 `.SchDoc` |
| 送厂 Gerber | `source/dummy/hardware/motor42/motor42-gerber.zip` | 2023-11-13 从 V1.01 导出,177 孔齐全 |
| ❌ 不要用 | `<V2>/1.Hardware/motor42/motor42 Gaber.zip` | 缺 `.TXT` 钻孔文件,工厂没法打孔 |
| ❌ 不要用 | `<V2>/1.Hardware/motor42/Motor-42(焊盘更改版).rar` | 比 V1.01 少 4 个过孔、无配套 Gerber、改动无说明 |

**要原理图 + 版图配套看,直接去 `<V2>/1.Hardware/motor42/PCB源文件/` 开工程**,不用两边切。

### ⚠️ 一个必须心里有数的错位

**手上的 Gerber 和能打开的 PcbDoc,不是同一时刻的同一个文件。**

- Gerber = 2023-11 从 **V1.01** 导出,丝印上**带 `V1.01` 字样**
- `PCB源文件/` 的 PcbDoc = 2024 年改版,**丝印里 `V1.01` 被删掉了**(在 AD 的 3D 底面视图里能亲眼验证:只有 `HENGX`,没有 V1.01)

两者**布线完全相同**(索引第十三章:155 个过孔坐标一一对应),差别只在丝印和部分焊盘。

实际影响:

| 用途 | 能不能用 PcbDoc |
|---|---|
| 看元件位置、看走线、学叠层 | ✅ 完全可靠 |
| 重新导 Gerber 去打板 | ⚠️ 做得出板子,但那就不是被别人焊通过的那一版了 |

**结论:打板用现成 zip,PcbDoc 只用来读。打回来的板子底面会比屏幕上多一行 `V1.01`,这是正常的。**

## 二、文件类型对照表

### 设计侧(AD 里编辑的)

| 扩展名 | 是什么 | 本项目情况 |
|---|---|---|
| `.PrjPCB` | 工程文件。**本身不含电路**,只是一张清单(哪些图纸/版图属于本工程)+ 工程选项 | **42/35/REF 都缺**,只有 LedRing 有 → 要自己建 |
| `.PrjPCBStructure` | 工程图纸层次结构缓存 | 可忽略 |
| `.SchDoc` | 原理图页。记录**谁连谁**,无真实尺寸概念 | 42 板 5 页:`Port` `Power` `MCU` `Interface` `Drive` |
| `.PcbDoc` | 版图。记录**东西在哪、铜皮怎么走**,有真实毫米 | 4.1 MB |
| `.SchLib` / `.PcbLib` | 原理图符号库 / 封装库 | **本项目没有**。只读图不影响;想改图加元件时会发现库是空的 |
| `.~(1).PcbDoc.Zip` | AD 自动版本备份(`History/` 下) | 不是"另一版设计",不要当资料 |
| `.html` | InteractiveHtmlBom 导出的交互式 BOM | 浏览器开,点型号 → 板上正反面同时高亮 |

**核心认知**:原理图和 PCB 是**两份互相独立的文件**,靠「位号 + 网络名」对应。原理图上的 U3 和 PCB 上的 U3 是两个不同对象,AD 用 `Update PCB Document` 同步,用 `Cross Select Mode` 让你点一个另一个跟着亮。

### 制造侧(Gerber + 钻孔)

判据一句话:**能在板子上留下物理痕迹的层才要送厂,其余全是报告。**

| 扩展名 | 含义 | 送厂 | 对应工序 |
|---|---|---|---|
| `.GTL` / `.GBL` | 顶层 / 底层铜 | ✅ | 底片曝光 → 蚀刻 |
| `.G1` / `.G2` | 中间层铜,**正片**(画的就是铜) | ✅ | 内层芯板蚀刻 |
| `.GP1` / `.GP2` | 内电层 Plane,**负片**(画的是"不要铜"的地方) | ✅ | REF 主控板用这种 |
| `.GTS` / `.GBS` | 顶 / 底阻焊 | ✅ | 刷绿油,照它开窗 |
| `.GTO` / `.GBO` | 顶 / 底丝印 | ✅ | 印白字 |
| `.GTP` / `.GBP` | 顶 / 底锡膏层 | 做钢网才要 | 钢网开孔 |
| `.GKO` | Keep-Out 板框 | ✅ | 铣刀照它切外形 |
| `.TXT` | 钻孔(Excellon NC Drill) | ✅ | 钻头照它打孔 |
| `.DRR` | 钻孔报告,**纯文本** | ❌ | **自检神器,见下** |
| `.GD1` / `.GG1` | 钻孔图(给人看)/ 钻孔导引 | ❌ | |
| `.GM1` `.GM13~15` | 机械层(标注、3D 外形、位号层) | ❌ | 留着可能让系统误判板框 |
| `.REP` `.EXTREP` `Status Report.Txt` | 导出报告 | ❌ | |
| `.RUL` | DRC 规则导出,纯文本 | ❌ | 本项目:线宽≥4 mil、间距≥4 mil |
| `.apr` / `.APR_LIB` | 老式 RS-274D 的**外挂光圈表** | ❌ | 现在是 RS-274X,光圈已嵌在文件头 |
| `.drc` / `Design Rule Check*.html` | DRC 检查报告 | ❌ | |

**Gerber 全家都是纯文本**,这是它能跨 30 年通用的原因。

### 为什么不能直接把 `.PcbDoc` 发给工厂

1. 工厂不一定装 AD,更不一定是同一版本(这套文件是 AD 22.11 存的)
2. `.PcbDoc` 里有大量与制造无关的东西:元件库引用、3D 模型、设计规则、未布线的网络
3. Gerber 是行业标准 + 纯文本,不依赖任何软件版本

### 30 秒自检任何一套光绘

记事本打开 `.DRR`。Motor-42 的内容:

| T1 | 0.254 mm | 16 | 过孔 |
| T2 | 0.3 mm | 132 | 过孔 |
| T3 | 0.6 mm | 3 | |
| T4 | 0.72 mm | 18 | 插件焊盘 |
| T5 | 0.9 mm | 4 | |
| T6 | **3.1 mm** | 4 | **四角安装孔** |

**拿到任何一套光绘,先开这个文件**,30 秒判断有没有钻孔、最小孔多大。比在网页上点来点去可靠。

## 三、AD 操作速查

### 打开这套文件的三个坑

| 坑 | 解决 |
|---|---|
| **没有 `.PrjPCB`** | File → New → Project → PCB Project,然后 Projects 面板右键工程 → **Add Existing to Project**,把 5 页图和 `Motor-42.PcbDoc` 都加进去 |
| **5 张图之间没有顶层图纸**,靠同名网络标签连接 | Project → Project Options → Options 页 → **Net Identifier Scope 设成 Global**,否则 AD 认为同名网络跨图纸不相连,追线会追断。设好后 Project → Validate 一次 |
| 别碰焊盘更改版 | 打的是 V1.01 的板,图就只看 `PCB源文件` 这套 |

### 原理图侧

| 动作 | 操作 | 用途 |
|---|---|---|
| 看全图 | `V` → `F` | 迷路就按它 |
| 高亮一条网络 | 按住 `Ctrl` 点导线 | **追线的核心动作**,跨 5 张图一起亮 |
| 按名字找 | `Ctrl+F` | ⚠️ 要勾 **Search All Open Documents**,否则只搜当前页 |
| **跨图纸追网络** | Projects 面板 → **Navigator** | 编译后列出全部网络,点一个 → 它在哪几张图上出现、落在哪个元件哪个脚全列出来。**这才是 5 张图之间追线的正确工具** |
| 看元件真身 | 双击元件 | 看三个字段:`Designator`(U3)、`Comment`(STM32F103CBT6)、`Footprint`(LQFP-48) |
| 导成 PDF | File → **Smart PDF** | 5 页图导成一个带网络超链接的 PDF,适合离线/平板标注 |

### PCB 侧

| 动作 | 操作 | 用途 |
|---|---|---|
| 2D / 3D | `2` / `3`,或 **View → 2D(3D) Layout Mode** | 见下方"坑" |
| **单层显示** | `Shift+S` 循环 | **看懂 4 层板走线的唯一办法**(三态:隐藏其他层 → 其他层变灰 → 关闭) |
| 层开关 | `L` 打开 View Configuration | |
| **层组预设** | 左下角 **`LS`** 按钮 | `All Layers` / `Signal Layers` / `Mechanical Layers`,切着看比逐个勾眼睛快 |
| 看叠层 | **Design → Layer Stack Manager** | 看四层排布、铜厚、层类型(Signal / Plane) |
| 翻到底面 | **`V` → `B`**(Flip Board) | 2D/3D 都好使。翻面后丝印镜像是正常的 |
| 量尺寸 | `Ctrl+M` | |

### 3D 视角操作

| 操作 | 手势 |
|---|---|
| **旋转** | ① 先按住 `Shift` 不放(画面中央出现球形指示器)→ ② 再按住**鼠标右键** → ③ 拖动 → ④ 先松右键再松 Shift。**顺序反了会变成平移** |
| 平移 | 右键直接拖(不按 Shift) |
| 缩放 | 滚轮 / `Ctrl`+滚轮 / `PgUp` `PgDn` |
| 复位 | `V` → `F` |

> 3D 里很多元件看起来是扁的或没有立体外形 —— 这套封装库很多元件没画 3D Body,**不是文件坏了**。焊盘、丝印、板框是真实的。
> 3D 黑屏或卡顿 → Preferences → System → **Graphics**,在 DirectX / Software 之间换一个。

### ⭐ 查找位号的 5 种方法(从快到好用)

| 方法 | 操作 | 特点 |
|---|---|---|
| **跳转** | `J` → `C` → 输入 `U8` 回车 | 最快。但**只移动视图不改缩放**,跳完可能还要 `PgUp` 放大 |
| **PCB 面板** ⭐ | Panels → PCB → 下拉选 **Components** | 列出全部 82 个元件。配合三个选项:**Zoom**(自动缩放)、**Select**(选中)、**Mask/Dim**(其他元件变暗)。点一下,目标孤零零亮着 |
| 原理图里 | `Ctrl+F` + 勾 Search All Open Documents | |
| **原理图 ↔ PCB 联动** ⭐⭐ | Tools → **Cross Select Mode**(`Shift+Ctrl+X`) | 标签页右键 → Split Vertical 分屏。点原理图上的元件 → PCB 立刻高亮;反之亦然。**读图时一直开着,"原理图—实物"的映射自动建立** |
| 板外野路子 | 浏览器开 `Motor-42.html` | 搜位号 → 正反面同时高亮。焊板子时比开 AD 实用 |

> **救命快捷键 `Shift+C`** —— 清除过滤 / 取消变暗。用了 Mask 之后整块板灰蒙蒙的,按它恢复。很多人在这卡住以为软件坏了。

> **自己发现快捷键的方法**:AD 快捷键大多是"菜单首字母串"。按 `J` 就是在调 **Edit → Jump** 子菜单。**去菜单里看 AD 自己标的键**,比记别人说的准。

## 四、板子参数与叠层

### 板级参数(✅ 均为 2026-10-13 从文件解析核实)

| 项 | 值 | 来源 |
|---|---|---|
| 外形尺寸 | **41.20 × 41.20 mm** | `.GKO` 板框坐标 |
| 层数 | **4** | zip 里四个铜层文件 |
| 钻孔总数 | **177** | `.DRR` |
| 最小孔径 | **0.254 mm**(10 mil) | `.DRR` T1 |
| 最小线宽 | **≥ 0.16 mm**(6.3 mil) | 铜层文件头 `%ADD70C,0.00630*%`,单位英寸 |
| 内层极性 | **正片** | 文件头 `TF.FilePolarity,Positive` |

> 工艺要求远在嘉立创四层板能力之内,不用担心做不出来。

### 叠层 ↔ Gerber 对应(在 AD 底部层标签里亲眼确认过)

| 叠层名 | Gerber 文件 | 这层干什么 |
|---|---|---|
| `[1] Top1` | `Motor-42.GTL` | 顶层信号 |
| `[2] Signal2` | `Motor-42.G1` | **内层信号**(名字就叫 Signal) |
| `[3] Gnd3` | `Motor-42.G2` | **地平面**(名字就叫 Gnd) |
| `[4] Bottom4` | `Motor-42.GBL` | 底层信号 |

**这解释了为什么 42 板内层是正片**:第 2 层走信号、第 3 层铺地,**两层都是普通 Signal 类型层**,不是 Altium 的 Internal Plane。REF 主控板用的才是 Plane 类型 → 导出负片。一个设计上的小选择,一路影响到送厂文件格式。

**为什么 41×41 mm 要用 4 层**:中心区域被编码器和电机轴占掉,剩下面积要塞 82 个元件 + 24 V 大电流路径 + 完整地平面,两层排不开。

## 五、板上元件逐个认

按"电和信号怎么走"的顺序,不按位号顺序。

### 1. 接口:和外界的全部连接(`Port.SchDoc`)

| 位号 | 实物 | 作用 |
|---|---|---|
| **P1 / P2** | 顶部两个蓝色 6P 座,丝印 `24V` + `IN` / `OUT` | ZH1.5 6P。**两个完全一样,一进一出** —— 电源和 CAN 从上一个关节进来再串到下一个,整条臂菊花链。6 根线:2×24 V、2×GND(并联加载流)、CAN_H、CAN_L |
| **A+ A- B+ B-** | 中间 4 个大圆焊盘 | 步进电机**两相线圈**,电机线直接焊,无接插件 |
| **P3** | 左侧蓝色 6P 座 | 调试口(`RX TX GND SWDIO SWCLK GND`,**详见第六章**)。⚠️ **和 P1/P2 外形相同、定义完全不同,插错会把 24 V 灌进 MCU 的 SWD 脚** |
| 四个大圆孔 | 四角 3.1 mm | 安装孔,对应 `.DRR` 的 T6 |

### 2. 电源链:24 V → 3.3 V(`Power.SchDoc`)

| 位号 | 实物 | 在链条上的位置 |
|---|---|---|
| **D1** | C11 右侧黑色 DO-214AC | **SS54 肖特基**,串在 24 V 入口 → 防反接 |
| **D2** | 右侧大黑块(C14 下方) | **SMBJ28CA TVS**,并联在 24 V / GND 之间,冲到 28 V 以上才击穿泄流 |
| **C11 / C14** | 两颗大圆柱电解 | 220 µF/25 V 母线储能。**C14 是 42 板独有,35 板只有 C11** |
| **C29~C34** | 底面那排 6 颗 1206 | 10 µF/50 V 陶瓷。电解管低频、陶瓷管高频,两种必须配合 |
| **U6 + L1 + D4 + C20** | 中右部 SOT23-6 + 棕色电感 + SOD-323 | **ME3116 降压 DC-DC**。L1 = 6.8 µH 储能电感,D4(B5819W)= 续流二极管 |
| **R13 / R14** | U6 旁两颗 0402 | 10 K + 1.8 K,**反馈分压 —— 决定中间电压是几伏** |
| **U7** | 右下 SOT23-5 | **LP2992 LDO** → 稳出 3.3 V。配套 C15/C17/C18/C19 |
| **D3** | U6 左下 SOD-323 | 另一颗 B5819W,接法待查 |

### 3. MCU 核心(`MCU.SchDoc`)

| 位号 | 实物 | 作用 |
|---|---|---|
| **U3** | 中间 48 脚方芯片 | **STM32F103CBT6**。⚠️ 是 **CB**(128 K Flash)不是 C8 —— 编码器校准表要占 32 K |
| **Y1** | U3 右侧金属封装 | 12 MHz 晶振 |
| **C12 / C13** | Y1 两侧 0402 | 20 pF 负载电容,**必须紧贴晶振** |
| RST 丝印附近 | C9 / C10 / R10 区域 | 复位电路 |
| **一堆 0.1 µF** | U3 四周密密麻麻的 0402 | **去耦电容**。板上 19 颗 0.1 µF 大半在这儿 |

> **认去耦电容的窍门:哪里 0402 扎堆,哪里就有芯片电源脚。**

### 4. 电机驱动(`Drive.SchDoc`)

| 位号 | 实物 | 作用 |
|---|---|---|
| **U1 / U2** | 顶部中间两颗黑色 SO-8 | **TB67H450FNG ×2,一颗驱动一相** |
| **R3 / R8** | **底面**,紧挨电机焊盘的 1206 | **0.1 Ω 电流采样电阻**,驱动芯片靠量它两端电压限制线圈电流 |
| **R4 / R5** | 顶面,夹在 U1 和 U2 **正中间** | R4 = **NTC 热敏**(NCP15XH103F03RC,不是普通电阻!),R5 = 3.3 K |
| **C27 / C28** | U1、U2 旁边 | 驱动芯片去耦 |

> **R4 的位置本身就是答案**:刻意放在两颗驱动芯片正中间,因为它测的是驱动芯片温度。固件里 PA1 上那个叫 `DRV_TEMP` 的 ADC 通道量的就是它。
>
> **读图习惯:布局会泄露电路意图。元件摆在哪,往往比原理图上的连线更快告诉你它是干什么的。**

### 5. 通信与人机接口(`Interface.SchDoc`)

| 位号 | 实物 | 作用 |
|---|---|---|
| **U8** | **底面正中**那颗 SO-8 | **MT6816 磁编码器**。✅ 已验证基本在板子几何中心 —— 电机轴尾端磁铁要正对它。SPI 四线接 MCU |
| **U5** | 底面下方 SO-8 | **SN65HVD232D CAN 收发器** |
| **R12** | 顶面底部,**紧挨 S1 左侧** | **120 Ω,CAN 总线终端电阻** |
| **S1** | 底部白色大开关 | **4 位拨码开关**,拨 CAN 节点 ID |
| **K1 / K2** | 右侧两个按键 | 功能键 |
| **LED1 / LED2** | 底部两个红色小块 | 状态灯 |
| **R11 / R18** | 紧挨 LED1 / LED2 | 1 K,LED 限流 |

### 6. 底面两个必须注意的细节

**① 横贯板子的金色铜带(C29~C32 那排下面)**

裸露的铜,没盖绿油 —— 这是**故意开窗的大电流铜带**:

- 原因:板子只有 41 mm 宽,24 V 母线和相电流要走几安培,铜箔厚度有限
- 做法:把这段走线的阻焊层挖掉,露出裸铜
- 好处:焊接时在上面**堆一层锡**,等效于把铜加厚,载流能力翻倍
- ⚠️ **对手焊的实际意义:这条带子要主动刷锡,不是"不小心沾上去的",是设计要求**

**② 成片的小圆点阵列**

六个一组、三个一组的小点是**过孔(via)**,密集出现在铜带和地平面之间,把热量和电流从顶层导到内层和底层。**第 3 层 `Gnd3` 地平面就是靠这些过孔和表面连通的。**

## 六、P3 接口与烧录调试

### P3 的真实针脚定义 ✅

来源:`source/dummy/hardware/dummy_boards_manual.pdf` 第 2 页侧视图。手册目录原文一行:

> **`P3 - ST-LINK and UART1`**

⚠️ **两份 PDF(本手册、`6.Docs/Pins definations.pdf`)的针脚定义都是「图」不是文字**,`pdftotext` 提取不到,必须抽 PDF 里的内嵌位图才能看。

实际是 6 针:

```
P3:   RX    TX    GND    SWDIO    SWCLK    GND
      └──── 串口三根 ────┘└──── SWD 三根 ────┘
```

两个 GND、一边一个,因为**这是两组独立接口挤在同一个座子上**:左三针给 USB 转串口,右三针给 ST-Link,**可以同时接,互不干扰**。

> ❌ 本笔记初版写的「SWDIO、SWCLK、UART_TX、UART_RX、GND」**顺序和数量都错**,已更正。

### ⚠️ P3 上没有任何电源针

**ST-Link 不能给这块板供电,必须先从 P1 接 24 V 把板子点起来,才能烧录。**

这不是可选项——板上 3.3 V 是 24 V 经 ME3116 降压、再经 LP2992 稳压出来的(见第五章电源链),不接 24 V 整块板就是死的,SWD 当然连不上。

### 接线

| ST-Link V2 | → | P3 |
|---|---|---|
| SWDIO | → | SWDIO |
| SWCLK | → | SWCLK |
| GND | → | GND(**用靠 SWCLK 那一侧的那个**) |
| 3.3V / VTREF | → | **先不接** |

同时另一头:**P1 接 24 V**。建议用带限流的可调电源,设 **24 V / 限流 0.3 A**,第一次上电**电机相线不接**。

关于那根 3.3V:ST-Link 需要知道目标板电平才能工作。正版 ST-Link 的 VTREF 是必须的,廉价克隆棒大多不用接。**先按上表三根线试**;若 CubeProgrammer 报 `No target connected` 或显示 `Target voltage = 0.00V`,再从板上取 3.3 V 引过去。

> ⚠️ **不要反过来用 ST-Link 的 3.3V 给板子供电** —— 它电流很小,而且板上 24 V 那一侧(驱动芯片、编码器)根本不会工作,你会得到一堆莫名其妙的现象。

### 线材的坑

P3 是 **ZH1.5 座子,间距 1.5 mm**。**杜邦线是 2.54 mm,插不进去。**

需要:**ZH1.5 6P 成品线**(一头端子一头散线),或买端子 + 压线钳自己做。P1/P2/P3 用同一种,一次多买几根。

> ⚠️ **P1、P2、P3 三个座子外形完全一样。** P1/P2 是 24 V + CAN,P3 是 SWD + 串口。
> **插错 = 24 V 直接灌进 MCU 的 SWD 脚,芯片当场报废。** 手册里专门用一句话警告过。**做线的时候就把标签贴上。**

### 软件与固件产物

**工具**:**STM32CubeProgrammer**(ST 官方,Windows 版直接装)。
项目里 `<V2>/6.Docs/en.stsw-link004 (1).zip` 是老的 ST-LINK Utility v4.6,已停止维护,不建议用。

**烧什么**:仓库里已有编译好的产物(2026-09-06 构建)

```
<V2>/2.Firmware/build/motor42-baseline/
    Ctrl-Step-STM32-fw.hex    ← 烧这个(209 KB)
    Ctrl-Step-STM32-fw.bin    ← 或这个(74 KB,但要手填起始地址 0x08000000)
    Ctrl-Step-STM32-fw.elf
```

用 `.hex` 省事——地址信息在文件里,不用自己填。

**目标芯片**:STM32F103CBTx,接口 SWD。
(工程文件 `Ctrl-Step-fw.xml` 里写死:`<dbgIF>SWD</dbgIF>`、`<dbgDEV>ST-LinkV2-1</dbgDEV>`)

### ⚠️⚠️ 烧录时最重要的一条:别勾「整片擦除」

这块板的 Flash 不只有程序:

| 地址 | 大小 | 内容 |
|---|---|---|
| `0x08000000` | ~74 KB | 程序本体 |
| **`0x08017C00`** | **32 KB** | **编码器校准表** —— 16384 项查找表,把 MT6816 的原始角度映射成线性坐标 |
| `0x0801FC00` | 1 KB | 参数区(模拟 EEPROM:CAN ID、PID 参数等) |

**勾了 Full chip erase,校准表和参数一起没了**,电机必须重新跑校准流程。如果买的是卖家已校准好的板,这一下全白费。

CubeProgrammer 的 Download 默认是「只擦写用到的扇区」,**保持默认别动**。

> **顺带一个本项目已知坑**(索引第五节第 15 条):链接脚本 `STM32F103CBTx_FLASH.ld` **把整片 128 KB 都划给了代码**,没给 `0x08017C00` 的校准区做保留。当前构建 73 KB,离 95 KB 边界还有约 22 KB 余量。
> **以后往固件里加东西要盯着体积** —— 超过 95 KB 会静默覆盖校准表,**编译器不会报错**。

### 另外三根线(RX / TX / GND)

接 USB 转串口,**115200 8N1**,用来:

- 看固件的 `printf` 输出(编码器角度、开机参数)
- 发命令控制电机(`!CALIBRATION`、`p0.25` 这类)

接线注意**交叉**:板子 TX → 适配器 RX,板子 RX → 适配器 TX,GND 对 GND。

**完整的调试台是三路线同时接**:P1 吃 24 V,P3 左三针出串口,P3 右三针进 ST-Link。

### 怎么自己验证这份针脚定义(比 PDF 权威)

手上没有板子也不用等——答案就在 AD 里,而且**比 PDF 权威**(PDF 是人画的可能画错,设计文件是实际生产依据):

1. 在 `Motor-42.PcbDoc` 里把光标放到 P3 的某个焊盘上,**Properties 面板 / 状态栏会显示该焊盘的网络名(Net)**
2. 六个焊盘逐个点一遍,记下顺序
3. 再去 `Port.SchDoc` 找到 P3,核对每个引脚号对应的网络标签

两边对上,就**亲手验证了这份手册**。顺便——**哪一端是第 1 针,也只有这样才能真正确定**,PDF 的侧视图看不出朝向。

## 七、42 与 35 的差异

两块板是**同一套设计换板型**,芯片型号一个不差。读 35 板时不要从头读,**直接找差异**。

### 42 有、35 没有

| 位号 | 值 | 用途 |
|---|---|---|
| `C14` | 220 µF / 25 V | 母线储能(原因见下) |
| `C33` `C34` | 10 µF / 50 V 1206 | 同上 |
| `C26` `C35` | 0.1 µF | ❓ |
| **`R16`** | 10 K | ❓ **35 板根本不存在,真正的侦探题** |
| **`R17`** | 1 K | ❓ 同上 |

> R16(10 K) + R17(1 K) 分压比 11:1 → 24 V 得到 2.18 V,正好落在 3.3 V ADC 量程内。
> **待查**:是不是接到 PA0(固件里叫 `POWER_U`,母线电压采样)?如果是,就能解释 35 板为什么没有这两颗。

### 只是正反面放置不同(不是电路差异,别浪费时间)

`R20`、`C21/C25`、`C22/C24` —— 42 在顶面,35 在底面。

### 为什么 42 板的母线储能几乎翻倍

**电机清单**(来源:`<V2>/5.Bom/dummy V2版本_bom.xlsx`「其它」页;关节对应来自索引第九章)

| 电机 | 机身长 | 数量 | 装在哪 |
|---|---|---|---|
| 42 步进 | **l = 40 mm** | 3 | J1 / J2 / J3(肩部三轴) |
| 35 步进 | **l = 28 mm** | 2 | J4 / J5 |
| 35 步进 | **l = 20 mm** | 1 | J6 |

> ⚠️ **已知冲突**(索引审计 A14):BOM 写 `42×40`,但 `4.Model/` 的 STEP 里 **42-34 和 42-40 两种并存**,42 电机机身长度**尚未冻结**。
> ⚠️ **BOM 没有记录任何一款电机的额定电流** —— 资料缺口,真要买得问卖家。

**母线储能对比**(来源:`source/dummy/hardware/dummy_boards_bom.xlsx`)

| | Motor-42 | Motor-35 | 倍数 |
|---|---|---|---|
| 220 µF/25 V 电解 | **2**(C11、C14) | **1**(C11) | 2× |
| 10 µF/50 V 1206 | **6**(C29~C34) | **4**(C29~C32) | 1.5× |
| 合计容量 | ≈ 500 µF | ≈ 260 µF | **1.9×** |

**电流能力对比(这条最反直觉)**

| | Motor-42 | Motor-35 |
|---|---|---|
| 采样电阻 R3/R8 | 0.1 Ω | **0.1 Ω(完全相同)** |
| 驱动芯片 | TB67H450FNG ×2 | **完全相同** |
| 固件限流 / 标定电流 | 1000 mA / 2000 mA | **完全相同** |

> 固件参数来源:索引第八章「42 与 35 固件的差异」—— 两份固件实测只有 5 个文件不同,**唯一的功能性差异是 `dce_kp` 200 vs 195**,电流/速度/加速度参数一模一样。

**所以:采样电阻和限流值都相同 ⇒ 两块板「能输出多大相电流」的设计是一样的。差的不是输出端,是输入端的储能。** 两个原因:

**原因一:42 电机实际工作电流大得多(电气层面)**
虽然限流设定相同,但 J1/J2/J3 要托举整条手臂,**长期工作在接近限幅的状态**;J4/J5/J6 是腕部,多数时候轻载。再加上 42×40 的绕组电感比 35×28 大,斩波时从 24 V 母线抽取的**脉冲电流幅度和纹波都更大**。母线电容的作用就是在斩波瞬间「就近供电」,不让 24 V 被拉塌。

**原因二:35 板根本放不下第二颗(物理层面,同样关键)**

| | 板面积 | 220 µF 电容占地 |
|---|---|---|
| Motor-42 | 41.20 × 41.20 = **1697 mm²** | φ8×8.3 mm ≈ 64 mm²/颗 |
| Motor-35 | 26.01 × 35.03 = **911 mm²** | 同上 |

**35 板只有 42 板 54% 的面积,却要塞下几乎同样的 72 个元件。** 两颗 8×8 电解会吃掉它 14% 的板面。砍掉一颗很可能是**布局被逼出来的**,不完全是电气计算的结果。

### ❓ 但这里有个必须自己验证的点

「C14 是 24 V 母线储能」是**根据封装和位置推断的,没有在原理图上确认过**。顶面布局其实暗示了另一种可能:

```
   C11          U2   U1          C14
  (最左)      (左驱) (右驱)      (最右)
```

**C11 和 C14 对称地分列在两颗驱动芯片的外侧。** 这很像「**一颗驱动芯片配一颗专属储能电容**」——把电容放在离负载最近的地方,而不是堆在一起。若真如此,35 板的那一颗 C11 就是两颗驱动共用。

**30 秒验证法**:

1. 打开 `Power.SchDoc`(或 `Drive.SchDoc`)
2. `Ctrl` + 点 C11 的正极
3. 看 C14 的正极**是不是同一个网络一起亮了**

| 结果 | 含义 |
|---|---|
| **一起亮** | 两颗并联在同一条 24 V 母线上,纯粹「加容量」,原因一成立 |
| **没一起亮** | 接在不同节点(比如 D1 前后、或各自靠近一颗驱动),是另一套设计意图,得重新解释 |

### 一个认知

这块板上的差异,**全是「同一套设计按负载缩放」**:

| | 42 板 | 35 板 |
|---|---|---|
| 芯片型号 | 完全相同 | 完全相同 |
| 固件 | 只差一个 PID 系数 | |
| 母线电容 | ≈500 µF | ≈260 µF |
| 板子面积 | 1697 mm² | 911 mm² |

设计者**没有为小关节重新设计一套电路,而是把同一套电路按空间和负载缩了一版**。这是工程上很常见的做法,也是为什么读 35 板时只找差异就够了——差异就那么几处,每一处背后都有一个可以追问的原因。

## 八、待验证的题

> 全部能在原理图上查到答案。查到任意一条可以和固件代码对照。

**① ME3116 的中间电压是几伏?**
打开 `<V2>/6.Docs/芯片说明/ME3116.pdf` 查 FB 基准电压,用 R13(10 K)、R14(1.8 K) 按分压公式算。
算出来应该比 3.3 V 高出 LDO 压降一点点。若离谱 → 上下臂电阻接反了,回图上看。

**② R4(NTC)和 R5(3.3 K)怎么接的?是不是接到 PA1?**
固件里 PA1 = `DRV_TEMP`。R5 很可能是和 NTC 配对的分压电阻。

**③ S1 的第 4 位和 R12(120 Ω)有没有关系?** → ✅ **已有答案**

手册的目录行自己就回答了:

> **`S1 - Driver board CAN ID definition and terminal resistor`**

**S1 既管 CAN 节点 ID,也管终端电阻。** 从布局看出「R12 紧贴 S1」的推断是对的。

**含义**:可以用拨码开关决定这块板要不要接入 CAN 终端电阻。**整条总线只有首尾两个节点该接 120 Ω,中间的不能接**——以后调 6 个关节时,这是第一个要查的地方。

**仍待补**:具体哪一位控制什么、怎么拨。手册第 2 页有一张 **CAN ID 真值表**(同样是图),需要抽出来。

**④ C11 和 C14 是不是同一个网络?**(新增,见第七章末)
`Ctrl` + 点 C11 正极,看 C14 正极是否一起亮。决定了「母线并联加容量」还是「一驱一容就近供电」。
