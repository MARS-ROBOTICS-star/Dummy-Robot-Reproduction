# Dummy Robot 高保真复现与研究平台设计

**日期：** 2026-07-22
**状态：** 用户已于 2026-07-22 确认，作为后续实施基线
**项目母本：** `peng-zhihui/Dummy-Robot`

## 1. 项目目的

本项目不以照教程组装一台演示玩具为目标，而以 Dummy Robot 为工程母本，完成一次机电软一体化产品从需求、架构、原型、制造、调试到实验平台交付的完整过程。

项目同时实现三个目标：

1. 理解并数字化还原原版 Dummy 的机械、电气、嵌入式和上位机架构；
2. 在正式整机制造前，利用机械专业知识完成一次有数据支撑的 Rev.B 优化；
3. 将实体 Rev.B 建成可用于系统辨识、模型控制、视觉控制、力控制和强化学习实验的安全研究平台。

项目的最终成果不只是一台机械臂，还包括可复用的需求文档、参数化 CAD、工程图、BOM、生产文件、固件构建环境、协议文档、仿真模型、测试数据、装配手册和复盘记录。

## 2. 已确认的项目边界

### 2.1 采用双基线

- **V0 数字基线：** 完整还原原版 Dummy 的结构、传动、控制和接口，用于理解、比较和验证。
- **Rev.B 实体版本：** 保持 Dummy 的构型、紧凑风格和分布式控制思想，但采用经过计算和试验验证的优化结构。

不制造完整的原版 V0 整机。允许制造原版或接近原版的电路首板、低成本装配样件和单关节样机，用于消除风险。昂贵的六轴 CNC 整机只制造 Rev.B。

### 2.2 保留的原版特征

- 桌面级六旋转关节机械臂；
- 末端三轴保持可用解析逆解的几何关系，优先维持 Pieper 条件；
- 步进电机、谐波减速器和一体闭环关节路线；
- REF 主控加分布式 CAN 关节控制器；
- 与原版接近的整体尺度、紧凑性和外观语言；
- 原固件、CLI 和 DummyStudio 可作为早期验机基准。

### 2.3 允许优化的内容

- 关节轴承和减速器输出支撑；
- 电机、减速比、同步带和负载惯量匹配；
- 连杆截面、局部加强、材料和质量分布；
- 装配基准、公差、紧固和润滑；
- 线束路径、可维护性、散热和防误接；
- 底座稳定性、机械限位和急停接口；
- 输出编码器、相机、力传感器和模块化末端法兰；
- 上位机研究接口、实时轨迹流、日志和安全状态机。

### 2.4 当前不作为前置条件的功能

- Peak 无线示教器；
- 空间定位控制器和 Dongle；
- 夹爪 PCB 和 LED 灯环；
- DummyStudio 源码逆向；
- 仓库中标为 unused 的 57 电机驱动；
- 未经过仿真、限幅和安全监督的真机强化学习。

这些功能可以在六轴平台可靠运行后作为独立扩展项目加入。

## 3. 项目实施条件与约束

- 项目能力基线涵盖机械设计、基础电子电工、C 语言与 Python；嵌入式工程能力从最小外设实验和调试闭环开始建立；
- 实验设备按阶段能力门配置电子、焊接和测量条件；
- 3D 打印、PCB 制造/贴片和 CNC 采用线上外协；
- 项目采用分阶段投入与阶段门采购规则，高价值物料仅在前一阶段通过实物验收后采购；
- 进度以能力门和实物验收为准，不以预设月份作为硬约束。

## 4. 仓库审计结论

仓库是工程母本，不是可以直接投产的完整制造包。

### 4.1 机械资产

`4.Model/` 提供：

- `Dummy v164.step` 六轴装配；
- 42 电机驱动上下盖；
- 便携箱 STEP。

主要缺口：

- 没有带参数和特征树的原生 CAD；
- 没有完整零件工程图、基准、公差和配合；
- 没有材料、热处理、表面处理和质量要求；
- 没有正式机械 BOM 和装配工艺；
- 没有原版的刚度、回差、载荷、模态和精度测试结果。

因此，机械工作的起点是装配逆向和关键零件参数化重建，不是直接把 STEP 交给加工商。

### 4.2 电子资产

`1.Hardware/` 提供以下 Altium 工程：

- REF 核心板与底板；
- 42、20 步进电机驱动；
- 57 电机驱动扩展设计；
- Controller、Dangle、HandModule 和 LedRing。

驱动板主要架构为 STM32F103、MT6816、TB67H450 和 CAN 收发器；REF 核心使用 STM32F405，并带有 CAN、OLED 和 IMU 等接口。

主要缺口：

- 大部分板卡没有统一、可直接下单的 Gerber、钻孔、BOM 和贴片坐标包；
- 缺少整机线束图、端子定义总表和生产测试规范；
- 缺少替代料验证和当前可采购性记录；
- 缺少首板分电源域上电与热测试记录。

### 4.3 电机固件

`2.Firmware/Ctrl-Step-Driver-STM32F1-fw/` 提供：

- STM32 HAL 和启动工程；
- MT6816 读取与编码器校准；
- TB67H450 电流矢量驱动；
- 位置、速度、电流和轨迹模式；
- CAN/UART 协议；
- 模拟 EEPROM 参数保存；
- 堵转、过载和未校准状态；
- 一份已发布 HEX。

主要缺口：

- 没有固定版本的完整工具链说明和自动构建验证；
- 没有按六个关节整理的正式参数配置；
- 没有完整的磁铁安装、校准、调参和热测试手册；
- 轨迹和电流能力没有形成面向研究用途的性能边界。

### 4.4 REF 主控固件

`2.Firmware/Core-STM32F4-fw/` 提供：

- STM32F405、HAL、FreeRTOS；
- USB CDC、UART、CAN 和 Fibre；
- OLED、IMU、存储等 BSP；
- 六自由度正逆运动学；
- MoveJ、MoveL、关节限位和同步运动；
- 顺序、可打断、轨迹和调参命令模式框架。

仓库 README 明确说明动力学没有完全实现，200 Hz 轨迹模式仍标记为 `ToDo`。研究平台不能把这两项视为已有能力。

### 4.5 PC 软件与文档

`3.Software/CLI-Tool/` 提供基于 Fibre 的 Python CLI 源码；`3.Software/DummyStudio/` 提供 Windows/Unity 成品，但不提供业务源码。仓库没有 URDF、ROS 接口、动力学模型、统一数据记录、实验配置管理或自动测试。

仓库也没有明确的项目许可证文件。对外发布 Rev.B 的派生文件前，需要单独确认原项目各类资产的再分发和衍生授权边界。

### 4.6 Peak 子模块

`.gitmodules` 指向 `git@github.com:peng-zhihui/Peak.git`，当前工作副本没有实际检出其内容。Peak 属于后期交互扩展，不阻塞主线。

## 5. 系统架构

### 5.1 原版控制流

```text
DummyStudio / Python CLI / ASCII 命令
                    │
               USB CDC / UART
                    ↓
          REF：STM32F405 + FreeRTOS
          ├─ 正逆运动学
          ├─ 关节限位
          ├─ 速度与同步规划
          └─ 命令队列
                    │
                 CAN
                    ↓
     J1  J2  J3  J4  J5  J6 分布式关节板
     ├─ 编码器校准
     ├─ 位置/速度/电流控制
     ├─ 电流矢量输出
     └─ 状态和位置反馈
```

### 5.2 Rev.B 目标控制流

```text
研究计算机
仿真 / 视觉 / 系统辨识 / MPC / 强化学习
                    │
         统一状态、轨迹和实验日志接口
                    ↓
实时协调与安全层
轨迹缓存 / 限位 / 看门狗 / 状态估计 / 急停
                    │
                 CAN
                    ↓
关节控制层
电流 / 速度 / 位置 / 编码器 / 故障保护
                    │
                    ↓
输出编码器 / 力传感器 / 相机 / 末端工具
```

智能算法不得绕过实时协调与安全层直接操作功率驱动。算法输出为轨迹、关节位置/速度、受限的力矩修正或控制参数；底层始终执行电流、速度、关节范围、温度、通信超时和急停约束。

第一版实时协调与安全逻辑运行在 REF 主控中，研究计算机只承担非安全关键的规划、仿真、视觉和学习算法。硬件急停与执行器电源隔离独立于研究计算机和 REF 软件。

## 6. 项目推进方法

项目采用“架构先行、风险优先、原型消除未知、逐级集成”的方式。

```text
定义目标
  → 识别核心矛盾
  → 划分子系统和接口
  → 最小实验
  → 单板/单电机
  → 单关节
  → 多节点网络
  → 机械设计冻结
  → 六轴集成
  → 研究接口
  → 算法实验
```

每个阶段必须留下：

1. 阶段目标和验收标准；
2. 系统图、原理图或模型；
3. 可以独立运行的实物或软件；
4. 测量数据和结论；
5. 失败、原因、修正和下一版本复盘。

学习任务采用以下闭环模板：

```text
问题 → 前置知识 → 最小实验 → 仪器测量 → 验收 → 记录 → 映射回 Dummy
```

禁止以“看完课程”作为阶段完成条件。

## 7. 里程碑与能力门

### M0：读懂原机

交付：

- V0 装配树；
- 系统架构图；
- 机械、电气和采购 BOM 草案；
- 六关节传动、坐标和接口表；
- 证据、推断和缺失信息清单。

通过条件：能够从主机命令解释到关节运动，也能够从电源输入解释到驱动功率输出。

### M1：具备嵌入式最小能力

交付：

- GPIO、UART、定时器/PWM、ADC/DMA、SPI 和 CAN 最小工程；
- SPI 编码器角度曲线；
- 两块 STM32 之间的 CAN 目标值和反馈值交换；
- SWD 调试和故障记录。

通过条件：能够依据参考手册和数据手册新建外设实验，并区分硬件、驱动、协议和应用层故障。

### M2：闭环电机可用

交付：

- 一块经过首板检查的 42 电机驱动；
- 电机和 MT6816 磁铁安装工装；
- 可重复的校准、烧录和配置流程；
- 位置/速度/电流模式测试；
- 跟踪误差、阶跃响应、堵转保护和温升数据。

通过条件：在定义好的电流、速度、负载和持续时间下重复运行，无失控、无异常温升，故障行为可预测。

### M3：单关节合格

交付：

- 与最终路线一致的电机、谐波减速器和关节结构；
- 可反复拆装的单关节试验台；
- 输出角度、刚度、回差、重复性、温升和振动数据；
- 原版参数与 Rev.B 候选参数比较。

通过条件：单关节结果能够支撑整机电机、减速器、支撑和结构选型；未解决风险不得复制到六轴。

### M4：Rev.B 设计冻结

交付：

- 参数化总装；
- 完整工程图、公差、材料和表面要求；
- 静力、惯量、刚度、模态、工作空间、自碰撞和线束分析；
- 输出编码器、相机、力传感器和末端法兰预留；
- CNC、3D 打印和采购包；
- 初步设计评审和关键设计评审记录。

通过条件：每项更改有原版问题、计算结果或单关节试验证据；关键性能指标已经数值化；高价值物料和 CNC 接口已经冻结。

### M5：六轴研究平台可用

交付：

- 通过来料检验和逐级装配的六轴本体；
- 六个关节的节点、方向、减速比、零点和控制参数；
- 急停、限位、失联、堵转和过流测试；
- 机器人描述、碰撞模型、质量、重心和惯量；
- 仿真与真机统一的命令、状态和日志接口；
- 基线轨迹和重复精度报告。

通过条件：同一条受限轨迹能够在仿真和真机执行，日志可对齐命令、关节状态、电流和外部传感器，故障注入结果符合安全状态机定义。

## 8. 学习路径

### 8.1 电子与嵌入式

```text
安全用电和仪器
  → 焊接与首板上电
  → STM32 启动、编译和调试
  → GPIO/UART
  → 定时器/PWM/ADC/DMA
  → SPI 编码器
  → CAN 多节点
  → 闭环电机
  → FreeRTOS 和 REF
```

学习 SPI 是为了读取 MT6816；学习 PWM/ADC 是为了理解功率驱动和电流控制；学习 CAN 是为了扩展六个关节；学习 FreeRTOS 是为了组织实时控制、通信和状态任务。

### 8.2 机械与机器人

```text
STEP 装配逆向
  → 关节坐标和 DH
  → 参数化重建
  → 扭矩和惯量预算
  → 轴承/减速器支撑
  → 刚度和模态
  → 工作空间/奇异/碰撞
  → 公差和制造
  → 单关节试验校核
```

机械优化不能只比较有限元云图。计算必须通过单关节或代表性试样校核，结构改动必须同时考虑质量、制造、装配、线束、散热和传感器接口。

### 8.3 控制与研究

```text
正逆运动学
  → 轨迹生成
  → 系统辨识
  → 摩擦和重力补偿
  → 前馈加反馈控制
  → 振动抑制
  → 视觉伺服
  → 力控制
  → MPC
  → 安全约束下的强化学习
```

强化学习先在仿真中训练，再在受限工作空间、低速度和安全监督下部署。首个真机强化学习目标应采用残差策略或参数调整，不采用无底层保护的端到端电流控制。

## 9. Rev.B 机械设计流程

1. 从 STEP 建立原版零部件和装配关系；
2. 复核六个关节轴线、距离、范围、减速比和传动方向；
3. 建立 V0 质量、重心、工作空间、静力和刚度基线；
4. 选择覆盖最不利伸展、折叠、侧向和腕部负载的标准工况；
5. 进行电机、减速器、轴承、同步带和连杆分析；
6. 对承重链、输出支撑、底座、线束和维修空间提出候选方案；
7. 使用 3D 打印样件验证装配、干涉、线束和工具可达性；
8. 使用单关节试验校核模型；
9. 完成初步设计评审；
10. 完成详细工程图、公差链和制造评审；
11. 完成关键设计评审并冻结 Rev.B；
12. 只在设计冻结后下单整机 CNC。

具体载荷、刚度、模态和精度数值由 V0 基线、单关节实测和预定算法实验共同确定。设计冻结评审不得接受没有数值的“更轻”“更硬”或“精度更好”。

## 10. 安全和故障处理

### 10.1 实验室安全

- 项目只使用隔离低压直流供电，不进行市电电源设计；
- 首次上电必须限流并分电源域验证；
- 电机实验台必须固定，运动范围内不得放置身体部位；
- 焊接和返修必须采用排烟、护目和防烫措施；
- 电机和减速器在完整机械固定前不得高速运行。

### 10.2 控制安全

- 独立硬件急停切断执行器功率；
- 设置“受控减速停止”和“硬件功率隔离”两个停止层级；
- 主控和关节控制器具有通信看门狗；
- 每轴具有电流、速度、位置和温度边界；
- 上位机掉线、CAN 超时、编码器异常和节点故障都有定义状态；
- 算法命令经过限幅、速率限制、工作空间和碰撞检查；
- 故障发生时保留带时间戳的命令和状态数据。

在 Rev.B 设计冻结前，必须通过断电试验评估 J2、J3 承重链的重力下落风险。若减速器摩擦不足以保持安全姿态，则采用机械制动、配重/弹簧平衡、阻尼或等效的失电保护措施，不得把“谐波减速器可能自锁”作为安全假设。

### 10.3 集成顺序

```text
单板 → 单电机 → 单关节 → 两关节 → J1-J3 承重链 → J4-J6 腕部 → 六轴低速 → 六轴额定工况
```

每次只增加一个主要未知量，并逐级提高电流、速度、负载和工作空间。

## 11. 验证策略

### 11.1 电子验证

- 上电前短路和阻值检查；
- 电源轨电压、纹波、启动和负载测试；
- SPI、UART、PWM 和 CAN 波形；
- 编码器连续性和校准重复性；
- 功率器件和电机温升；
- 堵转、过载、掉线和重启测试。

### 11.2 机械验证

- 关键尺寸和配合来料检验；
- 关节回差和重复性；
- 标准姿态下的输出刚度和末端挠度；
- 空载与负载温升；
- 启停振动和频率响应；
- 线束在全行程内的弯折、摩擦和干涉；
- 底座稳定和机械限位。

### 11.3 软件与系统验证

- 正逆运动学互验；
- 仿真与实机关节方向、零点和范围一致；
- 轨迹缓存、覆盖、停止和恢复行为；
- 多轴同步和时间戳一致性；
- 故障注入与安全状态；
- 同一实验配置的可重复运行。

### 11.4 算法验证

每个新算法必须与上一基线在相同轨迹、载荷和初始条件下比较：

- 跟踪误差；
- 重复精度；
- 超调和稳定时间；
- 能耗和温升；
- 对负载变化的鲁棒性；
- 异常情况下的安全性。

## 13. 工程文档与版本管理

每个实验和设计版本至少记录：

- 日期、操作者、硬件版本和固件提交；
- 接线、电源限制和实验配置；
- 预期、原始数据、图表和结论；
- 失败表现、根因和修改；
- 是否通过验收门；
- 对 BOM、CAD、PCB、固件和说明书的影响。

推荐使用以下版本节点：

- `v0-digital-baseline`；
- `m1-embedded-basics`；
- `m2-closed-loop-motor`；
- `m3-single-joint`；
- `revb-design-freeze`；
- `m5-research-platform`。

不得用覆盖旧文件的方式隐藏失败版本。设计变更必须关联问题、证据和验证结果。

## 14. 第一阶段执行边界

第一阶段只推进到：

> 能够解释 Dummy 的系统组成，并让两块 STM32 开发板通过 CAN 交换目标角度和当前角度。

具体工作包括：

1. 建立工程日志和版本库；
2. 对照视频、STEP 和代码建立六轴装配树；
3. 建立 REF 到关节板的数据流图；
4. 建立机械、电气和采购 BOM 模板；
5. 搭建安全低压电子工作台；
6. 完成焊接和限流上电练习；
7. 完成 GPIO、UART、PWM、SPI 和 CAN 小实验；
8. 使用 Python 记录两块开发板之间的目标值与反馈值；
9. 完成 M0 和 M1 的第一次评审与复盘。

电机驱动、谐波减速器和 CNC 的详细任务在第一阶段通过后再展开，避免在工具链和测量能力尚未建立时提前投入。

## 15. 主要风险

| 风险 | 控制措施 |
|---|---|
| 把开源提交顺序误当实际开发顺序 | 以系统依赖和验证门组织路线 |
| STEP 被误当可直接制造的完整源文件 | 重建参数化 CAD、工程图和公差 |
| 缺少整机 BOM 和生产文件 | M0 完成资产审计，板卡逐块建立生产包 |
| 初学嵌入式时直接阅读大型工程 | 先做外设最小实验，再从 `UserApp` 向下阅读 |
| 一次采购六套高价值传动件 | 单关节验证后再锁定六轴采购 |
| 仿真优化没有实物校核 | 使用打印样件、代表性零件和单关节试验 |
| 原版单圈电机侧编码器无法观察输出误差 | Rev.B 预留输出编码器，优先覆盖 J1-J3 |
| 原动力学和 200 Hz 轨迹功能不完整 | 作为研究软件栈的明确开发项，不作为现成功能 |
| 智能算法造成真机危险运动 | 仿真先行、受限命令、安全监督和硬件急停 |
| 派生项目对外发布存在授权不清 | 发布前审查各资产许可证和第三方依赖 |

## 16. 成功定义

本项目成功不以“六轴能动”作为唯一标准，而以以下结果共同成立为准：

1. 用户能够解释并修改各子系统，不依赖不可理解的黑盒步骤；
2. Rev.B 的机械改进有 V0 基线、计算或试验数据支撑；
3. 整机具备可重复装配、校准、测试和故障恢复流程；
4. 仿真和真机共享明确的命令与状态接口；
5. 平台能够安全运行至少一种基线控制和一种进阶算法；
6. 所有关键决策、失败和版本均形成可供下一项目复用的工程记录。
